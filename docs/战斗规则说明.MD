# 战斗规则说明

> 本文档基于当前代码实现整理。代码入口：
> `scripts/Systems/CombatSystem.js` → `scripts/Systems/ContactResolver.js` → `scripts/Enties/CombatCharacter.js`

---

## 一、整体架构

```
每帧 fixedUpdate:

  ┌─ Character 1 ──────────────────────────────────────────┐
  │  getCombatSnapshot() → boxes + boxRole + dodgeActive    │
  └────────────────────────────────────────────────────────┘
  ┌─ Character 2 ──────────────────────────────────────────┐
  │  getCombatSnapshot() → boxes + boxRole + dodgeActive    │
  └────────────────────────────────────────────────────────┘
                         │
                    ContactResolver.resolve()
                         │
            ┌────────────┴────────────┐
            │  Phase 1: Wp vs Wp       │
            │  attack-shield  → 挡/弹  │
            │  attack-attack  → 拼刀    │
            │  → 产出 invalidatedIds   │
            └────────────┬────────────┘
                         │
            ┌────────────┴────────────┐
            │  Phase 2: Wp vs HBox     │
            │  (跳过 dodge/invalidated) │
            │  → 扣血 / hitstun / 击退  │
            └────────────┬────────────┘
                         │
                CombatSystem.fixedUpdate
                         │
               派发 effects → freezeImpact / hitstop / takeDamage / camera shake
```

## 二、碰撞盒子（Collision Mask）

### 2.1 颜色约定

| 颜色 | `box.type` | `subtype` | 含义 |
|---|---|---|---|
| `#FFFF00` | `hitbox` | — | 身体受击框 |
| `#FF0000` | `weaponbox` | `weak_blade` | 弱剑身（攻击侧，武器"刃"的一侧） |
| `#E37800` | `weaponbox` | `strong_blade` | 强剑身（防御侧，武器"背"的一侧） |
| `#7082C1` | root anchor | — | 根锚点（两个脚本都扫描此颜色） |

### 2.2 boxRole 计算

进入 resolver 之前，每个 `weaponbox` 会被打上 `boxRole`，决定它本帧扮演什么角色（`CombatCharacter.js`，`getCombatSnapshot`）：

```javascript
boxRole = (box.type === "weaponbox") ? (
  subtype === "strong_blade"
    ? (有 guardType 时 → "shield"    // 强剑身 + 防御状态 → 盾
       否则 → null)                   // 强剑身 + 非防御 → 不参与判定
    : (isActiveAttackFrame ? "attack" // 弱剑身 + 在 active window 内 → 攻击
       : null)                        // 弱剑身 + 不在 window 内 → 不参与判定
)
```

`isActiveAttackFrame` 的判断有两条路线，以 StateGraphDef 配置为准：

1. **新方案（ms-based active window）**：状态定义了 `attackActiveStartMs`，则用 `animation.elapsedInClipMs`（进入当前 clip 后的累计 ms，hitstop 期间自动冻结）与 start/end 区间比较
2. **旧方案（fallback）**：没定义 `attackActiveStartMs`，则用 `attackActiveFrames` 数组检查当前 `frameIndex` 是否在其中

**简化理解**：

- **弱剑身（红）**：仅在攻击状态的 active window 内才生效（`boxRole = "attack"`）
- **强剑身（橙）**：仅在防御状态才生效（`boxRole = "shield"`）
- **hitbox（黄）**：始终存在，但 `dodgeActive` 时会被过滤掉

一个角色某一帧可能同时携带多个 box：

- 挥剑时：一个 `attack` + 一个 `hitbox`（仅 active window 内 attack 生效）
- 举盾时：一个 `shield` + 一个 `hitbox`
- idle 时：只有 `hitbox`

### 2.3 State 属性

每个 State 在 StateGraphDef `.json` 中声明战斗相关属性：

```
attackActive: true                     ← 这是个攻击状态
attackWeight: "light" | "heavy"        ← 攻击力度
attackTrajectory: "slash" | "thrust"    ← 攻击轨迹

attackActiveStartMs: 450               ← 新方案：进入状态后多少 ms 开始 active
attackActiveDurationMs: 60             ← 新方案：active window 持续多少 ms
                                      （两字段必须同时出现；命中区间 = [startMs, startMs+durationMs)）

attackActiveFrames: [3, 4]             ← 旧方案（fallback）：哪些帧算"有效攻击帧"
                                      （仅当未定义 attackActiveStartMs 时使用）

guardType: "guard" | "shield"          ← 防御姿态类型
dodgeActive: true                      ← 闪避状态
guardActive: true                      ← 防御状态标记（暂未用于判定）
invincible: true                       ← 无敌（takeDamage 里检查）
```

## 三、两阶段结算

Resolver 严格按 Phase 1 → Phase 2 顺序执行，Phase 1 的结果会影响 Phase 2 的跳过列表。

### Phase 1: weapon vs weapon（武器碰武器）

遍历所有两两相交的 weaponbox OBB（OBB-SAT 检测，`ContactResolver.js:400-447`），按角色组合分流：

#### A. 攻击 ↔ 盾（attack vs shield）

防守方 `guardType` 决定能挡什么：

| 防守方 guardType | 能挡的攻击 |
|---|---|
| `"guard"`（剑身格挡，即长剑/木棒的"用剑身去挡"） | 挡一切 **非 thrust** 的攻击 |
| `"shield"`（盾牌） | 只能挡 `slash + heavy`（重劈） |
| 有 guardType 但未匹配 | 直接挡下（catch-all） |

被挡下后，判断是否触发 **parry（弹反/招架）**：

```javascript
canParry = defenseBox.canParry && (guardFrameIdx === 0 || tickDiff <= 16)
```

两个条件同时满足才算 parry：

- `canParry`：只有 `guardType === "guard"`（剑身格挡）的盾 box 才能触发
- 时机条件：防守方必须刚进入状态（帧 0，或 stateEnterTick 差距 ≤ 16 帧 ≈ 267ms）

结果分支：

| 结果 | 防守方 | 攻击方 |
|---|---|---|
| **Parry** | 获得 `parryBonus` tag（40帧）+ `freezeImpact` 冻结 24帧 | `freezeImpact` 冻结 24帧 + 击退 + hitstop 8帧 |
| **Block（普通格挡）** | `blockstun` 10帧 + hitstop 4帧 | hitstop 4帧 |

触发 parry 的角色，`parryBonus` tag 会让后续攻击使用 `bonusTimeScale`（zornhut 定义中是 1.75，见 `LongSwordMan.json:232`）。

#### B. 攻击 ↔ 攻击（attack vs attack）= 拼刀

两边都必须是 `boxRole === "attack"`，按 `attackWeight` 比较：

| 情况 | 结果 |
|---|---|
| weight 相同（light vs light / heavy vs heavy） | 双方都被 `freezeImpact` 冻结 24帧 + hitstop 8帧 |
| heavy vs light | **重的胜**：轻的被冻结 24帧 + 击退 + hitstop 6帧；重的 hitstop 4帧（不冻结） |

拼刀失败的攻击实例会被加入 `invalidatedAttacks`，Phase 2 里直接跳过。

#### Phase 1 共同规则

- 任一角色处于 `dodgeActive` 时，Phase 1 的所有 weapon-vs-weapon 接触直接跳过（`ContactResolver.js:47`）。

### Phase 2: weapon vs hitbox（武器碰身体）

收集所有 "攻击方 weaponbox（role=attack）× 另一方 hitbox" 的相交对，**但要过滤**：

```
跳过条件（任一命中就跳过）：
  target.dodgeActive           ← 闪避无敌
  weapon 没有 attackInstanceId ← 非攻击状态的武器框
  boxRole !== "attack"         ← shield 不打人
  invalidatedAttacks.has(id)   ← Phase 1 里被挡了/拼输了
  hitDedupe 已记录过            ← 同一攻击实例对同一目标只生效一次
```

命中后：

- 目标扣血 1（当前固定值）
- 有 knockbackX 就沿 X 推
- HP 归零 → 进入 `deathState`（默认 `"defeated"`）
- 否则进入 `hitState`（默认 `"hit"`）

## 四、时间控制（四种冻结）

`CombatCharacter.fixedUpdate` 开头先跑 `TimeControlSystem.tick()`，根据当前有没有冻结决定本帧能不能推进：

| 类型 | 效果 | 来源 |
|---|---|---|
| **hitstop** | animation `timeScale=0`，冻结所有角色 4~8帧 | Phase 1 的所有冲突（挡/拼/parry） |
| **blockstun** | 防守方状态机冻结（不能切状态），动画照常播放 10帧 | 普通格挡 |
| **hitstun（freezeImpact）** | 被击中角色冻结 24帧，animation timeScale=0，冻结结束时自动进 hit 状态 | `takeDamage` → 击退/进 hit 动画 |
| **impactContext（freezeImpact）** | Phase 1 里 clash/parry 的冻结，也是 24帧；结束时自动进 clash/hit 状态 | 拼刀/弹反后 |

`freezeImpact` 的关键设计：冻结期间角色完全不推进（不跑状态逻辑、不推进动画），冻结结束时根据预先记录的 `expectedStateAtResolve` + `stateEntrySerialAtCreate` 判断目标状态是否还有效，若有效才执行 `enterState(nextState)`，无效则静默跳过（避免 stale 状态切换）。

## 五、攻击 ID 与去重

每次 `enterState` 会 `stateEntrySerial += 1`，攻击实例 ID 拼为：

```
attackInstanceId = ${characterId}:${stateName}:${stateEntrySerial}
```

所有去重都靠它：

| 去重集合 | key 格式 | 作用 |
|---|---|---|
| `hitDedupe` | `attackId\|targetId` | 同一攻击实例对同一目标只生效一次 |
| `guardDedupe` | `attackId\|defenseCharId` | 同一攻击实例对同一防守方只处理一次拦截 |
| `clashDedupe` | `attackA::attackB`（排序后） | 同一攻击对只拼一次 |
| `invalidatedAttacks` | `attackId` | 被挡或拼输的攻击，跨帧保留直到攻击结束 |

所有集合在攻击不再活跃时自动清理（`ContactResolver.js:266-295`）。

## 六、全局 CD 与 HP

| 属性 | 位置 | 作用 |
|---|---|---|
| `globalCooldownMs` | `CombatCharacter.combat`（默认 700ms） | 从攻击状态回 idle 时 `triggerCooldown()`，`canAct()` 检查是否还在 CD 中 |
| `hp` / `maxHp` | `CombatCharacter.combat`（默认 3） | `takeDamage` 里扣；HP 归零 → 进 `deathState` → 后续 `fixedUpdate` 只跑动画不再跑状态逻辑 |

## 七、伤害、击退、hitstun 的连锁

Phase 2 命中 → `CombatSystem.fixedUpdate` 派发 effect → `takeDamage(ctx)`：

```
takeDamage(ctx):
  1. if stateDef.invincible || isDead → return false
  2. hp -= damage（默认 1）
  3. if hp <= 0 → isDead = true; enterState(deathState)
  4. if knockbackX ≠ 0 → root.position.x += knockbackX
  5. enterState(hitState) → 触发 hit 动画 → 下一帧 hitstun/freezeImpact 生效
```

## 八、Parry → 反击快攻

parry 成功后，防守方获得 `parryBonus` tag（40 帧）。在 `guard` 和 `clash` 状态的 transitions 中定义了利用此 tag 的快速分支（以 `LongSwordMan` 为例）：

```json
{
  "to": "zornhut",
  "when": [
    { "command": "zornhut" },
    { "hasTag": "parryBonus" }
  ]
}
```

同时，拥有 `parryBonus` tag 时，`CombatCharacter._getStateTimeScale()` 会使用 `bonusTimeScale`（zornhut 中为 1.75），让反击招式播放更快。
