# 音效配置指南

游戏音效的全部配置规则。工具链（切片/转码）见 `Audio Tools User Guide.MD`；素材授权登记见 `AudioLicensesInfo.MD`；架构背景见 `PROJECT_CONTEXT.md` §9.2。

---

## 1. 三层结构总览

```
触发源                          翻译层(sfx_map.json)         资产层(audio_clips.json)
─────────                      ─────────────────────        ───────────────────────
动画事件 (AnimationEvents)  ──► 必须经 sfx_map 翻译      ──► audioId → 音频文件
combat_impact (战斗结果)    ──► impact 模式规则匹配
Sequence playAudio          ──► 不经过 sfx_map，直接引 audio_clips 的 id
SceneDef.ambient / music    ──► 不经过 sfx_map，直接引 audio_clips 的 id
```

核心约定：**语义与素材分离**。动画事件只报告"发生了什么动作"，战斗系统只报告"碰撞结果是什么"，具体播哪个声音由 sfx_map 表驱动决定。改声音 = 改 JSON，不改代码。

---

## 2. 资产层：Data/Audio/audio_clips.json

每条目 = 一个可播放的声音资产：

```json
"combat_sharp_hit_light": {
    "clips": ["./Audio/sfx/weapon/xxx/slice_01.wav"],
    "volume": 0.85,
    "pitch": [0.94, 1.06],
    "bus": "sfx"
}
```

| 字段 | 规则 |
|---|---|
| `clips` | 数组，多文件时**每次播放随机选一个**（变体池）；路径相对项目根 |
| `volume` | 0-1 相对音量，可 >1 做增益（如环境音 1.2） |
| `pitch` | `[min, max]` 随机音高范围，避免重复感；**环境音不要加**（循环内音高抖动突兀） |
| `bus` | `sfx`（默认音效）/ `ambient`（环境音）/ `music`（音乐），各自独立音量总线 |

---

## 3. 翻译层：Data/Audio/sfx_map.json

把语义事件 type 翻译成 audio_clips 的 id。**未收录的 type 一律静默忽略**（不报错、不出声）。

### 3.1 direct 模式（缺省）

一对一直映射：

```json
"swing_thrust": { "audioId": "swing_thrust" }
```

### 3.2 surface 模式（脚步声）

按发声角色脚下的地表类型选声：

```json
"footstep": {
    "mode": "surface",
    "fallback": "footstep",
    "bySurface": {
        "hard": { "audioId": "footstep_hard", "volume": 0.8 }
    }
}
```

- 地表由 SurfaceQuery 按角色坐标查询（SceneDef 的 walkAreas + `defaultSurfaceType`）；
- `bySurface` 未覆盖的地表 → `fallback`；注意 fallback 条目**不带音量**时用 audio_clips 里的默认值。

### 3.3 impact 模式（战斗碰撞）

`combat_impact` 是唯一的战斗结果事件，context 携带结构化碰撞描述：

```json
"combat_impact": {
    "mode": "impact",
    "fallbacks": {
        "body_hit": "combat_body_hit_default",
        "weapon_clash": "combat_weapon_clash"
    },
    "rules": [
        { "when": { "interaction": "body_hit", "sourceMaterial": "sharp", "impactClass": "light" }, "audioId": "combat_sharp_hit_light" }
    ]
}
```

**匹配规则**：
1. `rules` **按顺序**匹配；`when` 声明的每个字段与 context 值**全等**即命中（部分匹配，不必穷举所有维度）；`when` 为空对象视为配置错误，跳过；
2. 全部未命中 → 查 `fallbacks[context.interaction]`；
3. 仍未命中 → 静默。

**context 五字段与当前取值**：

| 字段 | 含义 | 当前词汇 |
|---|---|---|
| `interaction` | 碰撞类型 | `body_hit` / `weapon_clash` / `shield_block` / `shield_broken` / `projectile_cut` / `projectile_deflect` / `projectile_hit` |
| `sourceMaterial` | 攻方撞击材质 | `sharp`（利器）/ `blunt`（钝器） |
| `impactClass` | 轻重 | `light` / `heavy`（projectile 系无，恒 null） |
| `targetSurface` | 守方呈现的表面 | `flesh` / `sharp` / `blunt` |
| `sourceKind` | 来源种类 | `weapon` / `projectile` |

**材质数据落位**（改材质 = 改状态图，不改代码）：

| 数据 | 位置 |
|---|---|
| 招式撞击材质 `impactMaterial` | StateGraphDef 各攻击态 |
| 格挡接触材质 `contactSurface` | StateGraphDef guard/shield 态（override 顶层） |
| 肉体表面 `bodySurface` | StateGraphDef 顶层（guard/shield 无 override 时兜底） |
| 投掷物材质 `material` | Data/ProjectileDefs.js |
| 轻重 `attackWeight` | StateGraphDef 攻击态（已有 gameplay 字段） |

**guard 的归类**：无盾 guard（parry/guard_block）复用 clash 效果 → interaction 是 `weapon_clash`，守方表面取其 `contactSurface`；真盾走 `shield_block`。一格攻击只响一声（靠 `contactType` 有无防重复）。

**新增一种声音组合的标准流程**：在 `rules` 加一条 `when` + 在 audio_clips 登记新 id。零代码。

## 4. 动画事件：Data/AnimationEvents/&lt;archetype&gt;/&lt;state&gt;.events.json

在动画特定帧触发声音（挥击破空、脚步、倒地等动作时机类声音）。

```json
{
    "clips": {
        "thrust": {
            "events": [
                { "frame": 1, "type": "swing_thrust" }
            ]
        }
    }
}
```

- 顶层 `clips` 按**动画 clip 名**分组；一帧可挂多个事件（同帧叠加成音层，如 zornhut 的破空+金属滑击）；
- `type` 必须在 sfx_map 有 direct 条目，否则静默；
- 事件帧惯例：**activeFrame - 1**（声音在判定帧前一帧出，音画同步）；播放 restart 时 frame 0 事件会立即触发；
- 查帧号：先看状态图里该状态的 `activeWindows`/`frames` 时长，确认落脚/挥击姿势所在帧。

**三重注册缺一不可**：
1. 事件文件本身（Data/AnimationEvents/）；
2. [AssetManifest.js](../scripts/AssetManifest.js) 对应 `animationEvents.<group>` 资源组（负责加载）；
3. [CharacterFactory.js](../scripts/CharacterFactory.js) 该状态配置加 `eventsData`（负责接线到角色）。

## 5. SceneDef 环境音 / 音乐

```json
"ambient": ["field_ambient", "crickets_ambient"]
```

- 值可以是字符串、id 数组（多轨叠加）、或条件写法 `[ { "if": "...", "ids": [...] } ]`；
- 每个条目在 ambient 总线上独立循环；
- 昼夜成对场景建议白天/夜晚各自维护，夜晚常做"底噪 + 点缀"双层（如 field + crickets）。

## 6. Sequence 里的 playAudio

过场脚本（Data/Sequences/*.json）直接引用 audio_clips 的 id，**不经 sfx_map**：

```json
{ "type": "playAudio", "atMs": 11800, "id": "duvet_rustle" }
```

- `atMs` 与同一时刻的其他事件（resumeAnimation/disposeProp 等）对齐即可表达"稍后一点"；
- `stopOnInterrupt` 默认 true——跳过过场时声音随序列停止；正常播完不会被截断。

## 7. 资产工作流

```
Audio/sfx/_raw/（原始下载件，不入包）
    │
    ├─ 音效类：convert_audio_format.ps1 切片成 wav（见 Audio Tools User Guide.MD）
    ├─ 环境音类：ffmpeg 转 OGG q4（体积减 60-90%，游戏原生支持 ogg/mp3）
    │      ffmpeg -i input -c:a libvorbis -q:a 4 output.ogg
    ▼
Audio/sfx/（游戏用成品，按 weapon/footstep/cloth/ambient 分目录）
    ▼
audio_clips.json 登记 → 需要翻译层的在 sfx_map.json 加映射 → AudioLicensesInfo.MD 登记授权
```

---

## 8. 常见坑

1. **动画事件没声音**：先查 sfx_map 有没有该 type 的 direct 映射（sequence 的 playAudio 不需要，动画事件必须要）；
2. **改了 JSON 没生效**：浏览器缓存——Ctrl+F5 硬刷新；本地 http server 端口被旧进程占着也会返回旧代码；
3. **impact 规则不命中**：检查 when 字段拼写与 context 实际词汇（如材质是 `blunt` 不是 `wood`）；规则是顺序匹配，宽条件放后面；
4. **占位音约定**：开发中未定的真实素材一律先用 `Audio/sfx/47125__gyzhor__lightsaber3.mp3`（光剑声），听到即知配错；
5. **素材先行**：新素材进游戏前先登记 AudioLicensesInfo.MD（freesound id + 作者 + 协议）。
