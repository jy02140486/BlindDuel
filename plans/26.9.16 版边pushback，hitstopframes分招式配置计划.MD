# Per-State Impact Override + Boundary Compensation — 实施计划

> 目标：每个招式可以有自己的 knockback / hitstopFrames；角色被打到墙边时，剩余击退量转给攻击者
> 核心设计：Resolve-time 定 impact intent，Apply-time 根据当前空间约束算最终位移

---

## 1. 问题诊断

### 1.1 Impact 参数当前全在 CombatTuning 全局硬读

ContactResolver 和 CombatSystem 里所有 impact 参数都从 `this.tuning` 直接读：

```js
// ContactResolver.js:221 — hit knockback
const knockback = this.#signedKnockback(targetPos, attackerPos, this.tuning.hit.victimKnockbackX);

// CombatSystem.js:81 — hitstop
const hitstopFrames = this.tuning.hit.hitstopFrames ?? 0;

// CombatSystem.js:35 — clash freezeImpact
target.freezeImpact(this.tuning.hit.freezeImpactFrames, { ... });
```

StateGraph 里即使加了 `impact: { knockback: 0.18 }`，Resolver 也看不到。

### 1.2 边界 Clamp 在 Knockback 之前执行

`BattleMode.fixedUpdate` 执行链：

```
controller
character
pushbox
stageBoundary.clampCharacter   ← clamp 在这里
combatSystem.fixedUpdate       ← knockback 在这里生成并应用
```

knockback 把角色推出边界，没有第二次 clamp 兜底。

### 1.3 Knockback 应用有两条分裂路径，时序不同

| 路径 | 应用位置 | 时机 |
|------|---------|------|
| 普通 hit | `CombatCharacter.takeDamage():225` | **立即** |
| clash / parry | `TimeControlSystem.tick():80` | **延迟**（freeze 结束后，最多 24 帧后） |

两条路径都有 boundary-aware 需求，但不能在 Resolve-time 提前算好——clash 延迟 24 帧，那时的位置关系可能已经变了。

## 2. 架构决策（钉死以下模型，后续实现不得偏离）

### 2.1 Combat Effect 生命周期

```
StateGraph (behavior declaration — 声明"这招是什么、基础 impact 参数")
    ↓
CombatCharacter.getCombatSnapshot()  — resolve defaults，输出 resolved snapshot
    ↓
ContactResolver.resolve()  — 判定接触类型 + 写入 impact intent
    ↓
CombatEffect (hit / clash / parry / block)  — 携带 impact intent
    ↓
CombatSystem  — 分发给立即路径或延迟路径
    ↓
ImpactMovementResolver (NEW)  — Apply-time 根据当前空间约束算最终位移
    ↓
Character Movement  — 写入 transform
    ↓
post-combat boundary clamp (安全网)
```
### 2.2 核心原则：Resolve-time 定 intent，Apply-time 定落地

**Resolve-time**（ContactResolver）负责：
- 判定本次接触是什么（hit / clash / guard_block / parry / dodge）
- 写入"这次接触正常应该产生多少 knockback、多少 hitstop"——这是 **intent**

**Apply-time**（ImpactMovementResolver）负责：
- 在位移真正要写入的那一刻，检查双方当前位置和边界
- 算 victim 实际能退多少
- 算 residual 转给 attacker 多少
- 不突破边界

### 2.3 各层职责不变

| 层 | 负责 | 不负责 |
|---|---|---|
| StateGraph | 声明招式的 impact 参数（行为级 override） | 运行时边界判断 / 位移计算 |
| CombatSnapshot | 把 StateGraph + CombatTuning 解析成最终 resolved 参数 | 不做任何运行时判断 |
| ContactResolver | 碰撞判定 + combat result 判定 + 写入 impact intent | 不知道边界在哪 |
| CombatSystem | 路由 effect 到立即/延迟路径 | 不直接改 transform |
| ImpactMovementResolver (NEW) | Apply-time 边界约束求解 | 不产生新的 hit / clash effect |
| StageBoundary | 只管 minX/maxX 和 clamp | 不知道 combat 规则 |

### 2.4 开放的 override 参数

**第一版只开放两个**（经过需求验证的行为级参数）：

| 参数 | 语义 | 来源 |
|------|------|------|
| `knockback` | 该行为希望对 victim 施加的水平 displacement（带方向在 resolver 确定） | State → CombatTuning default |
| `hitstopFrames` | 该行为命中时双方各自的 hitstop 帧数 | State → CombatTuning default |

**明确不开放**（保持全局）：
- `freezeImpactFrames` — combat effect 的 freeze 生命周期规则，不是招式表现参数
- `block.knockbackX` — 防御侧 pushback
- `parry.hitstopFrames` — parry 专用 hitstop
- `clash.tieHitstopFrames` / `loseLoserHitstopFrames` / `loseWinnerHitstopFrames`
- `preemptiveTickDiffMax` — parry 判定阈值，系统规则
- `blockstunFrames`

> 以上"不开放"是阶段性限制，不是架构上永远禁止。将来有具体需求（如 boss 特殊盾击推得更远）时再评估是否加入。

### 2.5 hitstop 语义保持不变

`impact.hitstopFrames` 定义为：**本次接触 attacker 和 victim 各停 N 帧**。不在第一版拆成 attacker-only / victim-only。

### 2.6 Boundary compensation 算法（钉死，第一版不修改）

```
direction = sign(victim.x - attacker.x)        // 战斗接触方向，不用 facing
requested = direction × knockbackIntent        // victim 应该被推的方向 + 大小

// Victim 侧：最多能向 requested 方向移动多少
if direction > 0:
    victimAvailable = boundary.maxX - victim.x   // 右侧边界
else:
    victimAvailable = victim.x - boundary.minX   // 左侧边界

victimMoveSign = Math.sign(requested)
victimMoveMagnitude = min(abs(requested), abs(victimAvailable))
victimActual = victimMoveSign × victimMoveMagnitude

// Residual — 没推出去的量
residual = requested - victimActual

// Attacker 侧：反向推 attacker
attackerDirection = -direction                   // 相反方向
attackerRequested = attackerDirection × abs(residual)

if attackerDirection > 0:
    attackerAvailable = boundary.maxX - attacker.x
else:
    attackerAvailable = attacker.x - boundary.minX

attackerMoveSign = Math.sign(attackerRequested)
attackerMoveMagnitude = min(abs(attackerRequested), abs(attackerAvailable))
attackerComp = attackerMoveSign × attackerMoveMagnitude
```
**特殊情况处理**：
- residual = 0：attacker 不动（正常命中，墙边没到）
- attacker 也靠边：attackerAvailable ≤ 0 → residual 丢弃（不强行守恒而越出边界）
- **第一版不设 attacker 最大反向位移**：residual 全部转给 attacker，试玩有问题再加

**不使用"near boundary"阈值**：直接 `available < requested` 即触发，比 `distToBoundary < 0.2` 之类的 magic number 更干净。

### Step 1: CombatSnapshot 增加 impact 字段

**文件**：`scripts/Systems/CombatSystem.js` — hit effect 处理分支（当前 line 79-117）

**文件**：`scripts/Systems/CombatSystem.js` — hit effect 分支

当前 hit path 里的 knockback 由 `ContactResolver` 写入 `effect.context.knockbackX`（这是 intent），然后被 `takeDamage(effect.context)` 里直接消费。

改成：CombatSystem 在调用 takeDamage 之前先调 ImpactMovementResolver，把 resolved 的 knockback 写回 effect.context。

```js
        target.applyHitstop(hitstopFrames);

        if (attacker && typeof attacker.applyHitstop === "function") {

    // takeDamage — 用 resolved knockback，不是原始 intent
    if (typeof target.takeDamage === "function") {
        const modifiedCtx = { ...effect.context, knockbackX: finalKnockbackX };
        target.takeDamage(modifiedCtx);
    }

    this._fxShake(0.25, 180);
    this._fxFlash(80);
    continue;
}
```
**注意 CombatSystem 需要能访问 stageBoundary**。当前 CombatSystem 构造函数没拿它。需要在 Scene 创建 CombatSystem 时把 `stageBoundary` 传进去（通过 constructor options）。

## 7. 风险 & 注意事项

| 风险 | 应对 |
|------|------|
| combatSystem 需要访问 stageBoundary | Scene 创建时传 constructor options；sharedContext 里本来就有，走 Scene → BattleMode → CombatSystem 或构造注入 |
| TimeControlSystem.tick 新增 worldContext 参数 | 不传时 fallback 到直接应用 knockback，兼容现有非战斗场景 |
| ImpactContext.attackerId 为 null | ContactResolver 的 clash/parry effect 里目前有 attackerId 吗？需要确认并补齐 |
| CombatSystem hit path 里 ImpactMovementResolver 调用时机 | 必须在 takeDamage **之前**，因为 takeDamage 内部会写 `position.x += knockbackX`，我们需要先算出正确的 knockbackX 再传进去 |
| 第一版 clash/parry impact 不开放 override | 明确记录为阶段限制，不是架构禁止；将来有需求再扩 |
| impact 参数未配置的攻击状态 | 全部 fallback 到 CombatTuning 默认值（0.12 / 8），行为完全不变 |
