# AI 多层决策解耦计划

> 日期：2026-09-21
> 背景：现有 AI 是单层 Utility Scoring（每 200ms 根据对手当前 phase 选最高分动作），
> 缺乏"整体战斗倾向"这一慢变量，导致一路猛攻、idle 时只能攻击、
> 连吃几打不改节奏等行为。本次重构引入 Memory → Posture → Utility 三层。

---

## 目标

把当前 AI 架构：

```
Situation → Attack/Defense/Positioning Utility → Action
```

改成：

```
             ┌→ Posture（慢变量，500ms~1s 更新一次）
Memory ──────┤
             └→ Utility（快变量，200ms 决策一次）→ Action → Outcome → Memory
Situation ───┘
```

具体收益：
- 对手 idle 时 AI 能进入"警惕待命"姿态（guard readiness 进候选池）
- 连吃几打后 Posture 自动降 aggression、升 caution，开始想退
- Positioning（advance/retreat/hold）从 fallback 提升为正式候选 action
- 连续的行为修正由 Posture 承担，Feedback Memory 只管 tactical
- "模式化程度"（tutorial vs elite vs boss）可通过 Posture 对 Memory 的敏感度来调

---

## 三层定义

### Layer 0：Combat Memory（纯记录，不做解释）

**频率**：每次 Outcome（hit/miss/parry/dodge/attack end）时 append

**内容**：

| 字段 | 含义 | 已有/新增 |
|------|------|----------|
| `entries[]` | 最近 N 条 action outcome（attack/defense 的 hit/miss/parry）| **已有**，加 decay 过滤 |
| `consecutiveHitsTaken` | 连续被击中次数（self hit → +1；self 成功防住/对手 miss → reset）| **新增** |
| `consecutiveMisses` | 连续 attack miss 次数 | **已有**（via entries 推导）|
| `oppIdleMs` | 对手 phase 进入 none 后累计持续时间 | **新增** |
| `oppLastActiveMs` | 对手上一次 active 帧的时间戳 | **新增** |

**约束**：Memory 不直接修改任何 Utility 分数。它只提供原始数据。

### Layer 1：Combat Posture（慢变量，核心）

**频率**：500ms 更新一次（或 Memory 有重大变化时触发重算）
**更新方式**：target → exponential smoothing（避免突然跳人格）

**输出**：连续值对象，debug 时可解释为标签（AGGRESSIVE / CAUTIOUS / DEFENSIVE / NEUTRAL）

```js
posture = {
    attackBias:      0.0 ~ 1.0,  // 乘到 #scoreAttack 最终分上
    defenseBias:     0.0 ~ 1.0,  // 乘到 #scoreDefense 最终分上
    advanceBias:     0.0 ~ 1.0,  // 加到 positioning approach 上
    retreatBias:     0.0 ~ 1.0,  // 加到 positioning retreat 上
    riskTolerance:   0.0 ~ 1.0,  // 乘到 threatPenalty/vulnReward 的权重上
}
```

**Target 计算公式（t=当前 tick 计算的原始目标）**：

```
t.attackBias    = baseAggression
                - min(1, consecutiveHitsTaken / 5) * cautionFromDamage
                - min(1, consecutiveMisses / 3) * cautionFromMisses
                + min(1, oppVulnerable > 0.5 ? 1 : 0) * punishDesire
                - smoothstep(oppIdleMs, 800, 2000) * idleCaution

t.defenseBias   = baseDefense
                + min(1, consecutiveHitsTaken / 3) * defenseFromDamage
                + smoothstep(oppIdleMs, 800, 2000) * readinessFromIdle
                + (oppPhase === "startup" ? 0.3 : 0)

t.advanceBias   = t.attackBias * distanceAppetite
t.retreatBias   = t.defenseBias * retreatDesire
```

**Exponential Smoothing**：

```
alpha = 0.15  // 低通系数，越小越慢
currentPosture = currentPosture + alpha * (target - currentPosture)
```

**baseAggression / baseDefense** 存在 AITuning 里作为默认值，角色级 override 放在角色的 CombatCharacter 配置里（不进 StateGraph，StateGraph 只记录能力不记录 AI 策略）。

### Layer 2：Action Utility（快变量，保持现有机制）

**频率**：200ms（decisionIntervalMs）
**改动**：在现有评分函数末尾乘入/加 posture bias

```js
// #scoreAttack 末尾
score *= posture.attackBias;
score *= posture.riskTolerance;  // threatPenalty/vulnReward 的权重乘入

// #scoreDefense 末尾
score *= posture.defenseBias;
// 新增 defensiveReadiness 分支
if (oppPhase === "none") {
    score += 0.10 * smoothstep(oppIdleMs, 800, 2000) * posture.defenseBias;
}

// #executePositioning 升为正式候选
const posScore = {
    approach: /* 当前的接近逻辑 + posture.advanceBias 加成 */,
    hold:     /* 当前的 hold 逻辑 */,
    retreat:  /* 当前的 retreat 逻辑 + posture.retreatBias 加成 */,
};
// 和 attack/defense 一起选最高分
```

## 分阶段落地（严格按顺序）

### Phase 0：纯计算，只 log 不接入

- [ ] 新建 `scripts/Systems/CombatPosture.js`
  - 构造函数吃 Memory + Situation
  - `#computeTarget()` 实现上述公式
  - `#tick()` 每 500ms（或 Memory 重大变化）调，做 exponential smoothing
  - 输出 `{attackBias, defenseBias, advanceBias, retreatBias, riskTolerance}`
- [ ] 新建 `scripts/Systems/CombatMemory.js`（或从 AIController 里抽出来）
  - `#recordOutcome(stateName, outcome)` — 记录 action 结果
  - `#recordHitTaken()` / `#recordSuccessfulBlock()` — 记录 self 防御事件
  - `#tickSituation(sit)` — 更新 oppIdleMs
  - 保留现有 entries + decay
- [ ] 跑起来，加 `[Posture]` 和 `[Memory]` 诊断 log
  - 挨打 3 次 → attackBias 是否逐渐降
  - 对手 idle 2s → defenseBias 是否逐渐升
  - 连续 miss → attackBias 是否降
  - **验证 Posture 对实际事件响应合理后**，才进 Phase 1

### Phase 1：接入 Utility（评分函数末尾乘入 bias）

- [ ] AIController 持有 Memory 和 Posture 实例
- [ ] `#scoreAttack` 末尾：`score *= posture.attackBias`
- [ ] `#scoreDefense` 末尾：`score *= posture.defenseBias`，新增 `oppPhase === "none"` 时的 defensiveReadiness
- [ ] 所有现有 AITuning 值 = neutral posture（attackBias=1.0, defenseBias=1.0）时的 baseline
- [ ] **验证行为变化是渐变而非换人格**

### Phase 2：Positioning 升为正式候选

- [ ] `#executePositioning` 拆成 `#scorePositioning(sit)` 返回 `{approach, hold, retreat}` 三个分数
- [ ] 三个分数分别加 posture.advanceBias / 不加 / posture.retreatBias
- [ ] 把 positioning 分数和 attack/defense 分数放到同一个 pool 里选最高分
- [ ] 这是 AI 感觉变化最大的一步，单独做、慢慢调

### Phase 3：Memory 从 AIController 里抽出来 + 清理

- [ ] Feedback Memory（entries + consecutiveFail/consecutiveSuccess）从 AIController 移到 CombatMemory
- [ ] consecutiveFail 仍在 attack 评分里扣 tactical penalty（**保留**，这不是 Posture 该管的）
- [ ] consecutiveFail **同时**驱动 Posture 的 attackBias 下降（**新增**，这是 strategic 层）
- [ ] 原来分散在 `#scoreAttack` / `#scoreDefense` 里的 memory 读代码，改成读 Memory 的 clean API
- [ ] 清理调试 log，保留必要的

### Phase 4：角色级 Posture 配置

- [ ] AITuning 里默认值保留
- [ ] 角色 override 放在角色的 CombatCharacter 配置 JSON 里（如 `CharacterConfigs/Rabble.json`）：

```json
{
  "aiProfile": {
    "baseAggression": 0.6,
    "baseDefense": 0.4,
    "decayAlpha": 0.15
  }
}
```

- [ ] AIController 构造时从角色配置读取，与 AITuning 默认值合并
- [ ] tutorial 敌人：baseAggression=0.3，decayAlpha=0.08（变化极慢，好预测）
- [ ] elite 敌人：baseAggression=0.8，decayAlpha=0.25（反应快，会迅速适应）

## 哪些东西**不做**

- **不做** aggressive/cautious/defensive/punishing 四个互斥 Intent 状态机 — 用连续值 + low-pass 平滑替代
- **不做** Posture 切换冷却（"连续 N tick 满足才切换"）— 低通平滑已经解决了
- **不做** Posture 直接修改 threatPenalty/vulnReward 的原始权重 — 只乘 final score，更干净
- **不把 AI 策略放进 StateGraph** — StateGraph 只记录角色能力（攻击/防御状态、weaponbox、时序），策略是角色的性格
- **不删掉 Feedback Memory 的 tactical penalty** — consecutiveFail 扣分是"这招不太好"，属于 tactical，Posture 管的是"我现在整体不想打"

## 现有系统不变的部分

- Commitment 机制（攻击/防御/闪避执行期间不重决策）
- `decisionIntervalMs` = 200ms 的高频决策节奏
- `#scoreAttack` / `#scoreDefense` 的核心评分逻辑（所有 Phase 1 之前的 tuning 值保留为 neutral baseline）
- PushboxResolver、ContactResolver、CombatResolver
- AIKnowledgeRegistry 的 weaponbox 扫描和 cache 机制
