# 26.7.28 战败重置后 ambient 不响 + _activeSounds 泄漏修复

## 一、现象

- 战败 checkpoint 重置后，新场景的 `forest_ambient` 环境音不再播放
- `AudioManager._activeSounds` 每次场景重载后单调增长（2 → 3 → 4 → 5 → 6 → 7 ...），内存泄漏

## 二、诊断过程

### 2.1 排查路径

1. 在 `AudioManager.tryResume` / `detachScene` 加诊断 log
2. 在 `AmbientPlayer.play` / `_applyPlay` / `onload` / `stop` 加诊断 log
3. 对比"首次进 prologue（正常）"与"战败重置后（异常）"的完整 log

### 2.2 关键 log 对比

**周期 1（重置后 ambient 响）**：
_applyPlay immediate play OK          ← sound.play() 调用，但静默无声
onload hasPending=false
tryResume done=false suspended        ← flag 是 false
tryResume done=false running
tryResume flushed, replayed=1         ← 这一步才真正出声

**周期 2（重置后 ambient 不响）**：
_applyPlay immediate play OK          ← 同样调用，同样静默无声
onload hasPending=false
tryResume done=true running           ← flag 残留 true，早退
（无 flushed 行）                       ← 永不补播

### 2.3 排除的假设

- **fade 遮罩拦截 pointer 事件**：`document.elementsFromPoint()` 显示中心只有 CANVAS→BODY→HTML，无遮罩层。且 `restoreCheckpoint` 走 `skipTransition:true`，根本不触发 fade
- **window 监听器被移除**：`window.dispatchEvent(new PointerEvent('pointerdown'))` 能触发 tryResume，监听器在
- **AmbientPlayer 状态清理不彻底**：`AmbientPlayer.detachScene` → `stopAll` → `stop` 已正确调 `onSoundStop`，无需改

### 2.4 锁定的根因

#### 根因 A（ambient 不响）：`_audioResumeDone` 一次性 flag 残留

- `_audioResumeDone` 语义是"context 一旦 running，loop sound 永久由 `sound.play()` 自身保证"
- 这个假设在场景重载时被打破：`detachScene` 没复位 flag，重置后 `done=true`，`tryResume` 早退不补播
- **触发条件 C**：`forest_ambient` 的 URL 在浏览器 HTTP 缓存命中，`new BABYLON.Sound()` 构造时 onload 同步触发，`isReady` 立即为 true，`_applyPlay` 走 immediate 分支立即 `play()`。但此时 sound 与 audioContext 内部接线未完全就绪，`play()` 静默失败（不抛异常但无声）
- **真正出声靠 `tryResume` flush**：用户交互延迟若干 tick 后重放，此时 sound 完全就绪，play 成功
- **是 A 把可恢复的 C 变成了不可恢复**：即使 C 是触发器，只要 flag 能复位，`tryResume` 仍可在下次交互补救

#### 根因 B（activeSounds 泄漏）：detachScene 未调 `onSoundStop`

- `AudioManager._activeSounds` 通过子 player 的 `onSoundPlay`/`onSoundStop` 回调维护
- **`MusicPlayer.detachScene`**：直接 `sound.dispose()` + `_sounds.clear()`，**没调 `onSoundStop`** → music sound 残留
- **`AudioPool.detachScene`**：只置 null + `_cache.clear()`，**没调 `onSoundStop`** → 已 load 的 sfx sound 残留
- **`AmbientPlayer.detachScene`**：走 `stopAll()→stop(id)`，stop 里有 `onSoundStop`，正确清理
- 这解释了 log 中每次 detachScene activeSounds 只减 1（只 ambient 在清），music 和 pool 各漏 1 个

## 三、修复

### 3.1 `AudioManager.detachScene`（根因 A）

复位 `_audioResumeDone = false`，让下次 `tryResume` 能 flush 补播：

```javascript
detachScene() {
    this._pool.detachScene();
    this._music.detachScene();
    this._ambient.detachScene();
    this._audioResumeDone = false;
}
```

### 3.2 `AudioManager.tryResume` flush 循环（保护性）

加 `if (sound.isPlaying) continue`，避免复位 flag 后重放已在播 sound 导致重启爆音：

```javascript
for (const [sound, meta] of this._activeSounds) {
    if (!sound.isReady) continue;
    if (!meta || !meta.loop) continue;
    if (sound.isPlaying) continue;
    try { sound.play(); replayed++; } catch (e) {}
}
```

### 3.3 `MusicPlayer.detachScene`（根因 B）

dispose 前先回调 `onSoundStop`：

```javascript
detachScene() {
    for (const sound of this._sounds.values()) {
        if (this.onSoundStop) this.onSoundStop(sound);
        try { sound.dispose(); } catch (e) {}
    }
    this._sounds.clear();
    this._current = null;
    this._fade = null;
    this._scene = null;
}
```

### 3.4 `AudioPool.detachScene`（根因 B）

清缓存前遍历调 `onSoundStop`（`entry.sound` 在 PENDING 状态可能为 null，需判空）：

```javascript
detachScene() {
    if (this.onSoundStop) {
        for (const entry of this._cache.values()) {
            if (entry.sound) this.onSoundStop(entry.sound);
        }
    }
    this._scene = null;
    this._cache.clear();
}
```

### 3.5 不改 `_ctxStateChangeBound`

故意不复位。audioContext 是单例，旧 statechange 监听器仍挂在上面照常工作。复位会导致重复绑定监听器泄漏。

## 四、验证

1. 首次进 prologue：`activeSounds=2`（music + ambient），ambient 正常播放
2. 战败重置后点击画面：log 显示 `tryResume done=false → flushed replayed=1`，ambient 响 ✓
3. 多次战败重置：`activeSounds` 稳态在 2，**不再单调增长** ✓
