# 26.7.31 进战斗 blend 结束后 zoomT 跳变修复

## 一、现象

- `enterBattleSequence` 的 `cameraBlend to=duel` blend 到战斗相机位置后，相机会突然缩放/上移一下
- 从 walkarea 底部走入 trigger 时尤其明显（hero Y 为负，blend 起点 target.y 偏离 battleYBaseline）
- 与 7.31 上午的「战败重置后缩放」是不同根因：本问题在**首次进战斗**也复现

## 二、诊断过程

### 2.1 log 铺设

在以下节点加 `[CAMDBG]` 前缀 log（统一前缀便于过滤）：
- `TimelineSequencer.cameraBlend` start/end：输出 `toState`/`state` 的 pos.y、target.y、zoomT、`DuelRig.currentZoomT`
- `DuelCameraRig.enter`：输出 state 读取前后 `currentZoomT`/`currentTarget.y` 的变化
- `DuelCameraRig.compute`：HOLD 分支前 3 帧 + 主路径前 12 帧输出 fighterDistance、rawZoomT、currentZoomT、desiredHeight、cameraY
- `BattleMode.enter`/`fixedUpdate`：输出 payload.fighterDistance、smoothedFighterDistance、targetHeight

### 2.2 log 关键证据
[CAMDBG] CamBlend→duel START toState.zoomT=1.000 rig.currentZoomT=0.000
[CAMDBG] cameraBlend END state.zoomT=undefined rig.currentZoomT=0.000   ← zoomT 丢失
[CAMDBG] DuelRig.enter ... | currentZoomT 0.000→0.000                   ← 未同步
[CAMDBG] DuelRig.compute#1 rawZoomT=1.000 currentZoomT=0.120 desiredHeight=3.440 cameraY=3.440  ← 跳变
blend 终值 `toState.pos.y=5.200`（zoomT=1.0），`compute#1` 的 `cameraY=3.440`（zoomT=0.12），**跳变 -1.76**，orthoWidth 从 32 突变到 17.92 → 突然拉近 → 缓慢拉远。

## 三、根因

### 3.1 主因：`_cloneState` 不复制 zoomT

数据流断裂链：
_lerpState ✓ state.zoomT = 1.0
→ update() baseState = _cloneState(this.state)  ✗ zoomT 丢失
→ this.state = baseState                         ✗ state.zoomT = undefined
→ enter() 读 state.zoomT=undefined              ✗ currentZoomT 未同步
→ compute#1 currentZoomT=0 vs rawZoomT=1        ✗ desiredHeight 跳变
`_lerpState` 已正确传递 zoomT，但 `update()` 紧接着 `this.state = _cloneState(this.state)`，`_cloneState` 不复制 zoomT 字段，导致下游全部丢失。

### 3.2 次因：battleYBaseline 来源不一致

- `cameraBlend` handler 用 `opponentPos.y`（运行时位置，可能为 -0.398）
- `BattleMode` 用 `SceneDefs.battleYBaseline`（配置值，=0）
- target.y 不一致 → `currentTarget.y` 从 -0.398 缓慢 lerp 到 0 → 残余缓慢上移

### 3.3 次因：fighterDistance 两个时间点不一致

- `cameraBlend` 在 500ms snapshot fighterDistance（hero 在 `moveActorTo` 中途）
- `switchMode` 在 3000ms 重新计算（hero 已到位）
- zoomT 不一致 → `desiredHeight` 跳变

### 3.4 次因：`startBlend` 用 `compute(1000,...)` 生成 toState 是 lerp 中间值

`compute(1000, ...)` 只执行一帧 lerp，`currentTarget.y` 从 fromState(-1.0) lerp 到 -0.398，**未到达 frameCtx.target.y=0**，toState 是中间值而非稳态目标。

## 四、修复方案

| 文件 | 修改 | 解决问题 |
|------|------|----------|
| `CameraManager.js` | `_cloneState`/`_copyState` 复制 zoomT | 主因：state.zoomT 不再丢失，enter 能同步 currentZoomT |
| `CameraManager.js` | `_lerpState` 传递 zoomT | blend 期间 state.zoomT 正确插值 |
| `CameraManager.js` | `startBlend` 优先调用 `targetRig.snapshot` | 次因3.4：toState 是稳态目标而非 lerp 中间值 |
| `DuelCameraRig.js` | 新增 `snapshot` 方法 | 用 frameCtx 直接计算稳态 state，不做 lerp，不修改运行时状态 |
| `TimelineSequencer.js` | `cameraBlend` 用 `pendingBattleDef.battleYBaseline` | 次因3.2：target.y 与 BattleMode 统一 |
| `TimelineSequencer.js` | `switchMode` 复用 `sharedData.cameraBlendFighterDistance` | 次因3.3：fighterDistance 全程一致 |
| `TimelineSequencer.js` | 引入 `sharedData` 机制 | sequence 期间 clip 间共享数据 |
| `ExploreMode.js` | 触发战斗时存 `pendingBattleDef` 到 sharedContext | 供 cameraBlend handler 读取 battleYBaseline |
| `BattleMode.js` | `exit` 清理 `pendingBattleDef` | 避免跨战斗残留 |

### 4.1 关键代码：`_cloneState` 复制 zoomT

```javascript
function _cloneState(s) {
    const r = {
        pos: s.pos.clone(),
        target: s.target.clone(),
        projection: s.projection,
        orthoLeft: s.orthoLeft,
        orthoRight: s.orthoRight,
        orthoTop: s.orthoTop,
        orthoBottom: s.orthoBottom,
        fov: s.fov,
        aspect: s.aspect
    };
    if (typeof s.zoomT === "number") r.zoomT = s.zoomT;
    return r;
}
```

### 4.2 关键代码：`DuelCameraRig.snapshot`

```javascript
snapshot(context, prevState) {
    // 直接用 frameCtx 的 target/fighterDistance 计算稳态 state
    // 不做 lerp，不修改 this.currentTarget/currentZoomT
    const rawZoomT = BABYLON.Scalar.Clamp(
        (fighterDistance - this.zoomMinDistance) / (this.zoomMaxDistance - this.zoomMinDistance),
        0, 1
    );
    const desiredHeight = BABYLON.Scalar.Lerp(this.minCameraHeight, this.maxCameraHeight, rawZoomT);
    const cameraY = target.y + desiredHeight;
    // ...
    state.zoomT = rawZoomT;  // 关键：写入 zoomT 供 _lerpState 传递
    return state;
}
```

### 4.3 关键代码：`startBlend` 优先 snapshot

```javascript
if (frameCtx && typeof targetRig.snapshot === "function") {
    toState = targetRig.snapshot(computeCtx, fromState);
} else if (typeof targetRig.compute === "function") {
    toState = targetRig.compute(1000, computeCtx, fromState);
}
```

### 4.4 关键代码：sharedData 机制

```javascript
// TimelineSequencer constructor
this._sharedData = {};
this.context.sharedData = this._sharedData;

// cameraBlend handler 写入
ctx.sharedData.cameraBlendFighterDistance = fighterDistance;

// switchMode handler 读取（优先复用，fallback 重新计算）
const sharedFD = ctx.sharedData?.cameraBlendFighterDistance;
if (typeof sharedFD === "number") {
    payload = { ...(payload || {}), fighterDistance: sharedFD };
}
```

## 六、设计约束更新（project_memory）

- `CameraManager._cloneState`/`_copyState` 必须复制 `zoomT` 字段，否则 `update()` 中 `this.state = _cloneState(this.state)` 会丢失 `_lerpState` 传递的 zoomT，导致下游 rig.enter 无法同步 currentZoomT
- `DuelCameraRig` 新增 `snapshot` 方法供 `startBlend` 生成稳态 toState；`compute` 因含 lerp 不适合作为 toState 来源
- `cameraBlend` handler 的 `battleYBaseline` 必须取自 `pendingBattleDef.battleYBaseline`，与 `BattleMode` 的 `targetHeight` 来源统一；`opponentPos.y` 仅作 fallback
- `TimelineSequencer.sharedData` 用于 sequence 期间 clip 间共享数据，每次 `play` 重置；`cameraBlendFighterDistance` 必须由 `switchMode` 复用，避免 fighterDistance 在不同时间点计算不一致
- `ExploreMode` 触发战斗时存 `pendingBattleDef` 到 sharedContext；`BattleMode.exit` 必须清理，避免跨战斗残留
