# 26.7.31 战败重置后进战斗相机异常缩放修复

## 一、现象

- 战败 checkpoint 重置后，再次进入战斗时相机有预期外的缩放动作
- 具体表现：`enterBattleSequence` 的 `cameraBlend to=duel` blend 到战斗相机位置后，会突然朝主人公缩放一下，类似进了 follow 或 explore rig
- 刷新页面后第一次进战斗无此问题，仅在战败重置后复现

## 二、诊断过程

### 2.1 排查路径

1. 静态分析怀疑 `BattleMode.exit()` 未被调用导致 `sharedContext` 残留
2. 在 `GameModeManager` / `BattleMode.exit` / `Game.restoreCheckpoint` / `DuelCameraRig.compute` / `TimelineSequencer.cameraBlend` 加 `[CAM-DBG]` 诊断 log
3. 对比"首次进战斗（正常）"与"战败重置后进战斗（异常）"的完整 log

### 2.2 关键 log 对比

**首次进 battle blend to=duel（正常）：**

DuelCameraRig.compute SAFETY-NET hold — basePos=null fighterDistance=undefined

**重置后进 battle blend to=duel（异常）：**

### 2.3 锁定的根因

#### 根因：`GameModeManager.start()` 不调 `prevMode.exit()`，战败重置路径跳过 BattleMode 生命周期清理

- 战败路径：`defeatSequence callback → Game.restoreCheckpoint → requestSceneSwitch → 新 Scene.init → gameModeManager.start("explore")`
- `GameModeManager.start()` 语义为"首次启动"，直接覆盖 `currentMode`，**不调用 `prevMode.exit()`**（与 `switchMode` 不同）
- 导致 `BattleMode.exit()` 被跳过，`sharedContext.basePosition/target/fighterDistance` 残留上一场战斗的值

#### 残留值如何造成缩放

1. `enterBattleSequence` 的 `cameraBlend to=duel` 在 `startBlend` 时用 `frameCtx`（当前 fighter 位置）计算 `toState`，这部分正常
2. 但 blend 期间（500-2000ms）`CameraManager.update` 走 `sampleDriven` 路径，`state` 由 `updateBlend(t)` lerp 写入，**不调 `DuelCameraRig.compute`**，所以残留的 context 此时不影响 blend
3. blend 结束 `endBlend` 调 `switchRig("duel")` → `enter()` → 下一帧 `update` 调 `DuelCameraRig.compute(sharedContext)`
4. 此时 `BattleMode` 尚未 enter（`switchMode to battle` 在 3000ms），`sharedContext.basePosition/target/fighterDistance` 仍是残留值
5. `DuelCameraRig.compute` 的安全网 `if (!basePosition || !target || fighterDistance == null)` 判定为 false（残留值非空），安全网失效
6. 残留 `fighterDistance=2.69`（偏小）→ `rawZoomT` 偏小 → `currentZoomT` 被拉到 0.08（极近景）
7. `switchMode to battle` 后 `BattleMode.updateRender` 写入新的 `fighterDistance=6.95` → `currentZoomT` 从 0.08 突跳到 0.92 → **blend 后朝主人公缩放一下**

### 2.4 排除的假设

- **`BattleMode.exit()` 里的 context 清理代码缺失**：exit 里已有清理代码，但 exit 根本没被调用，清理无效
- **`switchMode` 未调 exit**：log 确认 `switchMode explore→battle` 正常调 `explore.exit()`，路径正确
- **DuelCameraRig 安全网逻辑缺陷**：安全网本身正确，问题是残留值让它误判 context 已就绪

## 三、修复

### 3.1 `Game.restoreCheckpoint()` 显式调用 `currentMode.exit()`（根因修复）

战败重置路径的 `start()` 不调 exit 是设计语义（首次启动），在 `restoreCheckpoint` 这个"检查点重置"的特定入口补上 `currentMode.exit()` 调用，复用 `BattleMode.exit()` 里已有的 context 清理逻辑：

```javascript
restoreCheckpoint() {
    const ctx = this.sharedContext;
    const currentMode = this.gameModeManager?.currentMode;
    // 检查点重置的统一清理入口（职责划分）：
    //   - AudioManager 内部状态（_audioResumeDone/_activeSounds）由 detachScene 自清
    //     （见 plans/commits_detailed/26.7.28 战败重置后 ambient 不响修复）
    //   - GameMode 的 context 残留由此处显式调 currentMode.exit() 清
    //     原因：战败路径 defeatSequence → restoreCheckpoint → 新 Scene.init → start("explore")，
    //     start() 语义为首次启动、不调 prevMode.exit()（与 switchMode 不同），
    //     若不在此处补调，上一场 BattleMode.exit 会被跳过，
    //     context.basePosition/target/fighterDistance 残留上一场战斗的值，
    //     下一轮 enterBattleSequence blend 期间 DuelCameraRig.compute 读残值，
    //     安全网失效 → zoomT 被残值拉偏 → switchMode 后新值突跳 → "blend 后朝主人公缩放"。
    // 跳过 explore→explore 的无意义 exit/enter。
    if (currentMode && typeof currentMode.exit === "function" && currentMode.id !== "explore") {
        currentMode.exit();
    }
    // ...
}
```

### 3.2 `BattleMode.exit()` 清理 context（已有代码，配合 3.1 生效）

`BattleMode.exit()` 中清理独占的相机上下文，避免跨场景/跨战斗残留。此代码在 3.1 修复前已存在但因 exit 未被调用而无效，3.1 修复后生效：

```javascript
exit() {
    // ... combatant 状态复位 ...
    this.context.basePosition = null;
    this.context.target = null;
    this.context.fighterDistance = null;
}
```

### 3.3 不改 `GameModeManager.start()` 语义

`start()` 保持"首次启动"语义，不调 `prevMode.exit()`。理由：
- `start()` 用于场景初始化时启动初始模式，语义清晰
- 战败重置是特定场景，清理由 `restoreCheckpoint` 这个"检查点重置入口"负责，与 ambient 修复（`detachScene` 自清）的职责划分一致
- 若改 `start()` 会改变其通用语义，影响面大于必要

## 四、验证

1. 首次进战斗：`cameraBlend to=duel` 时 `ctx.basePosition=null ctx.fighterDistance=undefined`，blend 期间 `DuelCameraRig.compute SAFETY-NET hold`，`switchMode` 后 `fighterDistance=4.61 zoomT=0.45` 平滑 ✓
2. 战败重置后进战斗：`restoreCheckpoint` log 显示 `calling currentMode.exit() for mode=battle`，`BattleMode.exit CALLED` + `after cleanup: basePosition=null target=null fighterDistance=null` ✓
3. 第二次 `cameraBlend to=duel` 时 `ctx.basePosition=null ctx.fighterDistance=null`，blend 期间 `SAFETY-NET hold`，`zoomT=1.00` 稳定，无突跳 ✓
4. 异常缩放现象消失 ✓

## 五、涉及文件

- `scripts/Game.js` — `restoreCheckpoint()` 显式调 `currentMode.exit()`
- `scripts/Systems/Modes/BattleMode.js` — `exit()` 清理 context（已有代码，配合生效）

## 六、与其他修复的关系

- **与 26.7.28 ambient 修复同源**：两者都是"战败重置路径下旧场景/旧 mode 状态未清理，残留到新场景"导致的 bug
- **清理职责划分**：
  - AudioManager 内部状态由 `detachScene` 自清（AudioManager 持有自己的状态，自己清）
  - GameMode context 由 `restoreCheckpoint` 调 `currentMode.exit()` 清（mode 状态由 mode 自己的 exit 清，restoreCheckpoint 负责触发）
- 两者思路一致（补上缺失的清理调用），清理位置不同但符合"谁持有状态谁清"的原则
