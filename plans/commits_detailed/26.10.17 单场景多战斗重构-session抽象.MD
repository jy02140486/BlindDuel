# 📋 单场景多战斗重构 — 代码变更总结

> 本次改动围绕「单场景多战斗」重构展开：引入 **`BattleSession`** 作为运行时战斗上下文，使 `prologue` 场景可承载多场战斗；同时解耦了所有对全局别名 `rabbleStick / rabbleController / "enemy"` 的依赖，并实现了 per-battle 的相机配置、AI 性格 profile 与 checkpoint 策略。

---

## 1. High-Level Summary（TL;DR）

| 维度 | 详情 |
|---|---|
| **Impact（影响范围）** | 🟠 **High** — 重构核心战斗运行时管线，影响 9 个核心脚本文件 + 新增 1 个关键模块 |
| **核心目标** | 把"单场景单战斗"的硬编码假设拆解为"任意场景可承载多 BattleDef / 多 Trigger / 多敌人实体" |
| **关键新增** | `BattleSession`（严格 1v1 校验 + 解析 enter/exit sequence）+ `DuelCameraRig.applyConfig()` + `_initEnemyController()` |
| **关键废弃** | 全局别名依赖、首个 trigger推断 stageBounds/duelCamera、用 `Object.keys(sceneDef.spawns)[0]` 做 checkpoint |

### ✨ 关键变更（Top 5）
1. **新建 `BattleSession.js`** — 战斗触发时按 BattleDef 解析 live entity 并严格校验 1v1（player+enemy 各 1）。
2. **`ExploreMode.#checkBattleTrigger`** — 改为选中心距 hero 最近的 trigger（不再按数组首元素），并在 play sequence 前完成全部校验、注入 session、应用本场相机配置。
3. **`Scene._spawnEntity`** — 每个 `kind: "enemy"` 实体独立创建 controller（支持 instance-level `aiProfile` / `aiTuningOverrides`），不再绑定到全局 `rabbleController`。
4. **`BattleMode`** — 不再依赖 `combatants[0]/[1]` 数组位置猜身份，全部从 `_activeSession` 取 player/opponent；checkpoint 由 `BattleDef.onVictory.checkpoint` 策略控制。
5. **`DuelCameraRig.applyConfig()`** — 新增入口让 CameraManager 在入场 blend 前按本场 BattleDef 注入相机参数。

## 3. Detailed Change Analysis

### 🆕 3.1 新增模块 — `scripts/Systems/BattleSession.js`（新增 146 行）

**作用**：作为本次 trigger 命中后的运行时战斗上下文，把 BattleDef 的 `id` 列表解析为 live entity，并固化 enter/exit 序列与失败重试 spawn。

| 字段 | 类型 | 说明 |
|---|---|---|
| `triggerId` | `string\|null` | 命中的 trigger id；无 trigger 直入为 null |
| `battleId` | `string` | 静态配置 id |
| `battleDef` | `Object` | 引用，不复制 |
| `playerId` / `opponentId` | `string` | BattleDef.combatants 中声明的 id |
| `player` / `opponent` | `Entity` | actorRegistry 解析出的 live entity |
| `retryCheckpointSpawnId` | `string\|null` | 战败恢复 spawn（trigger.checkpointSpawn） |
| `enterSequence` / `exitSequence` | `Object\|null` | 已深拷贝，sequencer 可安全标注 |

**严格校验门禁**（任意一项失败抛 `BattleSessionError`）：
- ✅ `combatants` 必须恰好 2 个 id 且不重复
- ✅ 必须能解析到 actorRegistry 中存在的实体
- ✅ 实体未死亡（`!isDead && !disposed`）
- ✅ 实体具备战斗能力（`enterState / takeDamage / fixedUpdate`）
- ✅ **恰好 1 个 player + 1 个 enemy**（不允许用数组位置猜身份）

> 💡 设计要点：所有错误必须在入场序列播放前暴露，避免相机/AI 运行时出现诡异异常。

### 🔧 3.2 `scripts/Scene.js` — 多敌人 controller 重构

**核心改造**：
- ❌ 移除 `_rabbleControllerBound` 单例锁 + `enemy_1` 硬编码查找
- ✅ 每个 `kind: "enemy"` 实体独立创建 controller（`entity.controller = controller`）
- ✅ 新增 `_buildInstanceAiTuning(entityDef)`：无 profile/overrides 时直接复用全局 AITuning（**行为零差异、零额外分配**）；否则深拷贝 + 深合并 + 挂载 profile

**兼容别名策略**（过渡期）：
```js
// 只绑定第一个敌人作为"通用别名"；多敌人场景必须用显式 id
if (!this.rabbleController) {
    this.rabbleController = controller;       // ← 兼容旧 sequence this.rabbleStick = entity;
} else if (!this._enemyAliasWarned) {
    this._enemyAliasWarned = true; // ← 多次触发只警告一次
    console.warn(`[Scene] multiple enemies present: alias stays bound to "${this.rabbleStick.id}"`);
}
```

**场景初始化默认值**：
| 项 | 旧行为 | 新行为 |
|---|---|---|
| `stageBounds` | 取第一个 battle trigger 的 BattleDef.stageBounds | `DEFAULT_STAGE_BOUNDS`（`minX:-8, maxX:8`） |
| `cameraRig` | Object.assign 9 个镜头字段 | `cameraRig.applyConfig(DEFAULT_DUEL_CAMERA)` |
| 战斗时配置应用 | BattleMode.enter 内 setBounds/applyConfig | pending 阶段即 `applyRigConfig("duel", battleDef.duelCamera)` |

### ⚔️ 3.3 `scripts/Systems/Modes/ExploreMode.js` — Trigger 触发逻辑重写

**关键变更**：

| 旧逻辑 | 新逻辑 |
|---|---|
| 按 JSON 顺序选第一个 overlap | 用 `checkOverlap`（无副作用）收集，**选中心距 hero 最近** |
| BattleDef 缺失静默 return | `console.error` 显式报错并中止 |
| 解析后直接 mutate clip payload | 解析结果固定进 BattleSession，clip payload 在 `#injectBattleSwitchPayload` 统一注入 |
| `Object.keys(sceneDef.spawns)[0]` 默认 checkpoint | `triggerDef.checkpointSpawn ?? Object.keys(sceneDef.spawns)[0] ?? "house_door"` |

**新增私有方法**：
- `#resolveEnterSequence(battleDef, sceneDef)` — SceneDef 内联（深拷贝）→ `battleDef.enterSequence()` → 代码 fallback
- `#resolveExitSequence(battleDef, sceneDef)` — SceneDef 内联 → `battleDef.exitSequence`（深拷贝）→ `null`
- `#injectBattleSwitchPayload(sequence, battleDef, session)` — 遍历所有 `switchMode("battle")` clip 注入 `battleDef + session`

**pending 阶段应用镜头配置**（在 `sceneSequencer.play()` 之前）：
```js
if (battleDef.duelCamera) {
    this.context.cameraManager?.applyRigConfig?.("duel", battleDef.duelCamera);
}
```

### 🎯 3.4 `scripts/Systems/Modes/BattleMode.js` — Session 驱动

**enter 阶段**：
```js
const session = payload?.session ?? this.context.pendingBattleSession ?? null;
this._activeSession = session;
if (session) {
    this._combatantEntries = [
        { id: session.playerId,  entity: session.player },
        { id: session.opponentId,entity: session.opponent },
    ];
    this._combatants = [session.player, session.opponent];
} else {
    // 兜底：用 BattleDef.combatants 数组位置（仅旧路径保留），并 console.warn
}
```

**结算阶段（checkpoint 策略）**：
| 旧逻辑 | 新逻辑 |
|---|---|
| `Object.keys(sceneDef.spawns)[0]` 永远写到战场附近 | `mainKey.onVictory.checkpoint` 显式声明才推进 |
| 默认 `useHeroPos: undefined` | 策略显式 `useHeroPos:true` 才存实时位置 |
| 无 checkpoint 策略时静默保存 | `console.log` 提示「保留 retry checkpoint」 |

**fixedUpdate 阶段**：
- ❌ 不再 `rabbleController.fixedUpdate(...)`
- ✅ `opponent?.controller?.fixedUpdate?.(...)` — 只驱动 session 中本场对手

### 🤖 3.5 `scripts/Systems/AI/AIController.js` — 实例级 AI Tuning

## 4. Impact & Risk Assessment

### ⚠️ Breaking Changes / 兼容性风险

| 风险点 | 影响 | 缓解措施 |
|---|---|---|
| 全局别名 `rabbleStick/rabbleController/"enemy"` 在多敌人场景下语义变化 | 旧 sequence 继续只绑定第一个敌人 → 第二场战斗的相机/AI 会用错对手 | BattleDef 与新 sequence **必须**用显式 id（`rabble_tutor/rabble_react` 等） |
| `cameraRig` 字段直接赋值 | 已迁移为 `applyConfig()`，旧 `Object.assign` 路径被移除 | DuelCameraRig 子类需自行实现 `applyConfig()` |
| `BattleMode` 不再依赖 `context.rabbleController` | 任何外部代码仍往 context 写 `rabbleController` 不再生效 | 代码已删除解构，编译器/IDE 会提示 |
| `WorldState.currentSceneId` 默认值改为 `"prologue"` | 旧存档若以 `ep1_tavern_hall` 为基准可能跳过 prologue | 视项目目标为预期行为（开场即 prologue） |
| `BattleDef.onVictory.checkpoint` 未声明 → 不再写 checkpoint | 旧依赖 `Object.keys(sceneDef.spawns)[0]` 行为的战斗需要补 checkpoint 策略 | 已在 4 个 BattleDef 补齐；新增 BattleDef 必须显式声明 |

### 🧪 Testing Suggestions（验证建议）

| # | 测试场景 | 关键断言 |
|---|---|---|
| 1 | 单敌人旧路径（`prologue_battle`） | 行为应与重构前**完全等价**（零差异回归门禁） |
| 2 | 多敌人同场景 | 检查 `_enemyAliasWarned` 仅触发一次；后续 sequence 必须用显式 id |
| 3 | 两个 trigger AABB 同时重叠 | 选中心距 hero **最近**的触发（distSq 严格小于）；非选中 trigger 不应被 `check()` latch |
| 4 | `battleId` 引用不存在的 BattleDef | `console.error` 后**不** latch trigger、不存 checkpoint、不切换 mode |
| 5 | `actorRegistry` 缺少某个 combatant | `BattleSessionError` 在 `sceneSequencer.play()` 之前抛出 |
| 6 | 两个 combatant 都 `kind: "enemy"` | `BattleSessionError`（不允许用数组位置猜身份） |
| 7 | 战斗中切换 mode 退出 | `context.pendingBattleSession` 与 `_activeSession` 都应清为 `null` |
| 8 | 同一场景重载（带 `attack` 已完成） | 已死亡的敌人不再更新 AI；未死亡敌人行为正常 |
| 9 | 不同 BattleDef 的 `duelCamera` | `applyRigConfig("duel", ...)` 必须**在**首个 `cameraBlend` clip 之前调用（已确认在 `sceneSequencer.play` 之前） |
| 10 | `aiProfile.repetitionCostRate` 与全局 tuning 冲突 | profile 字段应**优先**生效（实例级 override） |
| 11 | `prologue_intro.json` 新时长 | 4 秒内应完成淡入 + 信件 + hero/compaion 移动到 `x=-30/-29.5` + 切回 explore |
