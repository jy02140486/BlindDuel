# 投掷物系统实现计划

> 状态：方案已定稿（2026-09-24）
> 前置：Phase 4 aiProfile 正在进行中，但投掷物系统可独立并行推进
> 大原则：先闭环（投掷→飞行→命中/被斩→销毁），不做通用 framework；承认 Projectile 和 Character 是不同的 simulation entity

---

## §1 架构总览

```
BattleMode (生命周期 + 编排)
├── _combatants[]                      // 原有
├── _projectileManager                 // 新增
│      └── Projectile[]
└── _combatSystem
       ├── ContactResolver             // 保留原名，只处理 character↔character
       └── ProjectileContactResolver   // 新增，独立类
              ├── projectile↔character hit
              └── weapon↔projectile cut
```

职责边界：
- **BattleMode**：entity 归属 + fixedUpdate 编排顺序
- **ProjectileManager**：spawn/despawn/fixedUpdate/flushDestroyed。轻量壳，不做规则判定
- **Projectile**：自己的 simulation 状态与运动，不继承 CharacterBase
- **CombatSystem**：总协调，串两个 resolver + dispatch effects
- **ContactResolver**：character↔character 规则不动，完全隔离
- **ProjectileContactResolver**：独立 resolver，不伪造 CombatSnapshot，直接读 character.getCombatSnapshot()

关键设计原则：
1. **Projectile 不伪装成 Character**：没有 stateName/frameIndex/attackInstanceId/stateDef
2. **ProjectileContactResolver 独立**：不硬塞进现有 ContactResolver，避免变成万能 resolver
3. **不缓存 snapshots**：两个 resolver 各自独立调 getCombatSnapshot()，性能 profiling 出问题再共享
4. **XY 地平面 collision + Z 轴纯视觉抛物线**：和角色 hitbox/weaponbox 同平面判定，Z 偏移不参与碰撞
5. **斩切规则用 attackTrajectory**：slash 可切，thrust 不切
6. **同 tick 优先级**：先判 projectile↔weaponbox，被切=本 tick 不再能打中任何人。幸存才判 hit

## §2 Tick Pipeline（9 步）

```
Scene.fixedUpdate(clock)
  ① _restoreEntityPositions()          // root.position←previous（Projectile duck type 自动参与）
  ② sceneSequencer.fixedUpdate(clock)
  ③ gameModeManager.fixedUpdate(dtMs, tickCount)
     ├─ 3a. characters.fixedUpdate()       // 可能触发 throw release event → spawn
     ├─ 3b. pushboxResolver.resolve(combatants)
     ├─ 3c. stageBoundary.clampCharacter()
     ├─ 3d. projectileManager.fixedUpdate() // Projectile XY 积分 + Z 视觉 arc（同 tick 第一次移动）
     └─ 3e. combatSystem.fixedUpdate(combatants, tickCount, {projectiles})
         ├─ resolver.resolve(combatants)                     // 原有
         └─ projectileResolver.resolve(projectiles, combatants)
             ├─ SubPhase A: projectile↔weaponbox (cut first)
             └─ SubPhase B: surviving↔hitbox (hit second)
         → 合并 effects → dispatch → apply
     ├─ 3f. stageBoundary.postClamp()
     └─ 3g. projectileManager.flushDestroyed() // entityPool 移除 + dispose
  ④ _snapshotEntityPositions()          // previous←current←root.position

Scene.updateRender(clock)
  ⑤ _interpolateEntities(renderAlpha)   // Projectile 免费插值
```

### Spawn Timing 语义

`release event → spawn → 同 tick 立即积分一次`。和角色"收输入同 tick 开始走"语义一致，不需要 bornTick。

### Snapshot 双用前提（已验证）

Scene.fixedUpdate 时序保证 restore(开头)→simulation(中间)→snapshot(末尾)，interpolate 只读不改。renderTransform.previous/current 严格对应 tick N-1/N 模拟位置，可双用作未来 swept collision 区间数据。

## §3 Projectile 接口合同

### 字段

```js
class Projectile {
    root: BABYLON.TransformNode                       // Babylon 挂点

    // --- Render interpolation duck type（Scene.entityPool 免费享用）---
    renderTransform = { previous: new Vector3(), current: new Vector3() }
    supportsRenderSampling = false
    snapshotRenderTransform()                         // previous←current←root.position
    restoreRenderTransform()                          // root.position←previous

    // --- Simulation state ---              
    simPos: Vector2                                   // XY 地平面（碰撞判定用）
    velocity: Vector2                                 // XY 世界空间速度
    visualOffsetZ: number                             // Z 轴视觉抛物线偏移（不参与碰撞）
    prevSimPos: Vector2                               // tick N-1 位置（swept collision 备用）
    spawnTick: number
    lifetimeMs: number                                // 超时销毁保险（推荐 3000-5000）
    isDestroyed: boolean

    // --- Identity ---  
    id: string                                        // "proj_${ownerId}_${timestamp}"
    ownerId: string
    teamId: string                                    // 由 owner 衍生
    cuttable: boolean                                 // 斩切规则开关
    damage: number                                    // 命中伤害（默认 1）

    // --- Collider（运行时动态算，不是存固定值）---  
    colliderHalfWorld: { x: number, y: number, z: number }  // 构造时算好，之后不变
    
    getCombatBox(): {                                      // 给 ProjectileContactResolver 读
        type: "projectilebox",
        id: string,
        ownerId: string,
        cuttable: boolean,
        center: { x: number, y: number, z: number },       // 动态：simPos + root.position.z
        half: { x: number, y: number, z: number },         // 固定：colliderHalfWorld
        angle: 0                                           // v1 collider 不旋转
    }

    // --- Methods ---  
    fixedUpdate(dtMs, tickCount)                      // XY 直线积分 + Z 抛物线 + lifetime 检查
    dispose()                                         // Babylon mesh / transform dispose
}
```

### fixedUpdate 运动积分

```js
// XY：匀速直线
this.simPos.x += this.velocity.x * dtSec;
this.simPos.y += this.velocity.y * dtSec;

// Z：视觉抛物线（arcHeight / duration 在构造时算好）
const t = elapsedMs / durationMs;                    // 0→1
this.visualOffsetZ = arcHeight * 4 * t * (1 - t);

// 写 Babylon root
this.root.position.x = this.simPos.x;
this.root.position.y = this.simPos.y;
this.root.position.z = baseZ + this.visualOffsetZ;  // 视觉偏移
```

### 构造参数来源

ThrowComponent.release() 调 ProjectileManager.spawn(config) 传入：
- `ownerId` / `teamId` / `facing`（决定 velocity 方向）
- `startPos`（通常是 owner 的 hand/shoulder anchor）
- `speed`（世界空间速度）
- `spriteUrl`（Projectile sprite 路径 + atlas frame 数据）
- `colliderHalfPx`（可选 override，不传则用 frameRect 自动算，§3.4）
- `cuttable` / `damage` / `lifetimeMs`
- `arcHeight` / `durationMs`（Z 轴抛物线参数）

Projectile 不 back-reference owner。

### colliderHalfWorld 构造逻辑

```js
// 优先级：config.colliderHalfPx override > frameRect 自动 > 默认 16×16
const frameW = config.frame?.w ?? config.sourceSize?.w ?? 32;
const frameH = config.frame?.h ?? config.sourceSize?.h ?? 32;
const pxToWorld = config.pxToWorld ?? 0.03;

const halfPx = config.colliderHalfPx ?? {
    x: Math.round(frameW / 2),
    y: Math.round(frameH / 2)
};

this.colliderHalfWorld = {
    x: halfPx.x * pxToWorld,
    y: halfPx.y * pxToWorld,
    z: (config.colliderDepthPx ?? 4) * pxToWorld / 2
};
```

## §3.4 Collider 尺寸约定

Projectile collider 和 Character hitbox/weaponbox 的本质差异：
- Character collider 必须扫纹理是因为多帧动画，每帧 hitbox 位置形状都在变
- Projectile 是固定形状的飞行物体，大小永远不变，只需要知道 half/2 的 world 单位尺寸

### 方案：frameRect 自动 + 手动 override 兜底

| 投掷物 | sprite frameRect | colliderHalfPx（自动） | 实际 world box |
|--------|-----------------|----------------------|---------------|
| 飞刀 | 32×8 | `{x:16, y:4}` | 0.96×0.24×0.12 |
| 长矛 | 48×6 | `{x:24, y:3}` | 1.44×0.18×0.12 |
| 石块 | 16×16 | `{x:8, y:8}` | 0.48×0.48×0.12 |
| 魔法球 | 10×10 | `{x:5, y:5}` | 0.30×0.30×0.12 |

Aseprite atlas 导出时默认开启 trim，`frame.w/h` 已经是该帧 alpha 像素的外接矩形（不含画布空白），所以直接用 `frameRect.w/h / 2` 等价于扫 alpha bounding box，零脚本成本。

**override 场景**：如果美术给飞刀 sprite 留了 padding（比如实际 blade 只有 32×4，但 frameRect 是 32×8），spawn config 里配 `colliderHalfPx: {x: 14, y: 3}` 覆盖自动值即可。这是 gameplay 手感调参，和现有 WeaponData 的 `attackWeight` 同构。

### 和 Character collider 体系的区别

Character collider = 扫纹理 → collider.json 每帧 cx/cy/w/h → 每帧 getCombatSnapshot 转 world box。
Projectile collider = spawn config + frameRect → 构造时算一次 colliderHalfWorld → `getCombatBox()` 动态返回 center（随 simPos），half 永远不变。

### 未来升级路径（不做 v1）
- OBB（旋转 AABB）：Projectile 加 `angle` 字段 → ProjectileContactResolver 用 OBB intersect。Character weaponbox 已有 `box.angle` 字段，resolver 已预留。
- Circle collider：Projectile 加 `colliderShape: "aabb"|"circle"` + `radiusPx` → ProjectileContactResolver 按 shape 分派 intersect 函数。

## §3.1 持物阶段视觉处理（Pre-release Visual）

投掷动画中有几帧需要把投掷物 sprite 画在角色手上——这是**纯视觉**，不是 Projectile gameplay entity。

### 核心决策：两个实例

- **持物阶段**：ThrowComponent 在 throw 状态进入时创建一个纯视觉 sprite plane（不参与 simulation、不进 resolver），parent 到 character.root，每帧通过 collider.json 的 `anchors.hand` 跟随。
- **飞行阶段**：Projectile（gameplay entity），只在 release 动画事件帧才 spawn，startPos 即该帧 hand anchor 的世界坐标。

为什么不合并成一个实例：
- Projectile 从第一天起就是 gameplay entity（会运动、会碰撞、进 resolver）。"被手持"时它不做这些事——硬塞 mode 会让 Projectile 类充满 `if (this.mode === 'carried')` 分支，污染设计。
- spawn timing 语义（release event → spawn → 同 tick 立即积分）天然意味着 release 之前 Projectile 不存在。

### 交接时序

```
Character.fixedUpdate() 进入 throw 状态
  ├─ ThrowComponent 创建 carried sprite plane
  │    每帧（持物阶段）：
  │      sprite.worldPos = character.root.position
  │        + (handAnchor.cx - rootAnchor.cx) * pxToWorld * character.facing
  │        + (handAnchor.cy - rootAnchor.cy) * pxToWorld
  │      （和 ExploreMode pickup 动画的 action anchor 偏移公式完全同构）
  │
  ├─ 动画推进到 releaseFrameIndex
  │    ├─ ThrowComponent.release()
  │    │    ├─ 读当前帧 hand anchor → 转世界坐标 → ProjectileManager.spawn({ startPos })
  │    │    └─ dispose carried sprite
  │    │
  │    └─ 同 tick 后续 ProjectileManager.fixedUpdate → 飞行第一帧积分
```

### CombatCharacter 新增方法

和现有 `_getCurrentRootAnchor`（collider 优先、rootMotion 兜底）同模式，只从 collider 读：

```js
getHandAnchor(frameIndex) {
    const clipName = this.animation.currentClipName;
    const colliderClip = this.config.clips?.[clipName]?.colliderData;
    const colliderFrame = colliderClip?.frames?.[frameIndex];
    return colliderFrame?.anchors?.hand ?? null;
}
```

return null 表示这一帧不需要手持位置（比如 release 之后的帧）。

投掷动画只有 `.collider.json`（没有 occupancy.json），hand anchor 直接扩展 collider.json 的 anchors 字段。

| 颜色 | 用途 | 出现位置 |
|------|------|---------|
| `#7082C1` | `anchors.root`（已有） | RootPng，每帧一个像素点 |
| **`#FF00FF`** | **`anchors.hand`**（新增） | 同一张 RootPng，每帧一个像素点标记手持/发射位置 |

### `extract_collision_boxes.ps1` 改 3 处

```powershell
# 1. 顶部加 hand 颜色常量（现有 rootColor 旁边）
$rootColor = '#7082C1'

# 2. 第 173 行现有扫 root 之后，加一行扫 hand

$handAnchor = Extract-Root $rootBmp $fr (Parse-HexColor '#FF00FF')   # ← 新增

# 3. 第 179 行 anchors 输出加 hand
```

### collider.json 输出格式

现有：`"anchors": { "root": { "cx": 103, "cy": 136 } }`

新增后：`"anchors": { "root": { "cx": 103, "cy": 136 }, "hand": { "cx": 120, "cy": 85 } }`

### 美术绘制约定

- 预备帧（举起手）：hand 在胸前或手上位置
- release 帧：hand 在投掷物实际离开的位置（Projectile 的 startPos）
- release 之后的帧：可以不画（hand 为 null，ThrowComponent 已 dispose carried sprite）

## §3.3 输入映射

和现有战斗输入（swing/thrust/guard/dodge）走同一条链路：InputSystem → PlayerController → pendingCommands → StateGraph transition condition。

| 触发源 | 键位 | 说明 |
|--------|------|------|
| 键盘 | `;` （分号） | 投掷 command |
| 手柄 | `RT`（右扳机） | 投掷 command |

StateGraph transition condition（和现有风格一致）：
```json
{ "command": "throw" }
```

PlayerController / InputSystem 需新增：
- 键位 `;` 的 keydown → `enqueueCommand("throw")`
- 手柄 `RT` 的 button → `enqueueCommand("throw")`

Character.canThrow() gate 由 ThrowComponent + Character 共同判定：
- ThrowComponent.hasAmmo() && ThrowComponent.cooldownReady()
- Character 未处于 hitstop / blockstun / attack 等不可打断状态
- 未 dead

canThrow() 返回 false 时，`throw` command 被 pendingCommands 消费但不触发 transition（和现有 canAct() 拦截逻辑同构）。

## §4 ProjectileManager API

轻量壳，只管生命周期，不做规则判定：

```js
class ProjectileManager {
    // BattleMode.enter() 时创建
    // BattleMode.fixedUpdate 里调用：

    flushDestroyed()                                  // entityPool.remove + dispose + 数组清理
}
```

## §5 ProjectileContactResolver 设计

### 两阶段 resolution（完整代码见设计对话 §5）

SubPhase A：遍历所有 projectile × 所有 character 的 weaponbox
→ 条件：`proj.cuttable && box.boxRole==="attack" && box.attackTrajectory==="slash"`
→ 命中则标记 projectile destroyed，本 tick 跳过后续判定

SubPhase B：幸存 projectile × 所有 character 的 hitbox
→ 跳过 dodgeActive 的 character（和现有 dodge 语义一致）
→ 命中则 push hit effect（复用现有 hit effect 链路）

### intersects 实现

直接复用 ContactResolver 已有的 `#obbIntersect2D`（AABB 简化版，项目约定）。Projectile collider 用 angle=0 构造 OBB 格式：`{ center, half, angle: 0 }`。

### 不做的事（v1）
- projectile↔projectile 碰撞
- swept collision / TOI
- projectile 有耐久度
- weapon↔projectile 产生 hitstop
- projectile 旋转（visual 可以旋转 mesh，但 collider angle 固定 0）

## §6 CombatSystem 扩展点

### fixedUpdate 签名变化

```js
fixedUpdate(characters, tickCount, worldContext = {}) {
    const projectiles = worldContext.projectiles ?? [];

    // 1. 原有 character↔character（完全不动）
    const characterResult = this.resolver.resolve(characters, { tickCount });

    // 2. 新增 projectile resolve
    const projectileResult = this.projectileResolver
        ? this.projectileResolver.resolve(projectiles, characters)
        : { effects: [] };

    // 3. 合并 effects → dispatch → apply（现有链路完全复用）
    const allEffects = [...characterResult.effects, ...projectileResult.effects];
}
```

### 新增 effect types

| effect.type | 来源 | 消费方 |
|-------------|------|--------|
| `hit`（复用） | projectile↔hitbox | 现有 target.takeDamage() 链路 |
| `projectile_cut` | weapon↔projectile | v1 只标记 destroyed |
| `projectile_destroy` | projectile_cut / lifetime | CombatSystem callback → projectileManager.requestDestroy() |

### 关键：ContactResolver（原有）完全不动

原有 `ContactResolver.resolve(characters)` 输入是 `characters` 数组，Projectile 不进这个数组。两个 resolver 完全隔离。
