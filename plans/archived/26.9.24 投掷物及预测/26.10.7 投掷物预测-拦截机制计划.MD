## §1 设计决策

| # | 决策 | 理由 |
|---|------|------|
| ① | **最小侵入：复用现有 #scoreCutForProjectile** | 现有 timingAlignment 三段式逻辑（完美窗口=1.0/太早衰减/太晚衰减）已够用，只要给它正确的 predictedTTI |
| ② | **预测链只做 throw 路径** | 不做 attack preemptive 预测（B1）。那条链路和现有 #scoreDefense 的 oppPhase=startup 分支重叠，风险高 |
| ③ | **#evaluateProjectileDefense 接受 overrideTTI** | 不发明新评分函数。in-flight 路径仍用 estTimeToCurrentPositionMs，windup 路径用 predictedTTI——两者共用 timingAlignment |
| ④ | **Action Commitment 风险已接受** | AI 基于预测提前启动 slash，若对手取消投掷则被锁。风险对称于现有 `preemptiveBonus`（抢先攻击可能扑空，决策③） |
| ⑤ | **不做抽象重构** | 不引入 `predictedOpponentEvents[]`（Phase 5+ 方向）。先验证 AI 是否会因为预测而自然提前行动 |

### 核心数据流（§2 的预读）

```
opp 抬手 (throw_windup)
  ↓
throwProfile.timing.startupMs  // 已知：AIKnowledgeRegistry 扫描时存下了
oppNormTime                    // 已知：opp 当前动画进度
projectileSpeed = ProjectileDefs[type].speed  // 已知：静态数据源
distance                       // 已知：#getDistanceToOpponent()
  ↓
throwRemainingMs = startupMs - (oppNormTime * totalMs)
predictedFlightMs = (distance / projectileSpeed) * 1000
predictedTTI = throwRemainingMs + predictedFlightMs
  ↓
#scoreCutForProjectile(slash, predictedTTI, {cuttable, distanceToSelf})
  // timingAlignment 三段式自然产生分数曲线：
  //   刚抬手 → predictedTTI 大 → timingAlignment≈0 → cut 分低（"还早"）
  //   抬手过半 → predictedTTI 落在 slash active 窗口 → timingAlignment=1.0 → cut 分最高
  //   快 release → predictedTTI 太小 → timingAlignment 快速降为 0 → cut 分低（"赶不上"）
```

## §2 架构位置

### 2.1 在现有决策链中的位置

```
#buildSituation (每 decision tick)
  ├─ opp 动作识别
  │     ├─ attackActive → oppPhase=startup/active/recovery（已有）
  │     └─ throwActive → oppPhase=throw_windup（已有 §4.5）
  ├─ in-flight projectile 查询 → activeProjectileThreats[]（已有 §4.5）
  └─ 【新增】throw_windup 预测
        oppPhase=throw_windup 时 → 算 predictedTTI → 塞进 Situation

#makeDecision (每 decision tick)
  ├─ attack 候选（已有）
  ├─ defense 候选（已有）
  ├─ positioning 候选（已有）
  ├─ reactive projectile defense（已有，门控 activeProjectileThreats.length > 0）
  └─ 【新增】preemptive projectile defense
        门控：oppPhase=throw_windup && predictedProjectileCuttable
        → #evaluateProjectileDefense(sit, {overrideTTI: predictedTTI})
        → 复用已有的 #findBestSlashForProjectile / #scoreCutForProjectile
        → 和 reactive 候选同池竞争
```

### 2.2 和现有 reactive 路径的关系

```
                    reactive（已有）                    preemptive（本次新增）
触发条件：         activeProjectileThreats.length > 0   oppPhase === "throw_windup"
TTI 来源：         estTimeToCurrentPositionMs           predictedTTI
                  （从已存在 projectile 实例算）          （从 throwProfile + ProjectileDefs 外推）
评分函数：         同一个 #scoreCutForProjectile         同一个 #scoreCutForProjectile（overrideTTI）
物理假设：         projectile 已在飞，speed/位置已知     projectile 尚未 spawn，假设直线飞行
```

两条路径**不互斥**：windup 阶段 preemptive 先触发（如果 timing 好），release 后 reactive 接管（如果 AI 还没 committed）。

## §4 详细设计

### 4.1 `#buildSituation`：新增预测字段

在现有 throw_windup 分支之后（line 407 附近），追加预测计算：

```js
// 现有：oppPhase=throw_windup，oppThrowProfile 已存在
// 新增：外推 predictedTTI
let predictedProjectileTTI = null;
let predictedProjectileCuttable = false;
let predictedProjectileDistance = null;

if (oppPhase === "throw_windup" && oppThrowProfile) {
    const totalMs = oppThrowProfile.timing.totalMs;
    const startupMs = oppThrowProfile.timing.startupMs;
    const elapsedMs = oppNormTime * totalMs;  // 从动画进度算已过时间
    const throwRemainingMs = Math.max(0, startupMs - elapsedMs);  // 距 release 还剩多久

    // 从 ProjectileDefs 查 speed
    const projectileDef = this.projectileDefs?.[oppThrowProfile.projectileType] ?? null;
    if (projectileDef) {
        const projectileSpeed = projectileDef.speed;
        const predictedFlightMs = (distance / projectileSpeed) * 1000;
        predictedProjectileTTI = throwRemainingMs + predictedFlightMs;
        predictedProjectileCuttable = projectileDef.cuttable === true;
        predictedProjectileDistance = distance;
    }
}
```

塞进 Situation：
```js
predictedProjectileTTI,        // number | null，仅 throw_windup 时非 null
predictedProjectileCuttable,   // boolean
predictedProjectileDistance,   // number
```

**注意**：这里的 `distance` 是当前帧的 distance。假设 projectile spawn 后飞行期间 distance 基本不变（AI 不会在 windup 到 impact 这段时间内大幅移动）。这个简化和现有 reactive 路径的 `estTimeToCurrentPositionMs` 假设一致——都不考虑 self 主动移动。

### 4.2 `#evaluateProjectileDefense`：接受 overrideTTI

当前签名：`#evaluateProjectileDefense(sit)`，内部从 `sit.activeProjectileThreats[]` 读 TTI。

改为：`#evaluateProjectileDefense(sit, options = {})`
```js
// options = { overrideTTI, overrideCuttable, overrideDistance, isPreemptive }
```

门控逻辑变化：
```js
// 原门控：activeProjectileThreats.length === 0 → return []
// 新门控：要么有 reactive threats，要么有 preemptive override
const hasReactive = threats.length > 0;
const hasPreemptive = options.overrideTTI != null;
if (!hasReactive && !hasPreemptive) return [];

// TTI 来源优先级：override > threat
const tti = options.overrideTTI ?? threat.estTimeToCurrentPositionMs;
const cuttable = options.overrideCuttable ?? threat.cuttable;
const distanceToSelf = options.overrideDistance ?? threat.distanceToSelf;
```

`#findBestSlashForProjectile` 和 `#scoreCutForProjectile` **不需要改签名**——它们本来就接受 `tti` 参数。

### 4.3 `#makeDecision`：新增门控分支

在现有 reactive projectile defense 之后（line 309 附近）追加：

```js
// 现有 reactive（in-flight）
const projResults = (sit.activeProjectileThreats?.length > 0)
    ? this.#evaluateProjectileDefense(sit)
    : [];

// 新增 preemptive（throw_windup）
if (sit.opp.phase === "throw_windup"
    && sit.predictedProjectileTTI != null
    && sit.predictedProjectileCuttable === true) {
    const preemptiveResults = this.#evaluateProjectileDefense(sit, {
        overrideTTI: sit.predictedProjectileTTI,
        overrideCuttable: true,
        overrideDistance: sit.predictedProjectileDistance,
        isPreemptive: true,
    });
    // 和 reactive 结果合并进 projResults
    for (const r of preemptiveResults) {
        r.reason = "projectile_preemptive_cut";
        r.isProjectileCut = true;
    }
    projResults.push(...preemptiveResults);
}
```

**两条路径的候选会进同一个 scored pool**——如果 windup 阶段 preemptive cut 分够高，会在 release 之前就 commit slash；如果 timing 差，release 后 reactive cut 或 dodge 会接棒。

### 4.4 AI-Diag log 新增输出

throw_windup 阶段的新行：

[AI-Diag] preemptive_cut: predictedTTI=514ms throwRemaining=300ms flight=214ms
  slash_active=[200,500]ms timingAlignment=0.97 score=0.52 top3=[attack:swing=0.52 | ...]

### 4.5 timingAlignment 曲线（自然行为）

现有 `#scoreCutForProjectile` 三段式逻辑（不需要改）：

```
tti < activeStart → 太早 → timingAlignment = max(0, 1 - (activeStart - tti) / activeStart)
tti ∈ [activeStart, activeEnd] → 完美 → timingAlignment = 1.0
tti > activeEnd → 太晚 → timingAlignment = max(0, 1 - (tti - activeEnd) / cutTooSlowSpan)
```

代入 preemptive 场景自然产出：

```
opp 刚抬手（throwRemainingMs=350ms, distance=3m, speed=14）
  → predictedFlightMs=214 → predictedTTI=564
  → self slash active=[200,500]
  → timingAlignment = max(0, 1 - (564-500)/500) = 0.87（还早，但不算太早）
  → cut 分 = cutBase(0.55) × 0.87 × distanceAlignment × attackMult ≈ 0.47
  → 如果 positioning 分 ~0.35，cut 有机会赢

opp 抬手过半（throwRemainingMs=150ms, distance=3m）
  → predictedTTI=364
  → timingAlignment = 1.0（364 ∈ [200,500]，完美窗口）
  → cut 分 ≈ 0.55 × 1.0 × 1.0 × attackMult ≈ 0.55
  → 应该赢 positioning

opp 快 release（throwRemainingMs=30ms, distance=3m）
  → predictedTTI=244
  → timingAlignment = 1.0（244 刚好在窗口里）
  → 但 throwRemainingMs=30 意味着 AI 只有 ~30ms 决策窗口
  → 如果 decision tick 没赶上，直接错过 → reactive 路径接管
```

## §5 验收标准

### 端到端验证

| 场景 | 预期 | 验证方式 |
|------|------|----------|
| 玩家抬手扔 dagger（cuttable=true）| AI 在抬手后半段启动 slash，release 后 projectile 被斩 | AI-Diag 看 predictedTTI/timingAlignment/score → 看 weaponbox 覆盖 projectile |
| 玩家抬手扔 rock（cuttable=false）| AI 不尝试 preemptive cut | AI-Diag 看 predictedProjectileCuttable=false → 无 preemptive 候选 |
| opp 抬手但 AI 没赶上（timing 差）| release 后 reactive dodge/cut 接棒 | AI-Diag 先看 preemptive cut ≈ 0.1，后看 reactive dodge 分上来 |
| opp 取消投掷（抬手后没 release）| AI 被锁在 committed slash 里，扑空 | 手动取消投掷 → 观察 AI 行为（已接受的 Action Commitment 风险） |

### Debug 输出

每次决策 tick，如果 oppPhase=throw_windup，AI-Diag log 必须包含：
- `predictedTTI`（ms）
- `throwRemainingMs`（ms）
- `predictedFlightMs`（ms）
- 选中的 slash 的 `activeStart/activeEnd`
- 最终 `timingAlignment` 和 cut score

## §7 远期架构方向（不在本次实施，但值得记录）

本次补的 throw preemptive cut 不是孤立功能——它和 BACKLOG B1 共享同一个上层能力缺口：

```
Opponent Action（已 commit 的行为）
       ↓
【本次补的】Predict Future Events（release → impact）
       ↓  （B1 补的）
       ↓
Threat / Chance（这个事件对我是威胁还是机会）
       ↓
Counter / Attack / Defense（我该怎么应对）
```

远期可能收敛为 `predictedOpponentEvents[]` 中间层，让 Utility Scoring 的输入从"原始 Situation"升级为"Situation + Predicted Events"。但这是 Phase 5+ 的事——现在先验证"AI 会因为预测 projectile 而自然提前行动"这个效果是否真实成立。
