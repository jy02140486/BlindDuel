## 2. 现状问题

### 2.1 当前所有有效碰撞 → 同一个结局：destroy

```
projectile ↔ weaponbox（cut） → projectile_cut + projectile_destroy → 直接消失
projectile ↔ hitbox（hit）     → hit + projectile_destroy → 直接消失
```

没有"被剑劈飞再落地"、没有"命中角色后弹开"的物理延续感。

### 2.2 硬编码点

- `ProjectileContactResolver.js:118-122` — hit 效果的 `knockbackX` 硬编码 `1.0`，不从 ProjectileDefs 读
- `ProjectileContactResolver.js:47-84` — cut 分支无条件推 `projectile_destroy`，没有响应配置

### 2.3 两个投掷物的需求对照

| 投掷物 | 命中角色 | 被剑斩击 |
|---|---|---|
| **dagger** | 命中、消失 | 被斩落，**弹飞** |
| **rock** | 命中、**弹飞** | `cuttable=false`，SubPhase A 直接跳过（不产生 cut 事件） |
| **spear**（预留） | 命中、消失 | 被斩落，弹飞 |

## 3. 设计原则

1. **弹飞 = Projectile 的一种运动状态**（不是独立实体）。Projectile 已有完整的重力/抛物线积分 (`fixedUpdate`)，弹飞只是给同一物体一组新的 velocity 初始值，让它走同一条积分路径。
2. **ProjectileDefs 决定响应**（不是 Resolver 里写 `if (type === "dagger")`）。以后加斧头/燃烧瓶，只改数据不改代码。
3. **Resolver 识别碰撞类型 → 按配置产出 effect**。CombatSystem 消费 effect → 调 ProjectileManager → 调 Projectile.deflect()。
4. **同 tick 优先级天然已保证**：SubPhase A（Cut First）在 SubPhase B（Hit Second）之前跑，被 cut/弹飞的 projectile 在本 tick 自动跳过 hit 判定。
5. **弹飞后不再造成原始伤害**：`state !== "flying"` 的守卫让弹飞中的 projectile 跳过所有后续 hit 判定。

```javascript
dagger: {

    // ...现有字段...
    // rock.cuttable = false → SubPhase A 直接跳过，不需要 weaponCut 响应

    contactResponses: {
        characterHit: "deflect",     // 命中角色后弹开
    },

    hitKnockbackMultiplier: 1.5,       // rock 比较重，命中角色击退更大
},

spear: {
    // ...同 dagger...
    contactResponses: {
        characterHit: "destroy",
        weaponCut:    "deflect",
    },
    hitKnockbackMultiplier: 1.2,
},
```

**注意**：不引入 `deflectParams` 配置。弹飞行为用**统一的运行时随机公式**（见 §6.2-6.3），所有 projectile 的弹飞计算规则完全一致：
- **x 方向**：符号随机，绝对值 ∈ [0, 0.25 × 掷出时的水平速度]
- **y 方向**：符号随机，绝对值 ∈ [0, 掷出时的 launchVy]（用掷出时的初始向上速度，不是弹飞时刻的当前 velocity.y）
- **视觉旋转**：符号随机，绝对值 ∈ [90, 360] 度/秒

第一版硬编码在 Resolver 里（或抽成 ProjectileContactResolver 的常量 `#DEFLECT_X_RATIO / #DEFLECT_SPIN_MIN / #DEFLECT_SPIN_MAX`），后续如果不同 projectile 需要不同比例，再从 ProjectileDefs 读。

### 4.2 向后兼容

- **所有现有字段保留不动**（ThrowComponent、AIKnowledgeRegistry 继续读原字段）
- **新字段可选**：如果某个 ProjectileDef 没有 `contactResponses`，Resolver fallback 到默认行为（weaponCut → destroy，characterHit → destroy）——与当前代码行为完全一致，零回归风险
- **新字段可选**：如果没有 `hitKnockbackMultiplier`，fallback 到 `1.0`

## 5. Projectile.js — 新增弹飞状态

### 5.1 新增字段

```javascript
constructor() {
    // ...现有字段...

    // === 新增：掷出时的初始速度（Resolver 算弹飞上限要用，不随 gravity 变化）===
    this.initialVelX = this.velocity.x;     // 构造时 velocity.x 就已经是初始水平速度（恒定不变）
    this.launchVy = this.velocity.y;        // 构造时 velocity.y 就是初始向上速度（v0）

    // === 新增：运动状态 ===
    this.state = "flying";    // "flying" = 正常飞行 | "deflect" = 弹飞中

    // === 新增：视觉旋转 ===
    this.spinDegPerSec = 0;
}
```

**为什么存 `launchVy` 单独字段？** 因为 `velocity.y` 在 `fixedUpdate` 里每帧被重力积分（`velocity.y -= gravity * dtSec`），弹飞发生在飞行途中某个时刻，此时的 `velocity.y` 可能已经是负数（正在下落）。弹飞的 y 方向上限应该是**掷出时的初始向上速度**，不是弹飞时刻的当前值。`initialVelX` 同理（虽然 velocity.x 是恒定的，但单独存一个语义更清晰）。

### 5.2 新增 `deflect()` 方法

```javascript
/**
 * 进入弹飞状态。
 * @param {object} config
 * @param {number} config.newVelX          - 新的水平速度（世界单位/秒）
 * @param {number} config.newVelY          - 新的垂直速度（世界单位/秒，向上为正）
 * @param {number} [config.spinDegPerSec=0] - 视觉旋转速度（度/秒）
 */
deflect({ newVelX, newVelY, spinDegPerSec = 0 }) {
    this.state = "deflect";
    this.velocity.x = newVelX;
    this.velocity.y = newVelY;
    this.spinDegPerSec = spinDegPerSec;
    this._elapsedMs = 0;          // 重置 lifetime 计时（弹飞独立生命周期）
    // lifetimeMs 不重置——保持 ProjectileDefs 里的原值。
    // groundY 也不变——弹飞后仍然落地在同一个 y 位置销毁。
}
```

**销毁条件自动生效**：弹飞后走同一条 `fixedUpdate`，以下两个守卫全部照常：
```javascript
if (this.simPos.y <= this.groundY) { this.isDestroyed = true; }  // 落地（ybaseline）
if (this._elapsedMs >= this.lifetimeMs) { this.isDestroyed = true; }  // 超时
```
不需要为弹飞新增任何销毁逻辑。

### 5.3 `fixedUpdate` 新增视觉旋转

```javascript
fixedUpdate(dtMs, tickCount) {
    if (this.isDestroyed) return;

    const dtSec = dtMs / 1000;
    this.prevSimPos.x = this.simPos.x;
    this.prevSimPos.y = this.simPos.y;

    // X: 恒定水平速度
    this.simPos.x += this.velocity.x * dtSec;

    // Y: 重力积分
    this.velocity.y -= this.gravity * dtSec;
    this.simPos.y += this.velocity.y * dtSec;

    // Write Babylon root
    this.root.position.x = this.simPos.x;
    this.root.position.y = this.simPos.y;
    this.root.position.z = this.baseZ;

    // === 新增：视觉旋转 ===
    if (this.spinDegPerSec !== 0 && this.spritePlane) {
        const deltaRad = this.spinDegPerSec * dtSec * Math.PI / 180;
        this.spritePlane.rotation.z += deltaRad;
    }

    // Landed —— 弹飞也走同一条物理路径，落地自动销毁（现有逻辑不变）
    if (this.simPos.y <= this.groundY) {
        this.simPos.y = this.groundY;
        this.isDestroyed = true;
        return;
    }

    // Lifetime safety net
    this._elapsedMs += dtMs;
    if (this._elapsedMs >= this.lifetimeMs) {
        this.isDestroyed = true;
    }
}
```

### 6.2 弹飞随机公式（公共工具方法）

SubPhase A 和 SubPhase B 共用同一套随机公式，抽成 Resolver 的私有方法：

```javascript
// ProjectileContactResolver 常量
static DEFLECT_X_RATIO = 0.25;        // 弹飞水平速度上限 = 0.25 × 掷出时水平速度
static DEFLECT_SPIN_MIN = 90;         // 弹飞旋转角速度下限（度/秒）
static DEFLECT_SPIN_MAX = 360;        // 弹飞旋转角速度上限（度/秒）

/**
 * 为一个 projectile 生成弹飞时的新速度和旋转参数。
 * 全随机：x 符号随机，y 符号随机，spin 符号随机。
 * @param {Projectile} proj
 * @returns {{ newVelX: number, newVelY: number, spinDegPerSec: number }}
 */
#buildDeflectConfig(proj) {
    const randSign = () => Math.random() < 0.5 ? -1 : 1;

    // x: 符号随机，绝对值 ∈ [0, 0.25 × 掷出时水平速度]
    const xMax = Math.abs(proj.initialVelX ?? proj.velocity.x);
    const newVelX = randSign() * Math.random() * xMax * ProjectileContactResolver.DEFLECT_X_RATIO;

    // y: 符号随机，绝对值 ∈ [0, 掷出时 launchVy]
    const yMax = proj.launchVy ?? 0;
    const newVelY = randSign() * Math.random() * yMax;

    // spin: 符号随机，绝对值 ∈ [90, 360] 度/秒
    const spinMag = ProjectileContactResolver.DEFLECT_SPIN_MIN
                  + Math.random() * (ProjectileContactResolver.DEFLECT_SPIN_MAX - ProjectileContactResolver.DEFLECT_SPIN_MIN);
    const spinDegPerSec = randSign() * spinMag;

    return { newVelX, newVelY, spinDegPerSec };
}
```

### 6.3 SubPhase A（weaponCut）改动

```javascript
// ===== SubPhase A: projectile ↔ weaponbox (CUT FIRST) =====
// 新增：track 本 tick 已进入"终结或弹飞"的 projectile —— SubPhase B 跳过
const deflectIds = new Set();  // 复用现有 cutIds 的位置（改名语义更准）

for (const proj of projectiles) {
    if (proj.isDestroyed) continue;
    if (proj.state !== "flying") continue;    // ← 新增：弹飞中的不参与判定
    if (!proj.cuttable) continue;

    const projBox = proj.getCombatBox();

    for (const { snap, box } of allWeaponBoxes) {
        if (box.boxRole !== "attack") continue;
        if (box.attackTrajectory !== "slash") continue;

        if (this.#intersects(projBox, box)) {
            this.#trace(`[ProjectileResolver] cut proj=${proj.id} by ${snap.characterId} box=${box.id}`);

            // === 新增：查 ProjectileDefs 决定响应 ===
            const def = getProjectileDef(proj.projectileType);
            const response = def?.contactResponses?.weaponCut ?? "destroy";  // fallback

            // 无论 destroy 还是 deflect，都先推 projectile_cut（informational + hitstop 4帧）
            effects.push({
                type: "projectile_cut",
                targetId: proj.id,
                context: {
                    projectileId: proj.id,
                    cutterId: snap.characterId,
                    cutterAttackId: box.attackInstanceId,
                    contactType: "weapon_vs_projectile"
                }
            });

            if (response === "deflect") {
                // === 新增：弹飞 effect ===
                // 用统一随机公式，所有 projectile 规则一致
                const deflectConfig = this.#buildDeflectConfig(proj);

                effects.push({
                    type: "projectile_deflect",
                    targetId: proj.id,
                    context: {
                        deflectConfig,
                        contactType: "weaponCut",
                    }
                });

                deflectIds.add(proj.id);
            } else {
                // destroy —— 现有逻辑
                effects.push({
                    type: "projectile_destroy",
                    targetId: proj.id,
                    context: { reason: "cut" }
                });
                deflectIds.add(proj.id);  // 同样标记，SubPhase B 跳过
            }

            break;
        }
    }
}
```

### 6.4 SubPhase B（characterHit）改动

```javascript
// ===== SubPhase B: surviving projectile ↔ hitbox (HIT SECOND) =====
for (const proj of projectiles) {
    if (proj.isDestroyed) continue;
    if (proj.state !== "flying") continue;       // ← 新增：弹飞中的不参与判定
    if (deflectIds.has(proj.id)) continue;        // 本 tick 已被 cut/弹飞 → 跳过

    const projBox = proj.getCombatBox();

    for (const { snap, box } of allHitboxes) {
        if (box.invincible) continue;
        if (snap.dodgeActive) continue;
        if (snap.characterId === proj.ownerId) continue;

        if (this.#intersects(projBox, box)) {
            this.#trace(`[ProjectileResolver] hit proj=${proj.id} → ${snap.characterId}`);

            // === 新增：查 ProjectileDefs 决定响应 ===
            const def = getProjectileDef(proj.projectileType);
            const response = def?.contactResponses?.characterHit ?? "destroy";
            const kbMultiplier = def?.hitKnockbackMultiplier ?? 1.0;

            // knockbackX 用 ProjectileDefs 的 multiplier（替代硬编码 1.0）
            const knockback = this.#signedKnockback(
                box.center.x,
                projBox.center.x,
                kbMultiplier
            );

            // hit effect —— 无论 destroy 还是 deflect 都正常结算伤害
            effects.push({
                type: "hit",
                targetId: snap.characterId,
                context: {
                    attackInstanceId: null,
                    attackerId: proj.ownerId,
                    targetId: snap.characterId,
                    attackLevel: null,
                    contactType: "projectile_vs_hitbox",
                    damage: proj.damage,
                    hitState: "hit",
                    knockbackX: knockback,
                    attackHitstopFrames: 0,
                    pushbackMultiplier: 0.05,
                    source: "projectile"
                }
            });

            if (response === "deflect") {
                // === 新增：命中后弹飞（比如 rock）===
                // 用同一套随机公式，与 weaponCut 弹飞规则一致
                const deflectConfig = this.#buildDeflectConfig(proj);

                effects.push({
                    type: "projectile_deflect",
                    targetId: proj.id,
                    context: {
                        deflectConfig,
                        contactType: "characterHit",
                    }
                });

                deflectIds.add(proj.id);  // 标记，本 tick 不再重复 hit
            } else {
                // destroy —— 现有逻辑
                effects.push({
                    type: "projectile_destroy",
                    targetId: proj.id,
                    context: { reason: "hit" }
                });
            }

            break;
        }
    }
}
```

## 8. ProjectileManager.js — 新增 `initiateDeflect` 方法

```javascript
initiateDeflect(projectileId, deflectConfig) {
    // 被弹飞的 projectile 不立即 destroy，让它继续自然飞行/落地
    const proj = this._projectiles.find(p => p.id === projectileId);
    if (proj && !proj.isDestroyed) {
        proj.deflect(deflectConfig);
    }
}
```

同时注意：`fixedUpdate` 里的 `isDestroyed` 守卫已经自动处理弹飞 projectile 的继续推进——不需要改。`flushDestroyed` 里自然落地销毁的弹飞 projectile 也会被正常清理——不需要改。

## 9. 同 tick 交互总结

```
某个 tick 内 dagger 同时被剑斩 + 命中 hitbox：

SubPhase A 先跑：
  → weaponbox ↔ dagger intersects
  → def.contactResponses.weaponCut = "deflect"
  → 推 projectile_deflect effect
  → deflectIds.add(dagger.id)

SubPhase B 后跑：
  → dagger.state = "flying"? 是（deflect() 还没被调，effect 还在队列里）
  → deflectIds.has(dagger.id)? 是 → continue 跳过

本 tick end：CombatSystem 处理 projectile_deflect → pm.initiateDeflect → dagger.state = "deflect"
下 tick：dagger.state !== "flying" → SubPhase A/B 都跳过它的碰撞判定
```

这个顺序天然正确：**Resolver 在本 tick 内收集所有 contact 决定，effect 在下一阶段由 CombatSystem 统一执行**。不需要实现复杂的 swept collision / TOI。

## 12. 测试场景

1. **dagger 正常飞行命中角色** → 角色扣血 + 击退（用 ProjectileDefs.hitKnockbackMultiplier）+ dagger 消失（contactResponses.characterHit = "destroy"）
2. **dagger 被 slash 斩中** → 斩击者 hitstop 4帧 + dagger 弹飞（旋转 + 向上飞）+ 自然落地消失
3. **rock 命中角色** → 角色扣血 + 击退（1.5x multiplier）+ rock 反向弹开 + 旋转 + 自然落地消失（不扣第二次血）
4. **rock 被 slash 斩中** → cuttable=false → 完全不参与 SubPhase A → 正常 hitbox 判定
5. **spear 被 slash 斩中** → 同 dagger，弹飞参数不同（1.3x velocityScale，稍快但旋转较慢）
6. **弹飞中的 projectile 不再造成伤害** → 弹飞后即使再次碰撞 hitbox 也不触发 hit effect

- 不改 melee 管道（ContactResolver）
- 不改 AI 侧（AI 当前不关心 deflect 状态）
