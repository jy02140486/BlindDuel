## 2. 需求定义

### 2.1 效果一：整体半透明

- 刀光显示期间不再是实心片，整体 alpha 打折（彗尾质感打底）。
- 静止期沿轨迹可带轻微基础渐变（刀根略透、刀尖实），增强方向感——曲线形状作为可调常量，先给线性不做花活。

### 2.2 效果二：结束消散（从起点向终点渐隐消失）

- 触发时机：即现 v1 隐藏规则的触发点（帧推进越过最后 marker 帧 / 离开攻击状态 / enterState 兜底）——**触发语义不变，把"立即隐藏"改为"启动消散"**。
- 消散表现：一条透明度分界线从 `t=0`（起点/刀根）向 `t=1`（终点/刀尖）扫过，扫过处 alpha → 0；分界线带窄羽化带（smoothstep），不是硬切。
- 消散期间 ribbon 几何**冻结原位**（世界空间，D4 天然满足），纯透明度动画，不做形变/飘散。
- 消散总时长：常量（初值 120ms，可调）；消散完成后 `setEnabled(false)` + 清采样列，回到待复用状态。
- 复用守卫：消散中途进入新攻击（新 clip 采样）→ 立即终止消散并清场，不得残留。

## 3. 设计决议记录

| 编号 | 议题 | 决议 |
|---|---|---|
| E1 | 材质路线：顶点色 alpha / 渐变贴图 / ShaderMaterial | **顶点色 alpha**。顶点数极小（细分后百级），每 tick 重写颜色数据成本可忽略；渐变贴图留给 Phase ④（横向羽化 + 能量感）一起做；ShaderMaterial 是消散手感不满意后的升级项，先不引入。理由：改一个函数 + 少量状态，最小改动 |
| E2 | 顶点色与现有 emissive 材质的兼容性（风险点） | 现材质 `diffuseColor = Black` + `emissiveColor = 刀光色` + `disableLighting`。Babylon StandardMaterial 的顶点色 RGB 乘 diffuse（黑，无视觉影响），**A 通道进 finalAlpha**（VERTEXCOLOR 宏下 `finalAlpha *= vColor.a`）——正好只借用 alpha 通道，不动色相。⚠️ 需实测验证：若 vertex alpha 未生效，检查 `mesh.hasVertexAlpha` / transparencyMode 组合；实测不通的 fallback 是把 RGB 也交给顶点色（emissive 换 diffuse 通道），再不通才考虑 ShaderMaterial |
| E3 | 消散进度更新挂哪条时钟 | **fixedUpdate 驱动**。消散由 fixed tick 推进（`progress += dtMs / DISSOLVE_MS`），与 FrameClock/时间冻结语义天然一致（hitstop 期间消散同步冻结，符合"视觉跟随判定时间轴"的 D6 精神）。不挂 `onBeforeRenderObservable`，避免与插值/暂停语义纠缠 |
| E4 | 消散挂点位置 | `CombatCharacter.fixedUpdate` 无条件调用 `trailRenderer.tick(dtMs)`（内部非消散状态直接 return，成本可忽略）。不改 enterState 挂点——`hide()` 内部行为改为"启动消散"，签名与调用点不变（D8 预留的入口） |
| E5 | 消散期间的 peek-ahead / 采样交互 | 消散启动即置 `_dissolving = true` 并清 `collectedSamples`；`update(ctx)` 开头若在消散中且检测到新 clip/新采样 → 强制清场终止消散（新攻击优先）。消散期间不可能再采样（已离开 marker 窗口），唯一入口就是新攻击复用 |
| E6 | 半透明与消散的合成 | 最终 alpha = `基础渐变曲线(t) × 整体系数 × 消散因子(t, progress)`。三因子分离各管各的，调参互不干扰；消散因子 = `1 - smoothstep(edgeStart, edgeEnd, t)`，edge 随 progress 从 -羽化带宽 扫到 1+羽化带宽 |

## 4. 实现设计（TrailRenderer.js 内部）

### 4.1 顶点色写入

`buildRibbon` 的逐顶点循环里同步写 `colors`（`Float32Array(n * 2 * 4)`）：

```javascript
// 每 tick 由 _applyVertexAlphas() 统一计算；buildRibbon 首次建带后立即调用一次
_applyVertexAlphas() {
    // 读 this.samples（细分后点列）与当前状态：baseCurve / progress
    // 对每对顶点 i（截面两顶点同 alpha）：
    //   alpha = BASE_ALPHA_CURVE(t) * GLOBAL_ALPHA * dissolveFactor(t)
    //   colors[c]=1; colors[c+1]=1; colors[c+2]=1; colors[c+3]=alpha;   // RGB 占位 1，色相走 emissive
    // this.mesh.setVerticesData(BABYLON.VertexBuffer.ColorKind, this._colors);
}
```

- `BASE_ALPHA_CURVE(t)`：静止期基础渐变，初值 `lerp(0.55, 1.0, t)`（刀根透、刀尖实，可调）。
- `GLOBAL_ALPHA`：整体半透明系数，初值 `0.9`。
- 消散参数常量：`DISSOLVE_MS = 120`、`DISSOLVE_FEATHER = 0.18`（羽化带占轨迹比例，smoothstep 带宽）。
- alpha 计算集中在这一个函数，buildRibbon 与消散 tick 共用，杜绝两份渐变逻辑。

### 4.2 消散状态机（挂在 hide()/tick() 上）

```
hide()          → 若 mesh 在显示 → _dissolving = true, _dissolveElapsed = 0（不再立即 setEnabled(false)）
                  若 mesh 本就隐藏 → 保持现状（幂等，enterState 兜底重复调用无副作用）
tick(dtMs)      → !_dissolving → return
                  _dissolveElapsed += dtMs; progress = elapsed / DISSOLVE_MS
                  progress >= 1 → 终态清场（setEnabled(false) + samples/collectedSamples 清空 + _dissolving=false）
                  否则 _applyVertexAlphas()
update(ctx)     → 开头新增：_dissolving 且（clip 变化 / 帧号回退 / 采到新 marker）→ 强制清场终止消散（E5 复用守卫）
```

### 4.3 材质创建处微调

- 保持 `MATERIAL_ALPHABLEND` + `disableDepthWrite` + `renderingOrder = 100` 不变（现有透明 pass 压盖关系不动）。
- `material.alpha` 保持 1（逐顶点 alpha 已承担透明度，材质级再打折会双重相乘，调参混乱）。

## 8. 测试场景

1. **半透明**：刀光显示期间整体半透，sprite 像素透出可见；色相与 `TRAIL_COLORS` 一致（无偏色）。
2. **基础渐变**：刀根侧 alpha 低于刀尖侧，方向感正确（facing=-1 时亦然——t 基于轨迹序，与镜像无关）。
3. **消散扫除**：攻击结束后刀光从起点向终点逐渐消失，分界线有羽化、非硬切。
4. **clash 定格**：拼刀冻结期间刀光保持显示不消散（state 未切换不触发 hide）。
5. **连续攻击复用**：消散中途出下一刀 → 旧 ribbon 立即清场，新刀光正常，无残留/闪烁。
6. **debug 采样点**：`DEBUG_POINTS` 开启时采样点行为不受本次改动影响。
7. **性能抽查**：消散每 tick 重写顶点色无明显帧耗（预期可忽略，顶点百级）。

## 10. 落地记录（2026-11-01 全部完成）

- **Step 1 顶点色通道**：E2 方案实测通过——emissive + `diffuseColor=Black` 下顶点色 A 通道正常进 finalAlpha（`mesh.hasVertexAlpha = true`），未触发 fallback。基础渐变实测后调参：`BASE_ALPHA_ROOT=0.0 / BASE_ALPHA_TIP=0.64 / GLOBAL_ALPHA=1.0`（极值 0→1 验证通道生效后回归温和值，TIP 用户手调）。

- **⚠️ E5 决议修订（实施发现）**：原计划"消散中 clip 变化即终止消散"不成立——攻击结束进 idle/recovery 后 clip **必然**变化，会在消散第一帧就清场。守卫实际挂在 **`update()` 采到新 marker 分支**（新攻击真正开始采样时）；idle/recovery 的 clip 变化放行。§3 表 E5 以本条为准。
- **Step 2.5 X 键联动（计划外新增）**：debug 采样点接入 `Scene._applyDebugVisible`（X 键）链路——`TrailRenderer.setDebugVisible()` + `CharacterBase.setCollisionVisible` 转发。顺带修正 PROJECT_CONTEXT §6 既有文档偏差（debug 总开关实为 X 键，原文误写 C 键）。
- **涉及文件**：`scripts/Components/TrailRenderer.js` + `scripts/Enties/CombatCharacter.js`（一行挂点）+ `scripts/Enties/CharacterBase.js`（一行转发）。几何结构 / 材质压盖关系 / CombatSystem / StateGraphDef / 扫描管线：零改动（兑现 TL;DR 承诺）。
