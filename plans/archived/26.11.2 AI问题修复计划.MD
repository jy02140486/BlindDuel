## 0. 背景与架构定位

BlindDuel Combat AI v1 是预测式 Utility AI：

```
对手行为观测 → 攻击预测（startup/active/recovery + 有效窗口）
    → 候选行动生成（attack / guard / dodge / throw / approach / hold / retreat）
    → 各候选独立评分（距离、威胁、人格偏好、repetitionCost、posture 乘区等）
    → 最高分执行
```

架构冻结约束（本轮修复的边界）：

1. 不为单一敌人行为新增全局评分参数，优先修现有判据口径；
2. 硬性规则不放进 Utility 软处理；
3. 不新增独立决策类型；
4. 保留评分 breakdown 可解释性。

**本轮的问题定性（GPT 评估认可）**：全部属于"现有判据口径错误"或"已定义未接线的机制"，不是架构缺陷。修复主题从"加权重"转向"明确候选资格——什么情况有资格进入评分、什么情况应退出、什么时候所有候选都不值得执行"。

## 1. 问题一：远距离玩家挥空也会触发防御反应

### 现象

玩家在 AI 根本打不到的距离（4~6m）做出攻击动作，AI 依然 dodge/guard，"看穿了空气"。

### 日志证据

```
dist=6.44 oppPhase=startup(thrust, 129ms/620ms)
defenseScore dodge → timeUntilActive=91ms decisionBuffer=100 urgency=0.09
best=dodge:dodge(0.469) > guard(0.155)
```

thrust 真实可达 ≈ maxReach(4.15) + 前冲位移 ≈ 4.5m。6.44m 物理不可达。

### 决策路径与根因（v2 修正机制叙述）

防御评分资格链：

```
① 可达性门：sit.distance > oppEffReach × 1.5 → 直接 0 分
② timing 门：startup 阶段 timeUntilActive > decisionBuffer → 0 分
③ 通过后按 oppPhase 取基础分：startup → startupCanActBase；active → activeBase
④ × defenseMult（人格乘区）
```

**v2 修正**：6.44m 这条日志走的是 **startup 分支**（urgency=0.09 即 startup timing 路径），不是 active 分支——快招（thrust 620ms）的 timeUntilActive 在很远距离也会缩进 decisionBuffer(100ms) 内，timing 门挡不住。但两条分支共享同一个可达性门，所以**共同根因不变**：

- 可达性门名不副实：`oppEffReach` 注释写"算上前冲位移"，实际只有 `maxReach + rangeBuffer(0.3)`；
- 1.5 倍裕度过大：thrust 的门开到 6.675m，把物理不可达区整段放进来；
- 门内无距离衰减：无论 startup 还是 active 分支，基础分都不随距离衰减（防御评分重构后 oppThreat 已不参与 defense 打分——代码 L541 注释明确 oppThreat 只保留给 attack 评分与 positioning retreat）。

"够不够得到"是硬性资格问题，现在被松门 + 无梯度双重软化。

### 修复方案（v2 按 GPT 意见精化表述）

防御资格使用**当前对手招式的物理可达距离**，而非任何评分外缘：

```
R_physical = 当前招式 maxReach + 该招有效阶段前冲位移 + 决策余量
if (sit.distance > R_physical × 1.1) → defense 全系候选 0 分
```

- **针对当前招式**：日志已证实 oppReach 是按招式取的（oppReach=4.15 对应 thrust），不是武器库最大值——这点无需修改，仅确认；
- **决策余量用固定倍率，不用 speed×time 计算**（否决 GPT 建议，理由见 §9）：日志显示 91ms 窗口对手可移仅 0.036m，按速度算余量约 4cm，门会紧到误伤正常贴进；固定 ×1.1（~0.4m）覆盖决策 tick 离散化与预测误差，是合理量级；
- 该门只作用于 AI 决策评分层，不触及盾牌常驻 box 的物理防御规则（两者不同层，无交叉）。

### 预期行为变化

- 4.5m 外挥空：defense 全 0，无反应；
- 冲刺攻击贴脸挥砍：前冲位移计入，防御反应保留；
- normal 距离格挡/闪避不受影响（门只收窄不可达区）。

### 实施复盘（Step 1 首版判断被实证推翻 → Step 1b 修正）

Step 1 落地后实测日志：dodge 在 4.10/4.55 正确触发（AI 后撤后 thrust 从 5.2m 落空），4.64~5.55 无反应——首版据此判定"4.64+ 无反应是正确行为（KB 上限 4.19m）"。**但玩家随后在 4.6-4.7m 被尖端命中**，推翻该判断。真实根因是**口径差**：

- AI 距离口径 = root-to-root；
- 命中判定 = weaponbox × 受击方 hitbox 重叠（ContactResolver Phase 2）；
- 受击方身体朝攻击者一侧有 ~0.45m 的 hitbox 延伸，"尖端擦身命中"恰好发生在这段延伸里。

Step 1b 修正（已落地）：

```
远端：distance > (maxReach + 前冲位移 + bodyReachAllowance) × 1.05 → 0
近端：distance < minReach − bodyReachAllowance → 0   ← 镜像缺口：贴脸死区误防御
```

`bodyReachAllowance = 0.7`（AITuning.defense，尖端命中反推校准；初版 0.45 被 Step 1c 复测推翻，见下）。近端门是 KB 数据暴露的新发现：thrust 覆盖带 [3.03, 4.15]，AI 站在 2.5m 以内时该攻击物理打不到，旧门照样放行防御。

教训：**"KB 说够不着"不等于"打不到"——距离口径与命中几何的差必须显式建模**。精确方案是 KB 扫描受击方 hitbox 逐帧延伸（替代常数），记入遗留观察项。

### Step 1c：自身闭合法则 + 命中事件日志（2026-11-02，已落地）

1b 之后再测：玩家卡在门外 ~4.9m 反复 thrust，AI **匀速 approach 穿过整个攻击循环**仍被命中。日志证实：hold=0.000（holdTimeout，问题三）、attack=0（自己够不着）→ approach 是唯一候选，AI 像传送带一样走进尖端区；门边界 4.87 与玩家站位几乎重合。

两个落地项：

1. **自身闭合法则（门级）**：AI 朝对手移动时，命中时刻距离比当前读数近——closure = `currentSpd × timeUntilActiveEnd`（窗口算到 active 结束，AI 在 startup+active 全程都在走；上限 0.3m；仅"moveIntent 朝对手"时计入）。seq2 场景验证：4.90m startup 204ms → closure ≈ 0.09m → 门 ≈ 4.96，走进尖端纳入反应区。对手侧 speed×time 维持否决（速度不可靠），自身侧方向=intent、速度=引擎实测，物理成立。
2. **[AI-Diag] COMBAT 命中事件日志**：此前 AI-Diag 只有决策侧日志、没有命中事件，"被连续命中的距离在哪"无法从日志回答。挂点 `onCombatResult`（CombatSystem 命中解析时刻回调，此刻距离≈命中距离），记录 view/outcome/dist/双方状态/对手攻击相位。

**B 方案（根治 walk-in 循环：让 hold 活过来）= Step 2/3，做完这两步后重新验收本场景。**

#### Step 1c 复测结论（2026-11-02，defenseGate REJECT 观测日志）

观测日志先排除了三个嫌疑输入——closure 完全正常（`toward=true spd=0.40 intent=-1 win=242ms`），但暴露了真凶：**`bodyReachAllowance=0.45` 低估了受击方 hitbox 实际延伸**。

```
startup dist=4.94  REJECT dangerFar=4.93  ← 差 0.01m，拒掉后即被命中（HIT 4.95）
active   dist=4.90  REJECT dangerFar=4.89  ← 差 0.01m
实测命中带：4.90-5.10（多轮一致）；5.33/5.36 被拒后无命中
```

公式物理上限 (4.15+0.45)×1.05=4.83 vs 实测接触 4.9-5.1——0.45 是从旧观察（命中 4.6-4.7m）反推的，新 COMBAT+REJECT 双日志证明真实延伸 ≈0.75-0.8。**重校准 0.7**：(4.15+0.7)×1.05=5.10 覆盖全部实测命中，5.33+ 仍被拒。附带修正：静止在 4.91m（toward=false、closure=0）也从拒变过门——静止贴尖端本就是实证危险位。

## 2. 问题二：近距离进攻欲望过高，基本不后退

### 现象

距离 1.3~2.0m 时持续出招，连攻不中也只偶尔 dodge，从不拉开。

### 日志证据

```
dist=1.35~2.06 全场采样：retreat=0.000 恒成立（一次未触发）
attack rf=1.00（近距满分），behavior loop: attack → hold → attack ...
retreatMult 被 posture 钳在下限（CAUTIOUS: ret=0.72~0.73）
```

### 根因：近距离带的欲望真空

| 候选 | 近距得分 | 原因 |
|------|---------|------|
| attack | 0.4 × attackMult（满分） | rangeFactor 只在远端（> effectiveRange）衰减，近端无衰减 |
| retreat | 0 | 触发线 = idealEffReach × 0.4 ≈ 1.15m，整个近距离带在门槛外 |
| hold | ≤0.2 且被超时清零（问题三） | |
| defense | 0（opp idle 无 threat） | |

spacing 修正只有"太远想靠近"和"贴脸死区想退出"两个端点，中间整段唯一的动机就是打。结构性空档，不是单参数偏高。

### 修复方向（v2：保留 A+B 框架，数值待真实公式复核后定）

**A. attack 近距侧衰减** + **B. retreat 中间档（≤0.7×idealEffReach，基分待定）**，两者必须成对——单加 B 永远赢不了（retreatMult 被钳 0.7 下限）。

**v2 采纳 GPT 的两点修正**：

1. **数值论证不足**：GPT 用 attackMult=0.6、retreatMult=0.7 复算，1.9m 处 attack ≈ 0.214 vs retreat 0.175——attack 仍赢。v1 计划的预期表格过度乐观。**实施前必须用真实评分公式（含 posture 乘区、attackPreferences、repetitionCost）重算各距离带的全候选分数**，再定中间档基分与衰减下限；衰减下限（v1 草案 0.7）与中间档基分（v1 草案 0.25）均为待验证起点，不是结论。
2. **衰减锚点应考虑招式个体差异**：idealEffReach 是全招式中位数锚点，用它衰减所有攻击会让短招（dash minR=1.11）在 1.5m 被无差别惩罚，尽管那正是它的舒适距离。实施时评估将近距衰减锚定到**单招自己的射程带**（如以该招 minReach~maxReach 为参照），让长招先于短招感受贴脸劣势；若实现复杂度过高，退而求其次保持角色级锚点但降低衰减强度。此决定在真实公式复算时一并定。

**不受影响面（验收红线）**：opp startup 时的 preemptive/clashSeeker 加成（0.6+）必须仍能压过 retreat——正常攻防交换中 AI 不得为满足 retreat 偏好机械后退。

## 3. 问题三：maxHoldMs=0，hold 永久超时（v2：需定义完整超时语义）

### 现象与根因

```
holdTimeout: holdDuration=70.0s > maxHoldMs=0.0s → holdScore=0
hold 分数每 tick 闪烁：0.201 → 清零 → 0.081 → 清零 → ...
```

`maxHoldMs = 总攻击时长 × (1 - baseAggression)`，aggression=1.0 → 0 → hold 每 tick 判超时。日志中 holdDuration=70s 证明**计时器只在 commit 攻击/移动时重置，超时后保持归零**——不只是"刚开始就超时"，是永久禁用。

### 修复方案（v2 按 GPT 意见补语义定义）

先明确语义再改代码，三个决定：

1. **超时是周期性的，不是一次性的**：timeout 触发时同时重置 holdCommitStart——hold 进入新一轮评价周期，而不是永久禁用。语义：holdTimeout 表达"这个位置意图该重新评价了"，不是"永远不许再 hold"；
2. **最低保有期下限**：`max(计算值, 400ms)`，400ms 是防抖起点，不是已证明的设计值，随验收调整；
3. **baseAggression=1.0 是合法边界**：系统必须能处理它（方案 1+2 已覆盖），不通过"配置避开 1.0"绕过；同时增设边界回归场景（§8）。

**遗留观察（不在本批动）**：`总攻击时长求和` 使招式数量间接决定 hold 时长——加一招攻击会改变角色能 hold 多久，这个耦合是否有设计意图待查。按架构冻结，本轮不重设计该公式。

## 4. 问题四：评分全零塌缩 → 0 分 dodge 平局获胜

### 现象与根因

用户观察"大概失败五次会做一次 dodge"。日志证实该 dodge 与防御无关：

```
dist=1.48 oppPhase=none → best=dodge:dodge(0.000) top3=[dodge=0.000 | guard=0.000 | thrust=0.000]
```

三个机制叠加：attack 被 repetitionCost 压负 → hold 被超时清零（问题三）→ retreat 无资格（问题二真空带）→ **全场候选 ≤ 0，dodge 以 0.000 靠候选遍历顺序赢平局**。决策结果不再代表任何战术意图。

### 修复方案（v2 采纳 GPT 的语义修正：中立 fallback，不是强制 hold）

落地 `committedScoreThreshold`（AITuning 已定义 0.15、注释"评分超过此阈值才执行 committed action"，决策层从未读取——已确认）。

**语义按 GPT 修正**：

- 阈值只约束 **committed action**（attack / guard / dodge / throw 等需主动进入动作状态的候选）；
- **positioning 意图（approach / hold / retreat）按自己的资格规则评价**，不受此阈值约束（它们已有距离门控）；
- 若无任何 committed action 达标：**本次不提交新的战斗动作**，保持当前移动意图与允许的待机状态——而不是 fallback 到 hold 候选（v1 写法与 holdTimeout 冲突：hold 自己可能已被清零）；
- 不新增 `kind:"idle"` 决策类别——"无值得提交的动作"是仲裁的正常结果，不是一种选择。

**0.15 的数值正确性未经证明**（GPT 提醒）：可能过滤掉低分但有价值的投掷物防御，或在防御型人格评分环境中抑制合理反应。作为回归验证项处理，不是定论。

### 架构意义

系统从"必须每 tick 选出一个赢家"转向"达到足够战术价值才提交动作"。玩家看到的每个 dodge/guard 都对应真实评分动机，可读性同步提升。

### 落地记录（2026-11-02）

实现取"过滤池"而非"只看最高分"：排序后一次性把 score < 0.15 的 committed 候选移出候选池，再取最高分——若最高 committed 被过滤但次级 committed 达标（或 positioning 更优），池内自然产生正确赢家。positioning 三候选（approach/hold/retreat）不受阈值约束；全部候选为 0 时走既有"原地待机"分支（moveIntent 清零），语义等同"不提交战斗动作"。新增 `[AI-Diag] commitArbitration:` 打印被过滤候选与仲裁后 best（debugVisible 门控）。

已知边界：guard 的 defensiveReadiness 分支上限 0.08 < 0.15，该分支产物会被稳定过滤——这是"无威胁不出防御动作"的预期语义，但列入回归观察（若出现该反应本该触发而未触发的场景，重估阈值或该分支权重）。

## 5a. Step 5：dodge i-frame 意识（2026-11-02 新增）

### 问题

决策层对 dodge 的理解与游戏机制错位。dodge 的安全机制 = **i-frame（`dodgeActive` 状态全免疫，ContactResolver L53/L577/L649），不是位移拉开距离**——是时机判断而非距离判断。当前评分模型三层里只有一层对：

| 层 | 现状 | 评估 |
|----|------|------|
| 反应时机门（decisionBuffer + reflexOffset） | timeUntilActive ≤ buffer 才允许防御打分 | 部分对——i-frame 对齐的粗糙代理 |
| 有效性判定（evaluateInteraction） | 静态 trajectory/weight 相性检查 | **不评估时机**——i-frame 窗口与攻击 active 窗口是否重叠完全没查 |
| Distance Consequence | 按 dodge 位移相对 preferredRange 打分 | **语义错位**——把 dodge 当走位工具评价，位移只是副作用 |

实证：4.10m 处 dodge 时攻击命中只剩 ≤16ms，AI 安全纯靠后撤距离 + thrust 本来够不着，i-frame 判断未参与。

### 关键代码事实（已核实）

`dodgeActive` 是 **stateDef 级标志**（CombatCharacter L414：`currentStateDef?.dodgeActive === true`），即 **dodge 全状态期间无敌，无相位窗口**。这把重叠判定简化为：**决策时刻到 dodge 状态实际生效（dodgeActive=true）之间的延迟，是否晚于预测命中时刻**。

### 修复方案

**资格门（硬规则，符合本轮"资格判定"主题）**：

```
escapeLatency = 从当前自身状态到 dodgeActive=true 的预计延迟
  （idle → 0；recovery/active 等不可取消状态 → 剩余时长）
if (timeUntilHit < escapeLatency) → dodge 候选 0 分
```

`timeUntilHit` 用 events 层现成的 `opp_attack_active_window.startMs`；escapeLatency 需要 self 状态相位（sit 层已有 ownState 信息）。

**Distance Consequence 权重调整（软处理，视验收）**：dodge 的位移代价分下调或豁免——它的价值主体是 i-frame，位移是副作用。等 Step 2/3/4 稳定后观察再定，避免一次引入两个变量。

### 验收

- AI 处于自身攻击 recovery 中、玩家快招即将命中 → 不再出现"评分选了 dodge 但来不及进入 dodgeActive 被命中"；
- idle 状态下的正常 dodge 反应不受影响（escapeLatency=0）。

## 8. 遗留观察项（不在本批修复）

- **KB 扫描受击方 hitbox 逐帧延伸，替代 `bodyReachAllowance` 常数**（Step 1b/1c 双教训的精确解：常数已两轮反推校准 0.45→0.7，逐角色/逐帧 hitbox 数据在 collider atlas 里可得）；

- `#getClosestMinReach` 与 retreat 底线（idealEffReach×0.4）双"太近"定义并存，v2 重构后需再核；
- Distance Consequence 对 dodge 的 clamp(0.25) 在问题一修复后权重作用面变小，是否重估；
- 测试角色 baseAggression=1 的配置来源（§3 已保证系统可处理该边界，来源仍待查）。
- **防御时机门的 reflexOffset 抽卡属性（原 Step 6，2026-11-03 关闭时转观察）**：opp startup 时防御时机门仅在最后 `decisionBuffer(100+reflexOffset)` ms 打开，reflexOffset 每决策 tick 从 0~reflexMaxMs(≈200) 重抽 → 射程边缘攻防交换中 guard/dodge 能否及时参与约 23% 概率随机；未开门的 tick 中 attack 的 preemptive/PUNISH 加成不校验我方命中是否早于 opp active，物理上会被打断的攻击仍拿加分过仲裁（实证：zornhut vs swing 场景，swing 0.182 过阈 → commit 锁定 → self:hit）。定性：不是判据口径错误，是"反应门天然带概率属性"——与局势危险程度无关的抽卡，严格来说不算缺陷。**已推演方案（未实施）**：6b = guard 早开豁免（AI 在 oppEffReach 内 + opp startup → guard 跳过时机门；guard 可随时取消早开无成本，dodge 有锁死保持严格门），单做 6b 即可修掉当前场景，残留缺口为不可格挡招与无 guard 角色；6a = attack 侧截击可行性门（我方预计命中晚于 opp active 起始 → preemptive/PUNISH/clash 加成不生效）。**观察判据**：该场景造成实际受伤的频率（`[AI-Diag] COMBAT` HIT 日志中 opp startup 期 commit attack 被打断的比例），非"是否出现"本身；频率高到影响体验再回来补 6b。
