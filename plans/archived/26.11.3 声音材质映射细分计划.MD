# 26.11.3 声音材质映射细分计划

> 状态（2026-11-03）：**Step 1-3 全部实施并验证通过**。7 个 combat_* 语义事件已收敛为统一 `combat_impact` Impact Event + SfxResolver impact 条件规则匹配；材质字段（impactMaterial/contactSurface/bodySurface/material）已在 3 个状态图 + ProjectileDefs 标注完毕。占位音效仍为光剑（共 7 条：footstep_hard、combat_body_hit/stone_hit/wood_clash/weapon_clash/shield_block/shield_break），真素材到位后仅替换 audio_clips.json。首批规则 3 条（stone 打肉体 / 木棍拼刀 / 钢剑拼木棍），新增组合 = 加 JSON 规则零代码。Step 4 backlog 未启动。

> 核心原则（承接 plans/26.11.3 声音系统事件驱动改造计划.MD）：**碰撞系统决定发生了什么，音频系统决定这个结果应该听起来是什么样子。**
> 架构来源：plans/HandOff.MD（GPT 意见）——统一 Impact Event + 条件规则匹配 + 分层 fallback，经项目实际核对后修订。

## 0. 背景与问题

上一轮改造落地了 7 个 `combat_*` 语义事件（hit/clash/guard_block/shield_broken/projectile_cut/projectile_deflect/projectile_hit），但存在与脚步声同构的问题：

1. **hit 与接触双方材质有关**：钢剑砍肉体 vs 木棍打肉体应不同声；砍中盔甲（未来）更不同
2. **clash 与轻重有关**：轻斩拼刀 vs 重斩拼刀应有力度差
3. **projectile 与武器重合**：石块砸中肉体 vs 匕首命中肉体，在碰撞层面都是 body_hit，只有来源材质不同

若按 7 事件 × 材质 × 轻重直接扩展 audioId，映射表会组合爆炸。解法：把 7 个语义事件收敛为 **1 个 `combat_impact` 统一 Impact Event**，由 SfxResolver 按条件规则集解析 audioId。

## 1. 已核对的项目现状（数据真实性检查）

| GPT 五维度 | 项目现状 | 决策 |
|---|---|---|
| interaction | ✅ ContactResolver effects 已有全部 7 种 | 直接用 |
| Impact Class | ✅ 招式 `attackWeight`（light/heavy）已走通 stateDef→box→context 链路 | 直接用 |
| Source Kind | ✅ CombatSystem effect 分支天然知道 weapon/projectile | 直接用 |
| Source Material | ❌ 无武器定义文件；ProjectileDefs 有 typeId 无 material | **按用户方案放状态图**（见下） |
| Target Surface | ❌ 无盔甲/部位概念 | **按用户方案：角色整体一个属性**（见下） |

**用户决策的材质数据归属**（人物状态图即武器唯一确定，招式生效帧的撞击材质唯一确定）：

- **`impactMaterial`**：状态图攻击态字段（与 attackWeight 并列）——这招生效帧的撞击方材质（steel/wood/stone）
- **`contactSurface`**：状态图 guard/shield 态字段（override）——持此姿态时身体呈现的接触面材质
- **`bodySurface`**：角色定义（CharacterDef）字段——裸体/常态接触面（flesh）
- **`material`**：ProjectileDefs 每类型字段（dagger/spear=steel，rock=stone）

## 2. 设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 事件收敛 | 7 个 `combat_*` dispatch → 1 个 `combat_impact`，context 携带结构化碰撞描述 | ProjectileContactResolver 与 CombatSystem 产同构 Impact Event，音频不关心碰撞来自哪个子系统 |
| 规则匹配 | SfxResolver 加 `mode: "impact"`：rules 数组顺序匹配，when 条件**部分匹配**（声明的字段全等即命中）→ 未命中按 interaction 查 fallback | 按需匹配不做全排列；新增组合 = 加一条 JSON 规则，零代码 |
| 缺省语义 | 新字段全部缺省 `null` → 匹配不上 → fallback | 零配置零报错；不会把忘标材质的木棍误判成钢 |
| targetSurface 取值 | **永远取"守方当前呈现给这次接触的表面"**：guard/shield 态 → contactSurface override；攻击态（clash）→ 守方 stateDef.impactMaterial；其他 → bodySurface | 语义统一，clash 的 steel/wood 组合天然可区分 |
| 防重复 | parry/guard_block 仍复用 clash effect 靠 contactType 区分不发声（沿用上轮设计） | 一声攻击只响一次 |
| 不做 | 不为招式 ID（zornhut/oberhau...）建映射；不做盔甲部位；不做多维全排列表 | GPT 原则：Impact Class 归一，映射表不膨胀 |

### Impact Event context 结构

```js
context: {
    interaction,     // body_hit | weapon_clash | shield_block | shield_broken | projectile_cut | projectile_deflect | projectile_hit
    sourceKind,      // weapon | projectile（挥剑斩落投掷物时 = weapon，声音主体是剑）
    sourceMaterial,  // melee → 攻方 stateDef.impactMaterial；projectile → ProjectileDefs.material
    impactClass,     // 攻方 attackWeight（light/heavy）或 null
    targetSurface    // 守方呈现的接触面（见上表"targetSurface 取值"）
}
```

### sfx_map impact 模式结构

```json
"combat_impact": {
    "mode": "impact",
    "fallbacks": {
        "body_hit": "combat_body_hit",
        "weapon_clash": "combat_weapon_clash",
        "shield_block": "combat_shield_block",
        "shield_broken": "combat_shield_break",
        "projectile_cut": "combat_weapon_clash",
        "projectile_deflect": "combat_weapon_clash",
        "projectile_hit": "combat_body_hit"
    },
    "rules": [
        { "when": { "interaction": "body_hit", "sourceMaterial": "stone" }, "audioId": "combat_stone_hit" },
        { "when": { "interaction": "weapon_clash", "sourceMaterial": "wood" }, "audioId": "combat_wood_clash" },
        { "when": { "interaction": "weapon_clash", "targetSurface": "wood" }, "audioId": "combat_wood_clash" }
    ]
}
```

首批规则只有 3 条示范（stone 打肉体、木棍拼刀、钢剑拼木棍），近战钢剑主力场景全靠 fallback——等真素材到位按听感加规则。

## 3. 实施步骤

### Step 1：数据层——材质字段标注
- `Data/ProjectileDefs.js`：dagger/spear 加 `material: "steel"`，rock 加 `material: "stone"`
- `Data/StateGraphDef/LongSwordMan.json`：6 个攻击态加 `impactMaterial: "steel"`；guard 态加 `contactSurface: "steel"`；（若有 shield 态加 `contactSurface: "wood"`）
- `Data/StateGraphDef/ManatarmsSword.json`：同上
- `Data/StateGraphDef/RabbleStick.json`：攻击态加 `impactMaterial: "wood"`；guard 态加 `contactSurface: "wood"`
- 角色 CharacterDef（两/三个 def）：加 `bodySurface: "flesh"`
- **验收**：JSON/JS 语法校验通过；游戏行为完全不变（字段尚无人消费）

### Step 2：链路层——box 携带 + context 透传
- `CombatCharacter.js`：box 构建时解析 `box.impactMaterial = stateDef.impactMaterial ?? null`；`box.contactSurface = stateDef.contactSurface ?? charDef.bodySurface ?? null`（攻防两侧 box 都带，与 attackWeight 同一位置同一模式）
- `ContactResolver.js`：hit/clash/blockstun/shield_broken effect context 透传 `offenseMaterial`（攻 box）、`defenseSurface`（守 box）、`contactType`（沿用）；clash 时 defenseSurface 取守方 box.impactMaterial
- `ProjectileContactResolver.js`：projectile_hit / cut / deflect effect context 补 `projectileMaterial`（getProjectileDef().material）、`defenseSurface`（守方 box.contactSurface）
- **验收**：console 断点/日志确认 context 字段到位；结算逻辑与音效行为完全不变

### Step 3：收敛 dispatch + impact 解析
- `CombatSystem.js`：`_dispatchCombatAudio` 重构——7 个 combat_* dispatch 调用点收敛为 1 个 `combat_impact` dispatch（context 按第 2 节结构组装；projectile 分支 sourceKind="projectile" + 读 effect 内的 projectileMaterial）
- `SfxResolver.js`：加 `mode: "impact"` 分支 `resolveImpact(context)`：rules 顺序匹配（when 声明的每个 key 全等）→ 命中返回规则 audioId → 未命中 `fallbacks[interaction]` → 再未命中返回 null 静默
- `Data/Audio/sfx_map.json`：删 7 条 combat_* 映射 → 1 条 combat_impact 规则集（含 3 条示范规则）
- `Data/Audio/audio_clips.json`：4 条 combat 资源保留作 fallback；新增 `combat_stone_hit`、`combat_wood_clash`（光剑占位）
- **验收**：见下方统一验证清单

### Step 4：backlog（本轮不做）
- targetSurface 细分（盔甲/部位系统出现后）
- impactClass 规则（轻重拼刀差异化音量/音色）
- 投掷物 impactClass（medium/light 归一）
- 按 interaction × 材质补充真素材音频变体

## 4. 统一验证清单（Step 3 完成后）

1. **Ctrl+Shift+R 硬刷新**，控制台无报错，`sfx_map.json` 200
2. **回归**：进战斗重复上轮全部验证——命中/格挡/拼刀/破盾/投掷物命中各响一声占位光剑；挥空无声；拼刀只响一声
3. **控制台解析断言**（听不出来的部分靠这个）：
   ```js
   const r = game.audioManager._sfxResolver;
   r.resolveImpact({ interaction: "body_hit", sourceKind: "projectile", sourceMaterial: "stone" })   // → "combat_stone_hit"（规则命中）
   r.resolveImpact({ interaction: "weapon_clash", sourceMaterial: "wood" })                          // → "combat_wood_clash"（规则命中）
   r.resolveImpact({ interaction: "body_hit", sourceKind: "weapon", sourceMaterial: "steel" })       // → "combat_body_hit"（fallback）
   r.resolveImpact({ interaction: "shield_block", sourceMaterial: "steel" })                         // → "combat_shield_block"（fallback）
   r.resolveImpact({ interaction: "unknown_kind" })                                                  // → null（静默）
   ```
4. **实战抽查 RabbleStick**（如场景内有乱拳/棍兵 AI）：被他打中或拼刀时控制台临时打点确认 context.sourceMaterial === "wood" → 解析走 combat_wood_clash 规则
