## Phase A：环境旗标（开发/正式隔离的核心机制）

新建 `scripts/ReleaseFlag.js`（仓库内恒为 `false`，构建脚本在 dist 中覆写为 `true`）：
```js
export const IS_RELEASE = false;
```
改造三处 debug 开关为静态读旗标（构建即隔离，无运行时开关可绕）：
- `scripts/Components/ThrowComponent.js`：`DEBUG_INFINITE_AMMO = IS_RELEASE ? false : true`（当前是 true，🔴 破坏游戏经济）
- `scripts/Components/TrailRenderer.js`：`DEBUG_POINTS = IS_RELEASE ? false : true`（当前是 true，🔴 玩家可见 debug 点）
- `scripts/Game.js:100`：`debugTrace: IS_RELEASE ? false : true`（INDEX.md 标注"临时 true"，🟡 控制台刷屏）
- **X 键 debug 入口**（第四处，checklist 指出的遗漏）：`Scene._applyDebugVisible` 统一下发链路（碰撞盒/刀光采样点/trigger 网格）加 IS_RELEASE 门控，release 下快捷键不可触发。

**技术概念澄清**：这是静态常量短路，**不是编译期死代码剔除**——无 bundler，调试代码仍会被浏览器加载，只是条件恒 false。单机游戏足够，不为剔除几段调试代码引入构建系统。

**debug 入口审计**（实施时完成，防旁路）：① 全局搜索不经上述开关的调试入口；② 检查 URL 参数 / localStorage / 动态 import（Inspector）等重新启用路径；③ 与 `docs/DebugCmds.MD` 逐项对照，确保清单完整。

验证：开发环境行为与改造前完全一致（旗标 false）。

5. 可选参数：`-Zip` 产出 itch.io zip（index.html 必须在 zip 根）；`-Serve` 构建后在 dist 起本地服务。**两个独立动作，不捆绑**。

## Phase C：package.json（可选——仅当本机已有 Node/npm）

零依赖命令遥控器，**非必需**（直接跑 ps1 / py 命令完全等价，执行 `npm run` 需要装 Node）：

```json
{
  "name": "blindduel",
  "private": true,
  "scripts": {
    "serve:dev": "py -m http.server 9000 --bind 127.0.0.1",
    "serve:dist": "py -m http.server 9000 --bind 127.0.0.1 --directory dist",
    "build": "powershell -ExecutionPolicy Bypass -File scripts/tools/build_release.ps1",
    "preview": "npm run build && npm run serve:dist",
    "zip": "powershell -ExecutionPolicy Bypass -File scripts/tools/build_release.ps1 -Zip"
  }
}
```

要点：`--directory dist` 必须显式（npm 脚本从 package 根执行，否则默认服务源码目录）；preview 与 zip 是独立动作；不为"将来可能用 Vite"提前引入 npm——届时再加，并把 `build` 换成 `vite build`。

## 发布特征说明（预期管理）

无 bundler 意味着 dist 中 JS 仍是可读源码。"不含源码"仅指不含 plans/docs/构建工具/测试脚本/编辑期源素材，**不指玩家无法查看游戏 JS**（浏览器交付的代码本身可获取）。现阶段不做压缩混淆，接受此特征。
