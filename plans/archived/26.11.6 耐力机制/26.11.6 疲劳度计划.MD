# 26.11.6 疲劳度（Stamina）计划

> 状态：**大块一（疲劳系统实现）已全部落地（26.11.6~07）**；大块二（AI 识别疲劳）未开始
> 目标：为连续进攻引入累积成本，抑制"乱换招靠运气取胜"；疲劳以整体匀减速表达，AI 以人格化感知处理疲劳
> 上游提案：`plans/BlindDuel_Stamina_Prototype_Plan.md`（GPT），本文件为结合项目实际后的评审结论与实施计划

## 0. 已确认决策

| # | 项 | 结论 |
|---|-----|------|
| D1 | 减速范围 | **攻击类状态整体匀减速**，不区分前摇/后摇（LibreSprite 方案不便标注分段信息）。复用现有 timeScale 机制：动画变慢 → 碰撞判定帧、AI normTime、攻击窗口自动跟随，天然一致 |
| D2 | 减速上限 | 线性曲线，空耐力最多慢 **40%**（用户区间 30~50% 取中，playtest 调整） |
| D3 | guard 不足 | 允许 commit，正常进 guard 状态；**被打击结算时改判 clash**；无接触则耐力维持 0，不扣负。不足判定线 = **commit 时刻** stamina < guardCost（P1 已定）。**实施补充（用户确认保留）**：轻重分档——light vs 弱 guard → 防守方 clash_lose 且攻方攻击失效；heavy vs 弱 guard → clash_lose 且攻方攻击**不失效**（Phase 2 继续命中扣血，参照 shield 破盾体系类推的梯度）；parry 对弱 guard 关闭 |
| D9 | dodge 位移惩罚 | dodge 动画**不减速**，但位移按 commit 时刻耐力缩放（frameSpeeds 乘系数）：耐力不足时强行 dodge 拉开的距离变少。缩放公式 `dodgeScale = dodgeScaleFloor + (1 - dodgeScaleFloor) × staminaRatio`（空耐力 floor=0.5，待测） |
| D4 | throw | 减速但**不扣耐力**（AI 有 throw.cooldownMs=3000 兜底；玩家疲劳无限扔刀为已知风险，playtest 观察） |
| D5 | clash 状态 | 只减速不费耐力 |
| D6 | hit/stunned 硬直 | 不扣费不减速 |
| D7 | 资源归属 | `CombatCharacter.combat.stamina/maxStamina`；Battle enter 重置满值，不跨场持久化 |
| D8 | AI 失误感 | 新增 `aiProfile.fatigueAwareness(0~1)`：低感知 AI 耐力不足时仍倾向 guard（吃 clash），高感知转 dodge——以非最优决策表达初级敌人失误感 |
| D10 | 配置分层 | 四层数据各归其位（GPT HandOff 评审采纳）：**CombatTuning** = 全局规则与默认值（公式/消耗/曲线，含 `enabled` 总开关）；**StateGraphDef.combatProfile** = 个体体能（与 aiProfile 并列，属战斗属性非 AI 性格，玩家也用；第一版只开 maxStamina / recoveryMultiplier / costMultiplier 三键）；**招式级 staminaCostMultiplier** = 预留不实现（backlog）；**运行时** = CombatCharacter.combat。fatigueResistance 等其余体能键等有真实角色需求再加 |
| D11 | 防御成功回补（实施新增） | guard / dodge 成功回补耐力（successRefunds 表，×recoveryMultiplier）——消耗 ×costMultiplier、回补 ×recoveryMultiplier，体能差在攻防循环中复利放大。弱 guard 的 clash 改判路径不回补、不产 guard 记忆事件 |

减速公式（进入状态时固定本次倍率，动作执行期间不重算）：

```text
slowdown = 1 + 0.4 × (1 - staminaRatio)    // 满耐力 1.0，空耐力 1.4
timeScale = stateTimeScale / slowdown
```

## 1. 大块一：疲劳系统实现

### Step 1.1 耐力资源 ✅ 已落地（26.11.6）
- `CombatCharacter.combat` 加 `stamina / maxStamina`（缺省走 CombatTuning）+ `staminaRatio` getter
- `CombatTuning.js` 新增 `stamina` 配置块：maxStamina / 各状态消耗 / 恢复速率 / 减速上限
- BattleMode.enter 重置满值
- ✅ enabled 总开关已补（Step 1.1 补丁）：扣费/恢复/减速/回补全部以它短路；`enabled=false` 时头顶条与 overlay ST 均不渲染

### Step 1.1b combatProfile 个体体能接线（D10）
- `StateGraphDef/*.json` 顶层（characterTraits / aiProfile 同级）加 `combatProfile.stamina`：第一版只开 `maxStamina` / `recoveryMultiplier` / `costMultiplier` 三键，缺省 1.0
- `CombatCharacter` 构造时从 stateGraph 读 combatProfile：maxStamina 覆盖默认值；两个 multiplier 存 combat 供扣费/恢复消费
- 不与 aiProfile 混合：体能是战斗属性，玩家角色同样适用；fatigueAwareness 与体能正交（耐打 ≠ 会管理体力）

### Step 1.2 基础消耗 ✅ 已落地（26.11.6）
- 实施落点：CombatCharacter.enterState 覆写尾部 `_commitStaminaCost`（非 CharacterBase；combat 构造期守卫覆盖 initial state 路径）；attack 类按 attackWeight 扣 light 15 / heavy 25，guard 10、dodge 20，throw 0（D4）；全部 × costMultiplier
- `staminaInsufficientGuard` 标志在同一时刻采集（扣费前口径），guard 存续期间经 getCombatSnapshot 快照读取

### Step 1.3 结果追加消耗 ✅ 已落地
- `applyOutcomeStaminaCost`（表驱动 outcomeCosts：miss 10 / parried 5 / guard_blocked 5 / clash 5 / hit 0）× costMultiplier，floor 0
- 挂点：CombatSystem.#dispatchOutcomes（markAttackResolved 去重之后）+ CombatCharacter miss 回传处（规则与 controller 反馈解耦——无 controller 的角色也扣费）
- defender 侧不扣（guard 成功是正收益、hit 是 D6 豁免）；clash winner 无 outcome 无扣费

### Step 1.4 恢复 ✅ 已落地
- `CombatCharacter.fixedUpdate` 挂 `_regenStamina`（timeControlSystem.tick 之后），用 effectiveDeltaMs——hitstop 冻结时自动暂停恢复，免费收益
- 黑名单：attackActive / guardActive / dodgeActive 状态 + throw / clash / hit / stunned 状态名（P3：guard 暂不恢复，playtest 后定）
- × recoveryMultiplier

### Step 1.5 疲劳减速与 dodge 位移惩罚 ✅ 已落地
- `_getStateTimeScale` 覆写内复合：`timeScale = base / (1 + 0.4 × (1 - staminaRatio))`，先算 chainBonus/postDefenseCounter 的 base 再除——连招加速与疲劳减速可共存
- 生效范围：attackActive 状态 + throw + clash；guard/dodge 豁免；hitstop 解冻恢复保存值（已含疲劳倍率），验收项自动满足、零额外代码
- dodge 缩放（D9）：enterState 检测 dodgeActive 时按 commit 时刻 staminaRatio 算 `_dodgeFrameSpeedScale` 锁存；CharacterBase frameSpeeds 分支乘 `this._dodgeFrameSpeedScale ?? 1.0`（基类钩子默认 1；debug panel Speed 同步显示缩放值）

### Step 1.6 guard→clash 耐力路由 ✅ 已落地（含实施修订）
- 判定线在 ContactResolver Phase 1 blocked 分支顶部（非原计划 Phase 3）：insufficientGuard = guard 型 + 快照标志
- **实施修订（用户确认保留）**：light vs 弱 guard → 防守方 clash_lose effect（进 clash + 扣 5 + loser hitstop）+ 攻方攻击失效；heavy vs 弱 guard → 同 clash_lose 但攻方攻击**不失效**（Phase 2 继续命中扣血双重惩罚）——轻重梯度参照 shield 破盾体系类推
- parry 对弱 guard 关闭（路由在 canParry 之前）；shield 不参与本路由（guardType==="guard" 限定）
- 弱 guard 不产 defenseSuccess → 无回补、无 guard 记忆事件（后者留给大块二）

### Step 1.7 UI ✅ 已落地（26.11.7）
- 新增 `scripts/UI/StaminaBar.js`：头顶世界坐标锚定条（投影复刻 debugPanel 模式，HEAD_OFFSET_Y=3），光谱渐变红→黄→绿左锚定（background-size 固定条宽，收缩暴露状态色）
- BattleMode.updateRender 懒创建 + 每帧 update（enabled=false / 玩家死亡不渲染）；exit dispose；仅玩家条（敌方耐力靠观察，盲斗设计）
- debug overlay（_updateDebugPanel）追加 `ST: x.x/max (pct%)`，enabled=false 整段隐藏

## 2. 大块二：AI 识别与处理疲劳

### Step 2.1 有效时序接线 ✅ 已落地（26.11.9，四批接线 + 实战验证）
- AIController 新增 `#getEffectiveTiming(char)`：base timing × 该角色疲劳倍率（自身招式用 commit 时刻倍率）
- 三个绝对 ms 消费点统一走它：① 自招评分 / preemptive / clash seeker 窗口 ② predictedOpponentEvents 事件属性（startupMs / startMs）③ dodge i-frame 资格门的 timeUntilHit
- 近战 dodge i-frame 门是全状态免疫（时间口径），不受 D9 位移缩放影响；但 **projDodge 位移预测**（#scoreDodgeForProjectile 的 escape 距离估计）需读缩放后位移，否则疲劳 AI 会高估闪避成功率、站在弹道上白 dodge
- AIKnowledgeRegistry 保持 base timing 不动；normTime 类消费自动兼容不改
- ⚠ 不先做这步，疲劳 AI 的预测会系统性失真

### Step 2.2 fatigueAwareness knob ✅ 已落地（26.11.9；实测 aiProfile 通道 = 场景 entityDef，非 StateGraphDef，docs 已同步修正）
- `aiProfile.fatigueAwareness` 默认 1.0；档位：精英/Boss=1.0（永远规避）、普通=0.5（有时失误）、教学/rabble=0.0（无感知）
- 同步更新 docs/AI系统说明.MD 的 knob 表与配置示例

### Step 2.3 guard 资格门 + 概率锁存 ✅ 已落地（26.11.9，三档验证通过：0.0=照举吃 clash / 0.5=SUPPRESS 生效 / 1.0=风险区零 guard）
- 触发条件：本次 guard 将发生"耐力不足"风险（commit 所需耐力 > 当前 stamina）
- 掷骰 `random < fatigueAwareness`：通过 → 锁存"有意识"状态，#scoreDefense guard 分支压制，dodge 自然接管；不通过 → 照常 commit guard（吃 clash）
- 锁存 ~2.5s 或直到耐力恢复出风险区（防 200ms 决策 tick 抖动——sepDirY / attackFailBudget 已有无滞回踩坑先例）
- 玩家侧不受影响：规则对称，决策不对称

### Step 2.4 留观项（本计划不做）

**Playtest 证据（26.11.9，酒馆 rabble_stick，aware=0.5）：**
- AI 疲劳期进攻零收敛：空耐力（ratio 0.00，重剑前摇 1063ms）仍连续进攻至死（7 次 self:hit）——Utility 层 stamina 成本评分（GPT Phase 2）提上议程的直接证据
- 0.5 档弱 guard 被 SUPPRESS 有效替代（本局 0 次 insufficientGuard vs 0.0 档多次 clash_lose）；统计口径注意：一条 SUPPRESS 日志 ≈ 2.5s 锁存 ≈ 12 个决策拍的 guard 缺席，犯蠢率 = 弱 guard : (弱 guard + SUPPRESS)
- CombatMemory 涌现：低感知 AI 吃 clash → guard:broken → consecutiveFail 自动压 guard 评分，像"被打出来的经验"——先当 feature 留观；若低感知敌人过怂，再考虑用 fatigueAwareness 缩放 feedback 罚项
- Utility 层 stamina 成本评分（GPT Phase 2）、oppStaminaRatio 疲劳狩猎（GPT Phase 3）：验证后再议
- 招式级 `staminaCostMultiplier`（特殊招式覆盖按 attackWeight 推导的默认消耗）：预留能力，第一版不做
- BattleDef.combatantConfig 实例级初始 staminaRatio（剧情疲惫敌人 / Boss 二阶段继承）：当前无真实需求场景，backlog

### Step 2.5 对照 playtest
- 三组：无耐力 / 有消耗无减速 / 消耗+减速（CombatTuning 一键开关）
- 行为对照：A 无脑乱换招 / B 择机进攻 / C 交换后脱离
- 日志记录：start/end stamina、每次消耗来源与数值、commit 时 staminaRatio 与本次倍率、outcome 序列、战斗时长
