# 26.11.9 AI 进攻决策引入耐力（Fatigue-aware Attack Gate）计划

> 状态：**评审完成，待实施**
> 上游：`plans/26.11.9 BlindDuel_Fatigue_Aware_Attack_Policy.md`（GPT 方案）+ `plans/HandOff.MD`（本项目构思）；本计划为两稿对冲后的评审结论与实施版，冲突处以本计划为准
> 问题：playtest 证实 AI 疲劳期进攻零收敛（空耐力 ratio 0.00 仍连续进攻至死）——攻击决策层无资源约束资格检查

## 0. 核心原则（直接采纳 GPT）

1. **耐力管理是资源约束，不是新战术行为**：Gate（veto），不加 Utility 评分项、不建 conserve 候选、不改族内相对评分。
2. **三层分离**：真实耐力/疲劳时序 = 物理事实（所有 AI 都正确感知）；`fatigueAwareness` = 是否主动管理资源；`baseAggression` = 愿意压到多低。awareness=0 不能导致错误的时间预测（Step 2.1 接线已保证）。

## 1. 设计决策

| # | 项 | 结论 |
|---|-----|------|
| D1 | Gate 位置 | attack 候选完成既有评分**之后**、进最终 pool 仲裁**之前**，逐候选过滤。禁止全局 winner 选出后再 veto（会失去其他合法候选正常竞争的机会） |
| D2 | 储备阈值 | `reserveThreshold = 0.7 - 0.5 × clamp(baseAggression, 0, 1)`（精英 1.2 / Boss 1.3 攻击倍率保留原值，仅阈值派生时 clamp）；第一版不加每角色独立阈值 |
| D3 | projected 口径 | `projected = (stamina - 本次基础 commit 成本) / max`；不预扣 miss/outcome 追加费；除零边界（stamina=0）不得 NaN，0 < 阈值恒成立 → 走机会资格 |
| D4 | 机会放行 | **复用 `#scoreAttack` 的 `_breakdown`**：preemptive / clashSeeker 分量 > 0 直接放行（资格检查现成）；punish 分量需补逐候选时序验证（评审修订，见 §2 修订 R2） |
| D5 | 锁存统一 | 攻击门与 guard 风险门**共享同一个疲劳意识周期**（评审修订 R1）：进风险区（任一门的风险线）掷骰锁存 aware，周期内两门一致生效；退出 = 耐力过退出阈值。**实施修正（Step 5）**：guard 压制 = 周期在管 **且** stamina < guard 消耗（物理风险线独立于感知周期，恢复 Step 2.3 语义） |
| D6 | 退出滞回 | 退出阈值 = **攻击区上沿 + 0.1**（固定偏移，不加 knob）。攻击区上沿 = reserveThreshold + maxAttackCost/maxStamina——实施时若按裸 reserve + 0.1 会低于 heavy 拦截上沿，导致已验证的影子行为回归，故修正基准 |
| D7 | throw | 不进 Gate（不扣耐力、独立 cooldown）；留观疲劳期投掷绕过问题 |
| D8 | 回退开关 | 挂 `CombatTuning.stamina.enabled` 之下 + `fatigueAwareness <= 0` 双重短路；关闭后行为完全回归 |
| D9 | dodge | 防御动作**不设对称约束**（压制 dodge 危险）；留观低耐力白 dodge |

## 2. 对 GPT 方案的评审修订（实施前提）

- **R1 锁存语义变化**：现有 guard 门 = 进风险区判定 + 2.5s 时间锁 + 出区即解。统一为周期锁存后，**Step 2.3 已三档验证的行为与犯蠢率统计口径（一条 SUPPRESS ≈ 2.5s ≈ 12 决策拍）失效**，Step 5 完成后必须重过 0.0/0.5/1.0 三档验证。
- **R2 punish 资格需新建**：现有 punish 只有距离粗判（≤ selfMaxReach），无"startup+到达 ≤ 剩余 recovery"验证——套 dodge i-frame 资格门（escapeLatency vs timeUntilHit）模式补一段。
- **R3 成本查询口**：消耗逻辑在 `CombatCharacter._commitStaminaCost`（attackWeight 分档 × costMultiplier）私有；CombatCharacter 需公开 `getAttackCommitCost(attackWeight)`（同一计算源），禁止 AI 侧复刻消耗表。
- **R4 落地简化**：机会放行不用 GPT §4 的四类表格，收敛为"`_breakdown` 机会分量 > 0"一句（R2 补 punish 后成立）。

## 6. 已知问题（26.11.10 会话诊断：受击硬直连锁死亡）

> 背景与证据：26.11.10 会话为诊断本计划 Step 5 落地后的连锁死亡问题，临时加了 `defenseTiming REJECT` 日志并试了两版 P1 修复（均已回退，代码零残留）。死因链分析有留存价值，供后续立项直接引用。

### 6.1 死因链（三层叠加，非单一缺口）

rabble 四连白给的完整链条：

```
counter → hit 硬直（层3：hit 态无命令出口，命令被丢弃）
  → 回 idle：防御候选被清零（层1）→ attack 唯一幸存 → thrust 胜出
  → committed 锁死决策（层2）→ 窗口在 committed 中流逝 → 玩家刀落
  → interrupted thrust → 回 hit 态 → 循环至死
```

| 层 | 缺口 | 位置 |
|---|------|------|
| 1 时机窄窗 | startup 时机门 `timeUntilActive > decisionBuffer → 0` 无 kind 检查，dodge/guard 一起被拦；窗口宽 ≈ decisionIntervalMs（100ms，reflexMaxMs=0 时恒定），决策 tick 落不落得进纯靠相位对齐（实证：110ms 差 10ms 擦过） | `AIController.js #scoreDefense` startup 分支 |
| 2 attack commit 锁 | REJECT 后 attack 是唯一非零候选 → `#isCommitted()` 锁死整个攻击时长，dodge 晚交窗口恰好在这段流逝 | `AIController.js fixedUpdate` |
| 3 状态图封闭 | hit 态唯一出口 = 动画播完回 idle，无任何 command 出口；guard 态也只有 idle/dash（counter）出口，无 dodge；**所有非 idle/move 状态对 dodge 封闭**。且 `pendingCommands` 单槽队列不随 enterState 清空，命令被下一 tick 覆盖 | `RabbleStick.json` hit/guard 态 + `CharacterBase.js pendingCommands` |

实证日志（defenseTiming REJECT 过滤后）：`REJECT dodge 174ms (idle)` → `defenseScore dodge 53ms 通过 → guard:success` → `defenseScore dodge 49ms 通过 → self:hit (selfState=hit)` → `interrupted thrust selfState=hit` → `defenseScore dodge 69ms/22ms 通过（hit 态）→ self:hit`。关键反直觉信号：REJECT 全部发生在 selfState=idle/move（AI 能行动时），硬直期间时机门根本不进入。

### 6.2 与本计划的交互 bug（D8 设计假设失效）

D8 注释"dodge 自然接管"的前提是 dodge 在 opp active 时还有资格，但两门相乘后防御全空：疲劳周期在管 + stamina < guard 消耗 → guard 被压制清零（`_fatigueGuardSuppressed`）；同一时刻 opp active → dodge 走 activeBase 正常评分但 hit 态兑现不了（层 3）。低耐力 + 被压制场景下，D8 的接管假设与层 3 的状态封闭互相对消。

### 6.3 两版 P1 修复的结论（均已回退）

- **P1-v1（已回退，方向性错误）**：dodge 时机门改用自身 totalMs 口径（`max(decisionBuffer, dodge totalMs)`）。被用户反例否决：轻击触发 dodge → 立刻接 Zornhut → dodge 结束时刻 ≈ Zornhut 落点 → 白给。根因：dodge 免疫即时生效、有限时长，**早交 = 免疫被轻击消耗，晚交 = 覆盖命中帧且向后延伸罩住连段**——晚交才是最优，totalMs 口径等于鼓励早交。
- **P1-rev（已回退，待重启）**：保留窄窗 + 新增 defensePendingGate（opp startup 且 dodge 可行时非机会攻击资格除名，复用 fatigueOpportunity 通道，`#isDodgeFeasible` 探测不含 closure/耐力）。用户未否决方案本身，回退原因是本次会话整体收敛。已发现的代价：①AI 对出手中的对手基本不对攻，整体变后发风格；②不查耐力，低耐力白 dodge（D9 留观）风险放大。
- 层 3 的修复（hit 态加 escape window：`{ "to": "dodge", "when": [{command:"dodge"}, {time normalized ≥ 0.6}]}`）与 guard 态 dodge cancel 属 StateGraphDef 数据层改动，独立于 P1，**修复时要同时覆盖硬直中（数据层出口）和硬直后（防御候选不被门清零）两个窗口**，缺一层链不断。

### 6.4 重启时的验证清单

1. `defenseTiming REJECT`（buffer 恒 100ms）与 `defensePendingGate filtered` 应成对出现，随后 `defenseScore dodge` → `dodge:success`；
2. 诱饵场景回归：轻击 startup 期间 AI 不得早交 dodge（免疫不被消耗）；
3. 机会攻击保留：clashSeeker/preemptive 在 opp startup 中仍可突围（fatigueOpportunity > 0 放行）；
4. `defenseScore dodge 通过但 selfState=hit 仍死亡`属于层 3 预期现象（假放行：escapeLatency=0 对 hit 态不拒绝），不算 P1 回归；
5. D9 留观项联动：`#isDodgeFeasible` 不查耐力，观察低耐力 dodge 白发频率与 stamina 曲线。
