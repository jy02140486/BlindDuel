# AI 多层决策解耦计划

> 日期：2026-09-21
> 背景：现有 AI 是单层 Utility Scoring（每 200ms 根据对手当前 phase 选最高分动作），
> 缺乏"整体战斗倾向"这一慢变量，导致一路猛攻、idle 时只能攻击、
> 连吃几打不改节奏等行为。本次重构引入 Memory → Posture → Utility 三层。

---

## 目标

把当前 AI 架构：

```
Situation → Attack/Defense/Positioning Utility → Action
```

改成 **四层分离**：

```
           Memory
             │
             ▼
Situation ──→ Posture（500ms 慢变量）
    │           │
    └─────┬─────┘
          ▼
       Utility（200ms 快变量）
          │
          ▼
        Action
          │
          ▼
       Outcome
          │
          └──→ Memory
```

四层分工：
- **Memory**    = 过去发生了什么（纯历史，不做解释）
- **Situation** = 现在发生了什么（快变量感知）
- **Posture**   = 我现在总体想怎么打（慢变量，影响 Utility 的方向）
- **Utility**   = 在这个意图下，哪个动作现在最合适

具体收益：
- 对手 idle 时 AI 能进入"警惕待命"姿态（guard readiness 进候选池）
- 连吃几打后 Posture 自动降 aggression、升 caution，开始想退
- Positioning（advance/retreat/hold）从 fallback 提升为正式候选 action
- 连续的行为修正由 Posture 承担，Feedback Memory 只管 tactical
- "模式化程度"（tutorial vs elite vs boss）可通过 Posture 对 Memory 的敏感度来调

---

## 三层定义

### Layer 0：Combat Memory（纯历史记录，不做解释）

**频率**：每次 Outcome（hit/miss/parry/dodge/attack end）时 append；每次 COMMIT 时 push

**⚠️ Memory 只管"过去发生了什么"**，所有快变量感知（oppIdleMs、oppLastActiveMs、
currentPhase、distance）都在 **Situation** 里。这是 GPT 指出的核心结构修正。

**内容**：

| 字段 | 含义 | 更新方式 |
|------|------|----------|
| `outcomes[]` | 最近 N 条 action outcome（见下方 outcome 枚举）| outcome 时 append，decay 5s 过期 |
| `commits[]` | 最近 6 次 COMMIT `{kind, stateName}` | COMMIT 时 push，满 6 条 shift |
| `pressure` | 累计的被击压力值（衰减连续值，0~3）| hit → +1.0；success defense → ×0.6；opp miss → ×0.7；time → ×0.995/tick |
| `consecutiveMisses` | 连续 attack miss 次数 | miss → +1；hit/success → reset |

**⚠️ 为什么 pressure 取代 consecutiveHitsTaken**：

原来的 consecutiveHitsTaken 是二元的：hit→+1，success→reset 到 0。
改成 pressure 后，成功防住不会让 AI "完全恢复进攻心态"，
而是 "压力降低，进攻意愿逐渐回升" — 更符合慢变量理念。

```
pressure 初始 = 0
hit → pressure = min(3.0, pressure + 1.0)
successful defense → pressure *= 0.6
opponent miss → pressure *= 0.7
time → pressure *= 0.995  (500ms tick → ~135s 衰减到一半)

Posture target 里用 min(1, pressure / 3) * cautionFromDamage
```

**Outcome 枚举（Phase 0 实现时细分）**：

| outcome | 含义 | 是否驱动 pressure |
|---------|------|------------------|
| `attack:hit` | 我的攻击打中对手 | 否 |
| `attack:miss` | 我的攻击没打中 | 否 |
| `attack:parried` | 我的攻击被对手 parry | 否 |
| `guard:success` | 我的 guard 成功防住 | pressure × 0.6 |
| `guard:miss` | 我的 guard 没防住但也没被打中 | 否 |
| `guard:broken` | 我的 guard 被打穿导致被击中 | pressure + 1.0 |
| `dodge:success` | 我的 dodge 成功躲开 | pressure × 0.6 |
| `dodge:fail` | 我的 dodge 没躲开被击中 | pressure + 1.0 |
| `self:hit` | 直接被击中（没做出防御动作） | pressure + 1.0 |

**约束**：Memory 不直接修改任何 Utility 分数。它只提供原始数据。

### Layer 1：Combat Posture（500ms 慢变量，核心）

**频率**：500ms 更新一次（或 Memory 有重大变化时触发重算）
**更新方式**：target → exponential smoothing（避免突然跳人格）

**⚠️ 语义澄清：1.0-centered multiplier**
- 1.0 = 不改变原 Utility（neutral posture）
- >1 = 鼓励该行为
- <1 = 抑制该行为

**为什么不用 0~1 bias**：
0~1 语义和 baseAggression（也是 0~1）打架——两个 0~1 都在表达"攻击倾向"。
multiplier 语义干净：neutral = 1.0，只有偏离 1.0 时才改变原 Utility。

**输出**：连续值对象，debug 时可解释为标签（AGGRESSIVE / CAUTIOUS / DEFENSIVE / NEUTRAL）

```js
posture = {
    attackMultiplier:  0.6 ~ 1.4,  // neutral = 1.0
    defenseMultiplier: 0.7 ~ 1.3,  // neutral = 1.0
    advanceMultiplier: 0.7 ~ 1.3,
    retreatMultiplier: 0.7 ~ 1.3,
}
// ⚠️ 没有 riskTolerance — 见下方说明
```

**为什么砍掉 riskTolerance**：
原来的 riskTolerance 乘整个 attack score 不是"改变风险偏好"，
是"无条件降低/提高这个 action 的全部价值"。
如果以后真需要"风险偏好"，应只影响 threatPenalty 权重，不乘 final score。
Phase 0 先跑起来再看需不需要。

**⚠️ diversityPressure 也不在这里**！
这是安全阀，不是核心决策机制。等基础 Memory→Posture→Utility pipeline
跑起来、观察到确实有不可恢复的单一行为循环时再加。
当前优先级：先让基本逻辑正确，再处理边缘 case。

**⚠️ distanceHunger 也不在这里**！
Posture 是 500ms 慢变量，但 distance 是每帧变化的快变量。
distanceHunger（"现在距离太远了，该不该靠近"）放到 **Layer 2 Utility** 里——
Posture 只给 distanceAppetite（"我总体喜欢追多近的距离"）。

**Target 计算公式（围绕 1.0 上下波动）**：

```
// 输入：Memory.pressure, Memory.consecutiveMisses
//      Situation.oppIdleMs, Situation.oppVulnerable, Situation.oppPhase

t.attackMultiplier  = baseAggression                                    // 默认 1.0
                    - min(1, pressure / 3) * cautionFromDamage          // 被打降
                    - min(1, consecutiveMisses / 3) * cautionFromMisses  // miss 降
                    + min(1, oppVulnerable > 0.5) * punishDesire         // opp recovery 升
                    - smoothstep(oppIdleMs, 800, 2000) * idleCaution    // opp idle 降

t.defenseMultiplier = baseDefense                                       // 默认 1.0
                    + min(1, pressure / 3) * defenseFromDamage           // 被打升
                    + smoothstep(oppIdleMs, 800, 2000) * readinessFromIdle
                    + (oppPhase === "startup" ? startupDefenseBonus : 0)

t.advanceMultiplier = clamp(t.attackMultiplier * distanceAppetite, 0.7, 1.3)
t.retreatMultiplier = clamp(t.defenseMultiplier * retreatDesire, 0.7, 1.3)
```

**Exponential Smoothing**：

```
alpha = decayAlpha  // 默认 0.15，角色级可配
current = current + alpha * (target - current)
```

**AITuning 默认值（neutral posture 基线）**：

```js
postureDefaults: {
    baseAggression: 1.0, baseDefense: 1.0,
    cautionFromDamage: 0.15, cautionFromMisses: 0.10,
    defenseFromDamage: 0.12, punishDesire: 0.10,
    idleCaution: 0.12, readinessFromIdle: 0.10,
    startupDefenseBonus: 0.15,
    distanceAppetite: 0.7, retreatDesire: 0.6,
    decayAlpha: 0.15,
    // multiplier 区间边界
    MIN_ATTACK_MULT: 0.6, MAX_ATTACK_MULT: 1.4,
    MIN_DEFENSE_MULT: 0.7, MAX_DEFENSE_MULT: 1.3,
}
```

**角色级 override** 放在角色的 CombatCharacter 配置 JSON 里（不进 StateGraph，
StateGraph 只记录角色能力，策略是角色的性格）。

### Layer 2：Action Utility（200ms 快变量，保持现有评分逻辑）

**频率**：200ms（decisionIntervalMs）
**改动**：在现有评分函数末尾乘入 posture multiplier（neutral 时 1.0 不变）

```js
// #scoreAttack 末尾
score *= posture.attackMultiplier;   // neutral 1.0 不变
// per-attack 偏好（角色配置里 attackPreferences）
const pref = this.aiProfile?.attackPreferences?.[attack.stateName] ?? 1.0;
score *= pref;

// #scoreDefense 末尾
score *= posture.defenseMultiplier;
// 新增 defensiveReadiness 分支 — opp idle 时 guard 可以有小分进候选池
// 这是 GPT 指出的关键修正：不能让 oppPhase=none 时 defense 恒为 0
if (oppPhase === "none") {
    score += 0.08 * smoothstep(oppIdleMs, 800, 2000) * posture.defenseMultiplier;
    // 0.08 很小，保证只有 attack 分也低的时候 guard 才会赢
}

// #scorePositioning（正式候选！不再 fallback）
// ⚠️ 这里读 Situation.distance（快变量）+ Posture multiplier（慢变量）
const maxEffReach = max(...attacks.map(a => a.range.maxReach)) + rangeBuffer;
const distanceHunger = smoothstep(sit.distance, maxEffReach * 1.5, maxEffReach * 3);

const posScore = {
    // advance: 想靠近 = Posture 偏好 + distance 远时理性判断
    approach: (sit.distance > maxEffReach ? 0.5 : 0)
            * posture.advanceMultiplier
            * (1 + distanceHunger * 0.5),         // ← distanceHunger 在这里！
    hold:     0.3,                                  // 无 Posture 加成
    // retreat: 想拉开 = 只在真的太近（< closestMinReach）时才选
    retreat:  (sit.distance <= closestMinReach + 0.3 ? 0.4 : 0)
            * posture.retreatMultiplier,
};

// attack / defense / approach / hold / retreat
// 全部放进同一个 pool 里选最高分
// 不再需要 "attack/defense 都不够好 → fallback positioning"
```

## 分阶段落地（严格按顺序）

### Phase 0：纯计算，只 log 不接入（最简单的起点）

- [ ] **新建 `scripts/Systems/CombatMemory.js`**
  - `outcomes[]` 存最近 N 条 outcome（decay 5s 过期）
  - `commits[]` 存最近 6 次 COMMIT（`{kind, stateName}`）
  - `pressure` 衰减值（hit→+1.0, success→×0.6, opp miss→×0.7, time→×0.995/tick）
  - `consecutiveMisses` 连续 miss 计数
  - **不再包含 oppIdleMs/oppLastActiveMs**（移到 Situation）
- [ ] **Situation 清理**
  - 现有 `sit.oppPhase`, `sit.oppThreat`, `sit.oppVulnerable`, `sit.distance` 保留
  - 新增 `sit.oppIdleMs`（距 opp phase 进入 none 的时间）
  - 新增 `sit.oppLastActiveMs`（opp 上一次 active 帧时间戳）
- [ ] **新建 `scripts/Systems/CombatPosture.js`**
  - 吃 Memory + Situation
  - 输出 1.0-centered multipliers（attackMultiplier, defenseMultiplier, advanceMultiplier, retreatMultiplier）
  - target 公式用 pressure, consecutiveMisses, oppIdleMs, oppVulnerable, oppPhase
  - low-pass smoothing（alpha = decayAlpha）
  - MIN/MAX multiplier 边界写死在 AITuning.postureDefaults（Phase 4 再角色级化）
  - **不做 distanceHunger（移到 Phase 1 Utility）**
  - **不做 diversityPressure（等观察后再说）**
- [ ] **跑起来，加诊断 log**
  - `[Memory] pressure=2.3 consecutiveMisses=1 outcomes=[...]`
  - `[Posture] target={att=0.85,def=1.12,adv=0.60,ret=0.79} current={...}`
  - 挨打 3 次 → pressure 上升 → attackMultiplier target 是否降到 ~0.85
  - 连续 miss → consecutiveMisses ≥ 2 → attackMultiplier target 是否继续降
  - 对手 idle 2s → oppIdleMs=2000 → defenseMultiplier 是否升
  - **验证 Posture 对事件响应合理后**，才进 Phase 1

### Phase 1：接入 Utility（评分函数末尾乘入 multiplier）

- [ ] AIController 持有 Memory 和 Posture 实例
- [ ] `#scoreAttack` 末尾：`score *= posture.attackMultiplier` + attackPreferences 乘入
- [ ] `#scoreDefense` 末尾：`score *= posture.defenseMultiplier`，新增 oppPhase=none 时的 defensiveReadiness
- [ ] 所有现有 AITuning 值 = neutral posture（所有 multiplier=1.0）时的 baseline
- [ ] **验证行为变化是渐变而非换人格**

### Phase 2：Positioning 升为正式候选

- [ ] `#scorePositioning(sit)` 返回 `{approach, hold, retreat}` 三个分数
- [ ] distanceHunger 在 approach 里（distance 远时自然加分）
- [ ] 三个分数分别乘 posture.advanceMultiplier / 不加 / posture.retreatMultiplier
- [ ] 把 positioning 分数和 attack/defense 分数放到同一个 pool 里选最高分
- [ ] 这是 AI 感觉变化最大的一步，单独做、慢慢调

### Phase 3：Memory 从 AIController 里抽出来 + 清理

- [ ] Feedback Memory（entries + consecutiveFail/consecutiveSuccess）从 AIController 移到 CombatMemory
- [ ] consecutiveFail 仍在 attack 评分里扣 tactical penalty（**保留**，这不是 Posture 该管的）
- [ ] consecutiveFail **同时**驱动 Posture 的 attackBias 下降（**新增**，这是 strategic 层）
- [ ] 原来分散在 `#scoreAttack` / `#scoreDefense` 里的 memory 读代码，改成读 Memory 的 clean API
- [ ] 清理调试 log，保留必要的

### Phase 4：角色级配置（第一轮只出 7 个 knob）

**⚠️ 精简原则**：第一轮只暴露最核心的 7 个 knob，其余全留在 AITuning 系统级默认里。
等实际调参时发现某个敌人确实需要覆盖，再单独暴露。
这样能避免回到"AI 参数调参黑盒"。

| 字段 | 默认值 | 含义 | 关键覆盖场景 |
|------|--------|------|------------|
| `baseAggression` | 1.0 | 基础攻击 multiplier（neutral = 1.0）| 假人=0.0, 精英=1.2 |
| `baseDefense` | 1.0 | 基础防御 multiplier | 假人=1.4 |
| `decayAlpha` | 0.15 | low-pass 系数（越小越慢）| 教学=0.06, 精英=0.25 |
| `distanceAppetite` | 0.7 | 喜欢追近的程度 | 假人=0.05 |
| `retreatDesire` | 0.6 | 想拉开的程度 | 假人=0.05 |
| `repetitionCostRate` | 0.06 | 连续用同一 attack 的战术成本 | 教学=0.02, 精英=0.10 |
| `attackPreferences` | `{}` (全 1.0) | per-attack 分数乘数 | 教学={swing:1.6,thrust:0.4,dash:0.3} |

**三种敌人配置示例**（只列覆盖项）：

```json

{
  "aiProfile": {

    "attackPreferences": { "swing": 1.6, "thrust": 0.4, "dash": 0.3 }
  }

// 防御假人 — 只防不攻
{
  "aiProfile": {
    "baseAggression": 0.0, "baseDefense": 1.4,
    "decayAlpha": 0.10,
    "distanceAppetite": 0.05, "retreatDesire": 0.05,
    "repetitionCostRate": 0.06,
    "attackPreferences": {}
  }
}
// 注：baseAggression=0.0 时 attackMultiplier 永远是 0.0
// 所以 attack score 全 0，假人只会 guard/dodge

// 精英敌人 — 主动调动，变招变距离
{
  "aiProfile": {
    "baseAggression": 1.2, "baseDefense": 1.0,

    "distanceAppetite": 0.8, "retreatDesire": 0.5,
```

## 哪些东西**不做**

- **不做** aggressive/cautious/defensive/punishing 四个互斥 Intent 状态机 — 用连续值 + low-pass 平滑替代
- **不做** Posture 切换冷却（"连续 N tick 满足才切换"）— 低通平滑已经解决了
- **不做** Posture 直接修改 threatPenalty/vulnReward 的原始权重 — 只乘 final score，更干净
- **不把 AI 策略放进 StateGraph** — StateGraph 只记录角色能力（攻击/防御状态、weaponbox、时序），策略是角色的性格
- **不删掉 Feedback Memory 的 tactical penalty** — consecutiveFail 扣分是"这招不太好"，属于 tactical，Posture 管的是"我现在整体不想打"

## 现有系统不变的部分

- Commitment 机制（攻击/防御/闪避执行期间不重决策）
- `decisionIntervalMs` = 200ms 的高频决策节奏
- `#scoreAttack` / `#scoreDefense` 的核心评分逻辑（所有 Phase 1 之前的 tuning 值保留为 neutral baseline）
- PushboxResolver、ContactResolver、CombatResolver
- AIKnowledgeRegistry 的 weaponbox 扫描和 cache 机制
