# 26.11.3 声音系统事件驱动改造计划

> 状态（2026-11-03）：**Step 1-3 已实施并验证通过**（SfxResolver 翻译层 / SurfaceQuery 地表脚步 / CombatSystem 战斗结果事件）。脚步声按用户要求简化为软硬两档：`footstep` = 软表面原声，`footstep_hard` = 硬表面（酒馆 4 场景 hard，prologue soft）。音频资产暂用 `Audio/sfx/47125__gyzhor__lightsaber3.mp3` 光剑占位（footstep_hard、combat_body_hit/combat_weapon_clash/combat_shield_block/combat_shield_break 共 5 条），真素材到位后仅替换 audio_clips.json 的 clips 路径。Step 4 backlog 未启动。

> 核心原则（承接 plans/HandOff.MD）：**动画事件报告动作时机，游戏逻辑报告实际结果，音频系统负责声音表现。**

## 0. 背景与问题

当前音频播放 100% 依赖动画事件直连：`events.json → AnimationEventBus → AudioManager.play(payload.type)`，type 直接当 audioId。

问题：
1. `footstep` 语义写死 audioId，无法按地表材质变化（tavern 木板 vs prologue 泥土）
2. 战斗命中音效缺失：ContactResolver 有完整结算结果（hit/clash/shield_broken 等）但 CombatSystem 消费时只驱动相机 FX（`_fxShake`/`_fxFlash`），从不发声
3. `throw_draw`/`throw_release` 等非音频事件进入 `wireAnimationEventBus` 的 subscribeAll 后打 `unknown clip` warn（现存噪音 bug）

## 1. 设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 事件通道 | 复用现有 `Game.animationEventBus` 实例，不新建总线 | bus 本身无动画耦合，BattleMode 已订阅 throw_* 消费 gameplay；避免双总线维护 |
| type 命名空间 | 动作时机事件用原名（footstep/swing_*）；战斗结果事件加 `combat_` 前缀 | 单一约定，文档化即可 |
| 语义翻译层 | 新增 `SfxResolver`，映射表驱动（`Data/Audio/sfx_map.json`） | AudioManager 不再裸播 type；未知类型静默忽略（顺手修 warn bug） |
| 地表数据 | 放 SceneDef：`defaultSurfaceType` + `surfaceRegions[]` | 沿用 walkAreas 矩形语义；地表是场景环境数据不是音频数据 |
| 战斗事件落点 | CombatSystem 消费 effect 的各分支内 dispatch | 每个 contact 语义结果恰好对应单个标志 effect（hit/clash/shield_broken 均为单 effect），天然不重复；`_fxShake` 先例证明 CombatSystem 是 presentation 合法挂点 |
| 脚步位置来源 | resolver 读 `payload.source.root.position` | CharacterBase dispatch 已注入 source，无需改 FrameAnimationComponent |
| 挥空 whoosh | 维持现状（swing_light/swing_heavy 动画事件直连） | 与命中音效本就是两类事件，不动 |

### 事件 → 音效责任表（最终形态）

| 事件 | 来源 | 播放条件 |
|---|---|---|
| footstep | 动画事件（walk 落脚帧） | 时机确定；音效按 SurfaceType 解析 |
| swing_light / swing_heavy | 动画事件（攻击启动帧） | 无论是否命中都播（破空声） |
| combat_hit | CombatSystem（hit effect） | ContactResolver 确认命中才播 |
| combat_clash | CombatSystem（clash effect） | 拼刀结算 |
| combat_guard_block | CombatSystem（blockstun effect，含 guardType） | 格挡挡下 |
| combat_shield_broken | CombatSystem（shield_broken effect） | 破盾 |
| combat_projectile_cut / _deflect / _hit | CombatSystem（projectile effect） | 投掷物三结果 |
| on_land / on_cloaked / pickup 等 | 动画事件直连 | 不变 |


- 未列出的 type → 静默忽略
- `audio_clips.json` 保持"clip 资源定义"层（audioId → clips/volume/pitch/bus），新增 `footstep_wood/stone/dirt`、`combat_*` 条目；资源未到位前 clips 先复用现有 wav 占位（`clips: []` 空数组时 AudioPlayer 已有防御）

### SceneDef 扩展（Data/SceneDefs/*.json）

```json
{
    "defaultSurfaceType": "wood",
    "surfaceRegions": [
        { "surfaceType": "stone", "minX": -6.75, "maxX": 2.0, "minY": -4.77, "maxY": -1.65 }
    ]
}
```

查询优先级：surfaceRegions 矩形命中（后定义覆盖先定义，同 walkAreas）→ defaultSurfaceType。

## 3. 实施步骤

### Step 1：SfxResolver 翻译层（行为不变，消 warn）
- 新增 `scripts/Systems/Audio/SfxResolver.js`：`resolve(type, payload) → { audioId, options } | null`
- 新增 `Data/Audio/sfx_map.json`（先只含 direct 映射，与现状等价）
- 改 `AudioManager.wireAnimationEventBus`：subscribeAll → resolver.resolve → play；resolve 返回 null 静默
- **验收**：现有全部音效行为不变；throw_draw 不再 warn

### Step 2：地表系统 + 脚步声
- 新增 `scripts/Systems/SurfaceQuery.js`：持有 surfaceRegions + default，`queryAt(x, y) → surfaceType`
- SceneDef 读取字段（SceneDefRegistry 无需改，Scene.init 消费时传入）
- `AudioManager.setSurfaceProvider(provider)`：由 `Scene.init()` 注入、`Scene.dispose()` 置空（跟随场景生命周期，参照 attachScene 模式）
- sfx_map footstep 走 surface 分支；`audio_clips.json` 补三个 footstep id（clips 占位）
- **验收**：ep1_tavern_hall 走路木板声；prologue 泥土声；surfaceRegion 边界切换正确

### Step 3：战斗结果事件（核心增量）
- ContactResolver 补 context 字段（纯增量，向后兼容）：
  - `hit` effect：补 `attackTrajectory` / `attackWeight`（取自 offenseBox，为未来轻重击变体铺路）
  - `blockstun` effect：补 `attackerId` / `guardType`（现在只有 knockbackX，语义事件需要攻防双方）
- CombatSystem 在 effect 消费分支内 dispatch：
  ```js
  // hit 分支末尾
  this.context.animationEventBus?.dispatch({
      type: "combat_hit",
      source: target,
      context: { attackerId, attackTrajectory, attackWeight, contactType }
  });
  ```
  同样处理 clash / blockstun(→combat_guard_block) / shield_broken / projectile_cut / projectile_deflect / projectile_hit
- sfx_map 补 combat_* 映射；`audio_clips.json` 补对应条目
- **验收**：命中/格挡/拼刀/破盾/投掷物各结果音效正确且不重复；打空无声

### Step 4：后置 backlog（本轮不做）
- 轻重击变体（byWeight 条件映射）、武器材质变体（weaponType）
- intensity 分层（命中强度 → 音量/音调档位）
- 3D spatial（Babylon Sound spatializer，按 2.5D Y 远近衰减）
- 受击 VO / NPC 交互音效（NpcFrameComponent 事件同链路接入）
- run 脚步声（speedMode 区分）

## 6. 明确不做

- 不新建第二条事件总线
- 不给 ContactResolver 引入音频依赖（它不知道 audioId 的存在）
- 不改 FrameAnimationComponent 的事件 payload 结构
- 不做真物理射线检测地表（2.5D 坐标查矩形足够）
