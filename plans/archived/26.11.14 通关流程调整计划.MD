# 通关流程调整计划：战斗与 ending 解耦

## 一、背景与动机

当前通关 ending 与最后一场战斗（battle_tavern_night_manatarms）强耦合：BattleMode 在胜利退场序列末尾挂 callback（durationMs-100）接力 `#beginEndingSequence`，ending sequence 在 BattleMode 仍存活时播放，靠 `_ending` 标志冻结战斗模拟、靠 exitSequence 里提前的 switchMode（7500/8000，见 SceneDefs.js 注释 hack）配合。该耦合导致退场阶段相机抖动，且 BattleMode 承担了非战斗职责。

目标：复用 cutsceneInvokers 自动触发机制（序章 prologue_cs_rabble_flee 同款），改为：

```
战斗胜利 → advanceTo(EP1_TAVERN_NIGHT_VICTORY) + 置胜利 flag
  → 常规退场（sheath / 相机 blend / switchMode explore）
  → ExploreMode 轮询 cutsceneInvokers 条件命中（scenarioMin: 203）
  → 播 ep1_ending.json
  → 黑屏 callback 推进 EP1_COMPLETED + 通关画面 → 回主菜单

胜利事件进 scenario 里程碑（与序章 invoker 用 scenarioMin:105 触发同构），
胜利 flag（battle_tavern_night_manatarms）保留——enemy_2 的 spawnIf 与 battle
trigger condition 锚在其上，scenario/flag 双写各司其职。
```

分两步：**Step 1 解耦**（战斗结束顺利回 explore 并播 ending），**Step 2 接通关画面**。Step 1 完成后游戏停在黑屏定格态，即验证点。

## 二、现状关键点（已核实）

- 触发机制已存在：`ExploreMode.#updateCutsceneInvokers`（ExploreMode.js:566）每帧轮询 `sceneDef.cutsceneInvokers`，`sceneSequencer.isBusy()` 时跳过，条件走 `Scene._evaluateCondition`（支持 flag/flagNot/scenarioMin 等），armDelayMs 倒计时后 fetch sequence 播放，flagOnPlay + _playedCutsceneIds 双保险去重。
- BattleMode.js `#handleVictory`（~L443）：`onVictory.ending` 存在时走接力分支，flags/scenario/checkpoint 全部推迟到黑屏回调 `battle_on_ending_black`；`_ending` 冻结 fixedUpdate；exit() 删 handler。
- ep1_tavern_night.json：无 exitBattleSequence、无 cutsceneInvokers；enemy_2 `spawnIf: {flagNot: battle_tavern_night_manatarms}`。
- ep1_ending.json：黑屏 callback fn 为字符串 `battle_on_ending_black`；无 inputLock clip（旧流程靠 _ending 冻结 + controller disable）。
- manatarms exitSequence：switchMode 提前到 7500ms（耦合 hack），违反 §6.5（switchMode 必须在 atMs == durationMs）。

## 三、Step 1：解耦战斗与 ending

### 3.1 BattleMode.js

1. `#handleVictory`：删除 `if (ending)` 接力分支（含 ending_hook track 注入）与 `#beginEndingSequence`；胜利时统一走常规路径：**scenario（v.scenario = EP1_TAVERN_NIGHT_VICTORY）/ flags / questStages / checkpoint 全部立即生效**——回 explore 前世界状态必须就位（enemy_2 不复活 + invoker 条件命中），203 无任何演出监听，立即推进安全；EP1_COMPLETED 属穿帮敏感推进，留给 Step 2 黑屏回调。Step 1 阶段 BattleDef.onVictory.ending 数据保留但 BattleMode 不再读取（Step 2 移除）。
2. 删除 `_ending` 机制：enter() 里的初始化、fixedUpdate 的早退分支、`battle_on_ending_black` handler 注册、exit() 里的 handler delete。

### 3.2 SceneDefs.js

1. `Data/ScenarioMilestones.js`：新增 `EP1_TAVERN_NIGHT_VICTORY: 203`（202 与 210 之间）。
2. `BATTLE_TAVERN_NIGHT_MANATARMS.onVictory` 增加 `scenario: SCENARIO.EP1_TAVERN_NIGHT_VICTORY`。
3. manatarms `exitSequence`：switchMode 从 7500ms 恢复到 8000ms（== durationMs，回归 §6.5），删 hack 注释。

### 3.3 Data/SceneDefs/ep1_tavern_night.json

新增 cutsceneInvokers：

```jsonc
"cutsceneInvokers": [
    {
        "id": "ep1_ending",
        "sequenceUrl": "Data/Sequences/ep1_ending.json",
        "armDelayMs": 500,
        "flagOnPlay": "ep1_ending_played",
        "condition": { "scenarioMin": 203, "flagNot": "ep1_ending_played" }
    }
]
```

条件用 scenarioMin（与 prologue.json 的 scenarioMin:105 同构），胜利瞬间已推进；armDelayMs=500 让 explore 相机 blend 落定后再起 ending。

### 3.4 Data/Sequences/ep1_ending.json

1. 新增 hero.command track：`{ "type": "inputLock", "atMs": 0, "locked": true }`（explore 态下玩家可动，必须锁输入；ending 不回 controls，不 unlock）。
2. 黑屏 callback fn 由 `battle_on_ending_black` 改名 `ending_on_black`（Step 2 由 invoker 侧注册；Step 1 阶段无 handler，验证 TimelineSequencer 对缺失 handler 的容忍度——若报错则 Step 1 临时在 ExploreMode 注册空实现）。

### 3.5 验证

- 打赢 manatarms → 退场序列完整播完（收刀、相机回 explore、无抖动）→ ~500ms 后 ending 播出（马车 whip/drive + 淡出）→ 黑屏定格，输入锁定，无报错。
- 战斗期间 enemy_2 行为正常；胜利后 explore 中 enemy_2 不复活。
- checkpoint（house_door）在胜利瞬间已保存。

## 四、Step 2：ending 接通关画面

1. cutsceneInvoker 增加 ending 语义字段（如 `"ending": { "text": "EPISODE 1 COMPLETE", "scenario": 210 }`），`#updateCutsceneInvokers` 播放前注册通用 handler `ending_on_black`：advanceScenario + `gameFlowManager.showEnding(text)`，序列结束/模式退出时清理 handler。
2. onVictory.ending 数据从 BattleDef 移除（职责完全移交 SceneDef invoker），PROJECT_CONTEXT.md / 相关文档同步。
3. 验证：黑屏后出通关画面 → 任意键 → 主菜单（GameFlowManager 现有链路零改动）。

## 五、风险与注意点

- 时序竞态：退场序列结束与 invoker 轮询之间天然隔帧 + armDelay，无旧方案的同帧竞态问题。
- camera blend 穿帮：ending sequence 自带 setCameraFrame + blend scripted，起播时 explore 相机已落定（armDelay 保证），两段 sequence 不重叠。
- scenario 立即推进的副作用面：当前无 stateMap/music/spawnIf 锚在 203 上，安全；若未来有条件写法引用 203 档位，需留意胜利瞬间即生效的语义。
- `_evaluateCondition` 的 flag 直接读取 + flagOnPlay 直写 worldState.flags（不经 questManager/_notify），与 prologue 现状一致，不引入新行为。
- SceneDefRegistry 加载外部 JSON 的 SceneDef 是否透传 cutsceneInvokers 字段需在 Step 1 实测确认。
