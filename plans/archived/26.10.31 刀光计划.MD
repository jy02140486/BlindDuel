## 2. 需求定义（轨迹语义，用户原始方案）

### 2.1 marker 规则

- 每个 clip 帧至多 **2 个** marker 点。
- **1 个点**：该点即轨迹采样点，该处宽度为 **0**（收尖）。
- **2 个点**：两点连线**中点**为轨迹采样点，连线长度为该处刀光**宽度**，连线方向即该处刃向（ribbon 截面方向，非轨迹法向）。
- 轨迹 = 各采样帧的采样点按帧序连线。
  例：帧 3 点 1 个点，帧 4、5 各点 2 个点 → 轨迹 = 帧 3 的点 → 帧 4 中点 → 帧 5 中点。

### 2.2 首尾形状约定（O4 决议）

- 起点帧 2 个点 → 两端都**齐头**；起点帧 1 个点 → 起点**收尖**。
- 末帧单点 → 终点收尖；末帧双点 → 齐头。绘制者按需选择，无需代码特殊处理。

### 2.3 显示与消失（v1）

- mesh 出现时机：进入**最后一个有 marker 的帧**时立即显示（"一进入这一帧就显示"）。
- v1 消失规则：**离开攻击状态时隐藏**（O3 决议）。沿轨迹渐隐（从第一个标记向最后一个标记渐变）留到下一任务。

## 3. 设计决议记录（三方对齐结论）

| 编号 | 议题 | 决议 |
|---|---|---|
| D1 | 自建几何 vs Babylon `TrailMesh` | **自建 VertexData ribbon**。内置 TrailMesh 是连续位置发射器，与"帧 marker 离散取样 + 批量成带"模型不合 |
| D2 | 触发机制 | **marker 隐式驱动，不发 TrailStart/TrailStop 动画事件**。理由：① 避免与 marker 数据两份真相漂移；② AnimationEventBus E1 策略把 `type` 直接当 audioId，trail 事件会被 AudioManager 误消费 |
| D3 | 颜色来源（C2） | **基于攻击规则的映射表**，不逐 state 配置：`attackTrajectory`（slash/thrust）→ 颜色，人类玩家一看颜色即知攻击类型及应对方式。投掷物后续复用同一套词汇。StateGraphDef 因此**零改动** |
| D4 | 坐标空间（O2） | **世界空间采集 + mesh 挂场景根**。不用 root-local（framespeed/stateSpeed 前冲招式会把轨迹折叠、且 ribbon 会随人移动）。facing 镜像在**采集时**完成换算 |
| D5 | 生命周期归属 | 动画帧推进提供 marker 数据；**TrailRenderer 自管视觉生命周期**（采样/建 mesh/复用/隐藏）；CombatSystem **零参与**；每角色一个可复用实例，hide ≠ dispose |
| D6 | hitstop 行为 | 采样挂在动画帧推进之后，hitstop 冻结帧推进 → 采样**自动冻结**，与攻击判定时间轴天然一致，无需额外处理 |
| D7 | 顶点数据预留（GPT 采纳） | 顶点携带沿轨迹归一化进度 `t ∈ [0,1]`（首标记=0，末标记=1），几何阶段纯色不透明；下一任务做渐隐时只改材质，不动几何结构 |
| D8 | 实现顺序（GPT 修订版） | ① 几何（marker→ribbon 纯色显示）→ ② 消失规则（v1 取样帧结束即消失，修订 2026.11.01）→ ③ 沿轨迹渐隐 → ④ 纹理/发光。GPT 原版 Phase 2"旧采样点逐渐消失"是发射器模型，本方案为批量 ribbon，无中间态，直接跳到隐藏规则 |
| D9 | marker 资产载体 | **独立 trailmarker PNG**（`Data/TrailMarker/<char>/`，与 CollisionMask / RootMotion / PushBox 平级），不复用 CollisionMask PNG——点与盒/点与点互不干扰，绘制与扫描各自独立 |

## 4. 数据层设计

### 4.1 扫描色与 schema（`scripts/tools/extract_collision_boxes.ps1`）

- 新增 trailmarker 扫描色 **`#00FFFF`**（cyan）。与现有色表（`#FFFF00 / #FF0000 / #E37800 / #7082C1 / #FF00FF / #00FF88`）无冲突；运行时投掷物 debug 框虽也是青色，但那是渲染色不是扫描色，互不干扰。
- marker 是**点**不是盒：连通域分析后只输出质心，不做 OBB 拟合。
- 导出格式（与 `boxes` / `anchors` 平级，挂在每帧对象上）：

```json
"trailMarkers": [ { "cx": 210.5, "cy": 60.25 }, { "cx": 240.0, "cy": 58.0 } ]
```

- 无 marker 的帧省略该字段（或空数组，以现有 schema 风格为准）。
- 连通域按 `cx` 升序排序（左点在前），保证双点顺序稳定。
- 扫描校验：单帧 marker 连通域 > 2 → 输出警告；marker 独立 `minPixels` 阈值（建议 2，盒的 6 会吃掉小点）。
- collider.json 的 source 元数据新增 `trailMarkerPng` 字段记录来源路径（模式同 `rootPng` / `pushboxPng`）。
- 脚本遵守既有约定：PS 5.x 兼容（不用 `?.`）、英文注释、禁止手改 collider.json 产物。

### 4.2 资产绘制约定（独立 trailmarker PNG，D9）

- 新增一类独立 PNG：**`Data/TrailMarker/<char>/<clip>.png`**，与 `Data/CollisionMask/`、`Data/RootMotion/`、`Data/PushBox/` 平级。
- **网格布局必须与对应 clip 的 CollisionMask atlas 完全一致**（同一 frameRect 划分）——扫描时按 frameIndex 对齐到 collider.json 的帧；atlasJson 复用 CollisionMask clip 的同名 `.json`（与 rootPng / pushboxPng 同一模式）。
- PNG 内容：每帧格子里画 0~2 个青色点（单点 = 收尖 / 双点 = 定宽）；**两个点之间留间隔**，避免连成一个连通域（独立 PNG 里没有其它颜色，这是唯一要注意的间隔约束）。
- 扫描入口：脚本新增 **`-TrailMarkerPng`** 参数，模式对齐现有 `-PushBoxPng`（见 §4.1）。
- 首个落地 clip：`longswordman_zornhut`（slash 弧线）+ `longswordman_quart`（thrust 直线，且带 root 前冲位移——正好验证 D4 世界空间方案）。

### 4.3 颜色规则表（新文件 `Data/TrailColors.js`）

```javascript
// trajectory → 刀光颜色。人类玩家语义：颜色 = 攻击类型 = 应对方式。
// slash（斩击）：可被剑身格挡、可拼刀；thrust（刺击）：剑身格挡无效，只能闪避/盾挡。
export const TRAIL_COLORS = {
    slash:  "#FFE9A8",   // 暖白金（示意值，可调）
    thrust: "#FF7A45",   // 橙红（示意值，可调）
};

export function getTrailColor(trajectory) {
    return TRAIL_COLORS[trajectory] ?? "#FFFFFF";   // 未声明 trajectory → 中性白
}
```

纯数据文件，不 import Babylon；hex → Color4 转换在 TrailRenderer 内做。

## 5. TrailRenderer 组件（新文件 `scripts/Components/TrailRenderer.js`）

### 5.1 职责与实例模型

- **每角色一个可复用实例**（CombatCharacter 构造时创建，1v1 战斗全场最多 2 个）。
- 单 mesh 复用：每次攻击 rebuild VertexData，不创建/销毁 mesh；`hide()` = `setEnabled(false)` + 清采样列；`dispose()` 跟随 Character 销毁。
- **单窗口假设**：一个 attack state 内只支持一段连续 marker 窗口（v1）；双段斩（帧 3-5 有点、帧 8-10 又有点）记 backlog。

### 5.2 世界空间换算公式（核心，已对 sprite 渲染映射验证）

marker 在 PNG 像素空间，sprite 镜像实现是翻 `spritePlane`（`scaling.x × facing`）不翻 root（[CharacterBase.js:228](file:///e:/se/BlindDuel/scripts/Enties/CharacterBase.js#L228)、[244](file:///e:/se/BlindDuel/scripts/Enties/CharacterBase.js#L244)），因此**采集时手动应用 facing**：

```javascript
// rootAnchor = colliderFrame.anchors.root
worldX = root.position.x + facing * (marker.cx - rootAnchor.cx) * pxToWorld
worldY = root.position.y + (rootAnchor.cy - marker.cy) * pxToWorld
worldZ = root.position.z        // sprite 平面在 root -0.02 偏移，刀光天然在 sprite 之前
```

采样点属性：`{ x, y, width, dirX, dirY }`（width = 双点像素距 × pxToWorld，单点 = 0；dirX/dirY = 双点连线方向归一化后的世界空间刃向，细分时线性插值，单点 = 0）。

> **z 若与其它透明物件冲突**：微调 epsilon 或调整 renderingGroup，实施时以视觉为准。

### 5.3 ribbon 几何构建

```
输入：samples = [ {x, y, width}, ... ]（按帧序）
前置：控制点间 Catmull-Rom 平滑细分（每段固定 10 个子采样，宽度线性插值）——
      稀疏帧 marker 下把折线近似为曲线（同 Unity Line/TrailRenderer 思路）
每采样点 i：
  dir = normalize(P[i+1] - P[i-1])        // 端点用相邻段方向
  perp = (-dir.y, dir.x)                  // XY 平面垂直方向
  v0 = P[i] + perp * width/2
  v1 = P[i] - perp * width/2
索引：三角形条带（strip → triangle list 展开或用 indices）
顶点附加数据：uv.u = i / (n-1)            // 即 t ∈ [0,1]，D7 渐隐预留
```

- 单点采样（width=0）→ v0 == v1，自然收尖。
- 材质 v1：`StandardMaterial`，纯色 emissive、`disableLighting`、`backFaceCulling = false`、alpha = 1。
- mesh parent = **场景根**（世界空间，D4），不挂 character.root。

### 5.4 接口设计

```javascript
class TrailRenderer {
    constructor(scene, character)          // 持有角色引用，读 pxToWorld 等
    update(ctx)     // 每 fixed tick 调用，ctx 见 §6.1
    hide()          // v1：setEnabled(false) + 清采样列（下一任务渐隐时此方法内部改为启动消散）
    dispose()
}
```

`update(ctx)` 内部状态机：

```
当前帧有 marker？
 ├─ 有 → peek-ahead：下一帧无 marker（或已是 clip 末帧）？
 │        ├─ 是 → 采样本帧 → 构建 ribbon → setEnabled(true) + 应用颜色   // "一进入最后一帧就显示"
 │        └─ 否 → 仅采样入列
 └─ 无 → 取样帧结束：ribbon 在显示则立即隐藏（v1 消失规则，修订 2026.11.01）；enterState hide 为兜底
```

> peek-ahead 可行性：clip 全部帧的 marker 数据静态可知（`colliderClip.frames[i].trailMarkers`），无需预测运行时行为。
> clip 末帧有 marker（挥砍动画在 marker 帧收尾）→ 视为"最后一帧"直接构建；`hide()` 兜底。

## 6. 运行时挂点（CombatCharacter.js）

### 6.1 fixedUpdate：动画帧推进之后

```javascript
// 位置：TimeControlSystem.tick 冻结检查通过 → 动画组件帧推进之后
// （冻结时提前 return，采样自动停摆 —— D6）
this.trailRenderer?.update({
    colliderClip,                 // config.clips[clipName].colliderData（含各帧 trailMarkers）
    frameIndex: this.animation.currentFrameIndex,
    rootPosition: this.root.position,
    facing: this.facing,
    trajectory: this.currentStateDef?.attackTrajectory ?? null,
});
```

### 6.2 enterState：离开攻击状态时隐藏（O3）

```javascript
// CombatCharacter.enterState 内（或其覆写点）：
if (prevStateDef?.attackActive === true && newStateName !== prevStateName) {
    this.trailRenderer?.hide();
}
```

- 附赠正确性：clash/hitstun 冻结期间 state 不切换 → 刀光不会提前消失。
- 复用保障：新攻击 state 进入时旧 ribbon 已隐藏、采样列已清。

### 6.3 明确不做

- CombatSystem / ContactResolver / StateGraphDef：**零改动**（D3/D5）。
- 不往 AnimationEventBus 发任何 trail 事件（D2）。

## 9. 测试场景

1. **右向 zornhut**：挥砍进入最后 marker 帧时整条刀光出现，位置与剑刃扫过弧线重合（C 键 debug 对照）。
2. **左向同招（facing=-1）**：镜像正确——换算公式含 facing，刀光在剑刃实际一侧。
3. **quart（thrust + root 前冲）**：轨迹展开为完整世界空间直线/弧线，不被前冲折叠，出现后**不随角色移动**（D4 验收项）。
4. **拼刀 clash**：双方 freezeImpact 冻结期间刀光定格原位不消失（state 未切换）。
5. **攻击被格挡/打断**：刀光照常出现，离开 state 时消失（视觉与战斗判定解耦，D5 验收项）。
6. **连续两次攻击**：第二次攻击复用同一 mesh，无上一次残留。
7. **颜色规则**：slash 与 thrust 刀光颜色不同，与 TRAIL_COLORS 表一致。
