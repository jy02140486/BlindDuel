# 箭头推广到所有可互动对象计划

## 0. 目标与范围

### 目标

将现有的 Trigger 互动箭头机制扩展到 PickableEntity 和 NpcCharacter，统一为**所有可交互对象提供方向提示箭头**，让玩家在探索场景中一眼发现哪里可以互动。

### 本期覆盖

| 目标 | 检测方式 | 现有提示 | 本期改造 |
|---|---|---|---|
| **AABBTrigger**（sceneSwitch / battle / sequence） | AABB 盒子重叠 | ✅ Arrow | 接口不变，底层重构 |
| **PickableEntity** | 距离检测 `<= 1.6²` | ❌ 无 | ✅ 新增 Arrow |
| **NpcCharacter** `_needsInteract === true` | 距离检测 `<= greetingRadius²` | ⚠️ 只有 dialogueBubble | ✅ 新增 Arrow |

### 决策（已定）

| # | 问题 | 决策 |
|---|---|---|
| 1 | Pickable 箭头显隐 | 接近才显示（1.6 距离内） |
| 2 | NPC 箭头 | 只在 `_needsInteract === true` 时显示 |
| 3 | 箭头方向 | 静态配置 up/down/left/right（复用 direction 字段） |
| 4 | 配置方式 | 统一在 EntityDef JSON 里显式写 `"arrow": {...}` |

### 不在本期

- 箭头浮动动画（Y 轴 sin 波动）
- 多种箭头皮肤（quest / warning）
- off-screen HUD 箭头（屏幕外提示）
- 箭头方向动态指向玩家
- 普通 idle NPC 的对话箭头（只有 quest 交付状态显示）

***

## 1. 核心设计：三层职责分离

三个职责必须分开，互不渗透。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ Layer 1: Hint Source（业务逻辑层）                                         │
│ 谁应该被提示 + 提示在哪里                                                    │
│                                                                          │
│ 接口：queryHint(playerPos) → { anchor: Vector3 } | null                  │
│                                                                          │
│ AABBTrigger.queryHint(playerPos)   → 自己判断盒子重叠 + 自己算 anchor     │
│ PickableEntity.queryHint(playerPos) → 自己判断拾取距离 + 自己算 anchor    │
│ NpcCharacter.queryHint(playerPos)  → 自己判断 needsInteract + 距离 + anchor │
├──────────────────────────────────────────────────────────────────────────┤
│ Layer 2: Hint Manager（编排层，就是 ExploreMode 里的一个简单循环）            │
│ 统一遍历 sources，根据 queryHint 结果控制 ArrowIndicator 的显隐和位置          │
│                                                                          │
│ 没有独立类，没有注册框架。就是 ExploreMode.fixedUpdate 末尾的一个 for 循环。   │
├──────────────────────────────────────────────────────────────────────────┤
│ Layer 3: ArrowIndicator（纯视觉层）                                      │
│ setAnchor(Vector3) / setVisible(bool) / tick(dtMs) / dispose()            │
│                                                                          │
│ 不持有业务对象引用，不知道 trigger box，不知道 needsInteract，不知道          │
│ visualYOffset。只知道：把箭头 plane 放在某个世界坐标，显示一个 4 帧循环动画。  │
└──────────────────────────────────────────────────────────────────────────┘
```

### 为什么要这样分

原来的方案让 ArrowIndicator 越来越胖：既要知道静态 trigger box 怎么算位置，又要知道动态实体 root 怎么偏移，还要判断显隐条件。ExploreMode 里还散落着三套显隐判定（overlap 分支、pickable 距离分支、NPC needsInteract 分支）。

分层之后：

- **ArrowIndicator** 只管视觉，一行业务逻辑都没有。
- **显隐判断** 完全由业务方自己决定（queryHint 返回 null = 不提示，返回对象 = 提示），ExploreMode 里一个循环搞定所有类型，没有任何 `if (kind === "trigger")` 分支。
- **新增类型**（未来宝箱、可破坏物、door）只需要实现 `queryHint` 方法 + 在 JSON 里加配置，不改 ArrowIndicator，不改 ExploreMode。

## 2. queryHint 单一接口

### 设计

鸭子类型，不搞继承体系。每个需要箭头提示的对象实现这一个方法。运行时 ExploreMode._hintSources 里存的就是这些对象。

```javascript
/**
 * 查询当前是否应该显示提示箭头
 * @param {BABYLON.Vector3} playerPos 玩家当前世界坐标
 * @returns {{ anchor: BABYLON.Vector3 } | null}
 *   - 返回 null：不该提示（任何原因：盒子外、已拾取、needsInteract=false、被禁用……）
 *   - 返回 { anchor }：该提示，anchor 是箭头应该显示的世界坐标
 */
queryHint(playerPos)
```

### 为什么返回值里只有 anchor，没有 config

config（scale / direction / frameMs / atlasUrl）是 ArrowIndicator 的**构造时属性**，创建后不变。运行时 Manager 不需要关心配置，只需要知道"要不要显示 + 显示在哪"。

返回 null 就够了——`enabled` 永远等价于"有没有配置箭头"（没配置就不会创建 ArrowIndicator，Manager 根本不会来调 queryHint）。`visible` 已经被 queryHint 的返回值表达了（null = 不显示，对象 = 显示）。

### 三方各自实现

**AABBTrigger**：

```javascript
queryHint(playerPos) {
    if (!this._enabled || this.triggered) return null;
    if (!this.checkOverlap(playerPos)) return null;
    // edge/offset 在 setupArrow 时存到 this._hintConfig 里
    return { anchor: this._computeHintAnchor() };
}

// 原有 _computePosition 改个名，逻辑不动
_computeHintAnchor() {
    const p = this.position, s = this.size;
    const halfW = s.width / 2, halfH = s.height / 2;
    const { edge, offset } = this._hintConfig;
    switch (edge) {
        case "top":    return new BABYLON.Vector3(p.x, p.y + halfH + offset, p.z);
        case "bottom": return new BABYLON.Vector3(p.x, p.y - halfH - offset, p.z);
        case "left":   return new BABYLON.Vector3(p.x - halfW - offset, p.y, p.z);
        case "right":  return new BABYLON.Vector3(p.x + halfW + offset, p.y, p.z);
        default:       return new BABYLON.Vector3(p.x, p.y - halfH - offset, p.z);
    }
}
```

**PickableEntity**：

```javascript
queryHint(playerPos) {
    if (this.isDisposed) return null;
    const dx = this.root.position.x - playerPos.x;
    const dy = this.root.position.y - playerPos.y;
    if (dx * dx + dy * dy > 1.6 * 1.6) return null;
    // Pickable 的 sprite 显示在 root 上方 visualYOffset 处（视觉锚点）
    // ExploreMode 拾取判定用的是 root 位置（逻辑锚点）
    // 箭头对齐 sprite 头顶：root.y + visualYOffset + hintOffset
    const anchor = this.root.position.clone();
    anchor.y += this.visualYOffset + this._hintOffset;  // visualYOffset=1.5, _hintOffset≈0.3
    return { anchor };
}
```

**NpcCharacter**（CharacterBase 上默认返回 null，NpcCharacter 覆盖）：

```javascript
// CharacterBase 默认实现（给未来其他可提示类型兜底）
queryHint(playerPos) {
    return null;  // 默认不提示，子类覆盖
}

// NpcCharacter 覆盖
queryHint(playerPos) {
    const controller = this.npcController;
    if (!controller?._needsInteract) return null;
    const dx = this.root.position.x - playerPos.x;
    const dy = this.root.position.y - playerPos.y;
    const r = controller.greetingRadius ?? 1.6;
    if (dx * dx + dy * dy > r * r) return null;
    const anchor = this.root.position.clone();
    anchor.y += this._hintOffset;  // ≈ 0.5，头顶上方
    return { anchor };
}
```

## 3. ArrowIndicator 彻底简化

### 构造后只暴露四个方法

| 方法 | 职责 |
|---|---|
| `setAnchor(anchor)` | 把箭头 plane 放到算好的世界坐标（Manager 每帧调） |
| `setVisible(visible)` | 显示/隐藏 |
| `tick(dtMs)` | 帧动画步进（4 帧循环） |
| `dispose()` | 释放 mesh / material / texture |

### 构造时传入（运行时不变）

```javascript
new ArrowIndicator(scene, {
    scale: 0.4,           // 默认 1.0
    direction: "up",      // 默认 "up"，决定 plane 初始 rotation.z
    frameMs: 250,         // 默认 250
    atlasUrl: "./Art/Sprite/UI/arrow.png"
})
```

### 构造后不再做的事

- ❌ 不再持有业务对象引用（不再 attachTo / setStaticPosition）
- ❌ 不再有 edge / offset / position / size 字段
- ❌ 不再计算 anchor（由 queryHint 返回）
- ❌ 不再判断显隐（Manager 决定）

### 对比旧方案

旧方案 ArrowIndicator 要处理两种位置模式（静态 trigger box vs 动态实体 root），内部要有 attachTo / setStaticPosition / _updatePosition 分支。现在这些全在 source.queryHint 里做，ArrowIndicator 拿到的就是最终坐标。

## 4. ExploreMode 里的统一循环

### 新增数组和方法

```javascript
// ExploreMode 构造函数新增
this._hintSources = [];

// fixedUpdate 末尾新增调用（替代原 #updateTriggerArrows）
#updateHintArrows(playerPos, dtMs, sequencerBusy) {
    const hidden = sequencerBusy;
    for (const source of this._hintSources) {
        if (hidden) {
            source._hintArrow.setVisible(false);
            continue;
        }
        const hint = source.queryHint(playerPos);
        if (hint) {
            source._hintArrow.setAnchor(hint.anchor);
            source._hintArrow.setVisible(true);
            source._hintArrow.tick(dtMs);
        } else {
            source._hintArrow.setVisible(false);
        }
    }
}
```

**一个 for 循环，一个 `if (kind === ...)` 都没有。**

### 替代关系

| 现有代码 | 改造后 |
|---|---|
| `#updateTriggerArrows`（遍历 triggers + overlap 判定） | **替换为** `#updateHintArrows`（统一循环 + queryHint 判定） |
| （新增）`#updateInteractableArrows`（遍历 pickables + NPC + needsInteract 判定） | **不需要** — 已经被统一循环覆盖 |
| `ExploreMode._triggerArrowsEnabled` / 相关标志 | **删除** — 用 `_hintSources` 数组和 queryHint 返回值替代 |

## 5. 配置规则统一

### 规则

**所有箭头默认关闭。** 必须在 JSON 里显式写 `"arrow": { "enabled": true }` 才会：

1. Scene 初始化时创建 ArrowIndicator
2. 注册到 ExploreMode._hintSources

没有配置 → 完全不创建 → 不管业务状态怎么变都不显示箭头。

### 具体 JSON 示例

**AABBTrigger**（现有格式不变）：

```json
{
    "type": "sceneSwitch",
    "id": "exit_house",
    "pos": [-2, -1, 0],
    "size": [2, 2, 2],
    "arrow": { "enabled": true, "edge": "top", "direction": "up", "offset": 0.3, "scale": 0.4 }
}
```

**Pickable**（新增）：

```json
{
    "archetype": "pickable",
    "id": "ham_01",
    "pos": [6.0, -2.704],
    "visualYOffset": 1.5,
    "arrow": { "enabled": true, "offset": 0.5, "scale": 0.4 },
    "itemDef": { "id": "ham", "name": "火腿", "consumeType": "eat", "atlasKey": "ham", "textureUrl": "./Art/Sprite/items/Ham.png" }
}
```

**NPC**（新增）：

```json
{
    "archetype": "npc_customer",
    "id": "customer",
    "pos": [2.8, -2.04],
    "controller": "npc",
    "arrow": { "enabled": true, "offset": 0.5, "scale": 0.5 }
}
```

### edge 字段语义变化

- **AABBTrigger**：`edge: "top"` 仍表示"箭头相对 trigger 包围盒上沿 + offset 处"（语义不变，向后兼容）。
- **Pickable / NPC**：`edge` 字段不再由 ArrowIndicator 读取，而是在各自的 queryHint 实现里忽略（anchor 直接用 root + hintOffset 算）。为了 JSON 格式统一，可以保留字段但不强制。

### 配置优先级

箭头配置只有一个来源：**EntityDef / TriggerDef 的 JSON 里的 `arrow` 字段**。代码里不塞默认值兜底——没有配置就不创建。

## 6. 生命周期管理

### 创建

Scene 初始化时按配置创建 ArrowIndicator，创建一次。

```javascript
// Scene.js — trigger 创建循环（已有代码加两行）
for (const triggerDef of sceneDef.triggers) {
    const trigger = new AABBTrigger(...);
    if (triggerDef.arrow?.enabled) {
        trigger._hintArrow = new ArrowIndicator(scene, triggerDef.arrow);
        trigger._hintConfig = { edge: triggerDef.arrow.edge ?? "bottom", offset: triggerDef.arrow.offset ?? 0.3 };
    }
    this.triggers.set(triggerDef.id, trigger);
}

// Scene.js — 实体创建后循环（新增）
for (const entity of this.entityPool) {
    const entityDef = sceneDef.entities.find(e => e.id === entity.id);
    if (!entityDef?.arrow?.enabled) continue;

    if (entity.kind === "pickable" || entity.kind === "npc") {
        entity._hintArrow = new ArrowIndicator(scene, entityDef.arrow);
        entity._hintOffset = entityDef.arrow.offset ?? 0.5;
    }
}
```

### 注册到 Hint Sources

在 Scene.init 末尾（或 ExploreMode._buildIndices 时），把所有创建了 `_hintArrow` 的对象收集起来：

```javascript
// ExploreMode 新增（或 Scene.init 末尾）
this._hintSources.length = 0;
for (const trigger of scene.triggers.values()) {
    if (trigger._hintArrow) this._hintSources.push(trigger);
}
for (const entity of scene.entityPool) {
    if (entity._hintArrow) this._hintSources.push(entity);
}
```

### 更新

每帧 `#updateHintArrows` 循环里调 `queryHint`：

- queryHint 返回 null → setVisible(false)
- queryHint 返回对象 → setAnchor + setVisible(true) + tick

**没有创建/销毁逻辑。** ArrowIndicator 创建后就挂在对象上，跟着对象一起活。

### 销毁

Scene.dispose() 统一清理：

```javascript
// Scene.dispose() 末尾新增
for (const trigger of this.triggers.values()) {
    trigger._hintArrow?.dispose();
    trigger._hintArrow = null;
}
for (const entity of this.entityPool) {
    entity._hintArrow?.dispose();
    entity._hintArrow = null;
}
```

Pickable 被拾取时不需要单独清理 ArrowIndicator——Scene.dispose 统一兜底。

## 7. AABBTrigger 向后兼容

### 对外接口保持不变

现有 Scene.js 和 ExploreMode.js 里调用的 setupArrow / updateArrow / disposeArrow 全部内部适配，**签名不变**：

```javascript
setupArrow(config) {
    this._hintArrow = new ArrowIndicator(this.scene, config);
    this._hintConfig = { edge: config.edge ?? "bottom", offset: config.offset ?? 0.3 };
}

updateArrow(visible, dtMs) {
    // 这个方法 ExploreMode 不再调用，但保留给向后兼容
    const hint = visible ? this.queryHint(this._lastPlayerPos) : null;
    if (hint) {
        this._hintArrow.setAnchor(hint.anchor);
        this._hintArrow.setVisible(true);
        this._hintArrow.tick(dtMs);
    } else {
        this._hintArrow.setVisible(false);
    }
}

disposeArrow() {
    this._hintArrow?.dispose();
    this._hintArrow = null;
}
```

### 关键：ExploreMode 不再调用 `trigger.updateArrow`

原来 ExploreMode.#updateTriggerArrows 是直接调 `trigger.updateArrow(visible, dtMs)`。改造后 ExploreMode.#updateHintArrows 是**直接调 `source.queryHint(playerPos)` + `source._hintArrow.setAnchor/tick`**，完全绕过 AABBTrigger 的 updateArrow 方法。

但 setupArrow / disposeArrow 保留，Scene.js 里现有初始化代码继续调。

## 8. 实施步骤（带验证）

### 阶段一：内部重构，不动调用方，回归确认

旧调用链是 `ExploreMode.#updateTriggerArrows → trigger.updateArrow(visible, dtMs) → AABBTrigger 内部 ArrowIndicator`。阶段一只改 ArrowIndicator 和 AABBTrigger，ExploreMode 调用方完全不动。

| Step | 内容 | 验证标准 |
|---|---|---|
| **1** | ArrowIndicator 简化：只保留构造 / setAnchor / setVisible / tick / dispose。删除所有位置计算逻辑（edge / offset / size）。 | ArrowIndicator 构造不报错；setAnchor 后 plane.position 正确；tick 帧动画 4 帧循环正常 |
| **2** | AABBTrigger 适配：新增 queryHint / _computeHintAnchor；setupArrow / updateArrow / disposeArrow 内部改为调新 ArrowIndicator；**对外签名不变**。 | **关键回归点**：启动 game，走进 sceneSwitch trigger → 箭头出现且位置/帧动画/显隐与改造前完全一样；走出盒子消失；sequencer 期间箭头隐藏。Exit_house 和 enter_tavern_room 两个 trigger 都测。 |

### 阶段二：统一调用方

ArrowIndicator + AABBTrigger 回归确认后，再改 ExploreMode 的调用方式，把旧的 `#updateTriggerArrows` 替换为 `#updateHintArrows`。这一步只影响调用方，不影响 AABBTrigger 内部逻辑——但改完后 AABBTrigger 箭头应该仍然正常工作（调用方从 `trigger.updateArrow(visible, dtMs)` 换成了 `source.queryHint(playerPos) + source._hintArrow.setAnchor/tick`，本质等价）。

| Step | 内容 | 验证标准 |
|---|---|---|
| **3** | ExploreMode 删 #updateTriggerArrows；新增 `_hintSources` 数组 + `#updateHintArrows` 方法；fixedUpdate 里替换调用为新的统一循环 | AABBTrigger 箭头仍然完全正常（同一套 queryHint 逻辑被新循环驱动）。全局搜索确认无残留 `#updateTriggerArrows` 或 `trigger.updateArrow` 调用 |
| **4** | Scene 初始化适配（trigger + 实体创建循环里统一创建 ArrowIndicator + 注册 sources） + Scene.dispose 统一清理 | 场景加载无错误；切场景无 ArrowIndicator mesh 残留 |

### 阶段三：扩展新类型

调用路径稳定后，再加 Pickable 和 NPC。新增类型的逻辑完全在各自的 queryHint 实现里，不改 ArrowIndicator，不改 ExploreMode 统一循环。

| Step | 内容 | 验证标准 |
|---|---|---|
| **5** | PickableEntity 加 queryHint + Scene spawn Pickable 时按配置创建 ArrowIndicator | Scene spawn Pickable 后 entity._hintArrow 非空；queryHint 在 1.6 内返回非 null；Pickable 没配置 arrow 时完全不创建 |
| **6** | CharacterBase 加 queryHint 默认实现（返回 null）；NpcCharacter 覆盖（读 controller._needsInteract + greetingRadius） | Scene spawn NPC 后 entity._hintArrow 非空（有配置时）；needsInteract=true 且距离内 queryHint 返回非 null；needsInteract=false 时返回 null |
| **7** | **给实际场景配 arrow JSON 配置** | `ep1_tavern_hall.json` 给 ham_01 / tea_01 / dagger_01 加 `"arrow": { "enabled": true, "offset": 0.5, "scale": 0.4 }` |

| **9** | 边界场景 | Pickable 被拾取后箭头随 Entity 消失；dispose 无 mesh 残留；NPC 远离 greetingRadius 后箭头消失 |

## 9. 风险与回退

### 风险

| 风险 | 影响 | 概率 | 缓解 |
|---|---|---|---|
| ArrowIndicator 构造失败（纹理加载） | 该对象无箭头，不影响其他 | 低 | try-catch + warn，source 正常创建 |
| Pickable queryHint 位置不准（visualYOffset + hintOffset 和 sprite 实际位置偏差） | 箭头位置略偏 | 中 | 实测微调 hintOffset |
| NPC queryHint 覆盖不完整（needsInteract 变 true 后箭头没显示） | 体验缺失 | 低 | 确保 NpcCharacter.queryHint 里正确读 controller._needsInteract |
| 删除 updateTriggerArrows 后旧代码有调用残留 | 运行时报错 | 低 | 全局搜索确认无残留引用 |

### 回退

1. **全局禁用**：删掉所有 EntityDef / TriggerDef 的 `"arrow"` 字段 → 零箭头
2. **模块禁用**：注释 ExploreMode.#updateHintArrows 调用 + Scene 里的 ArrowIndicator 创建 → 什么都不变
3. **Step 1-2 是纯内部重构**，AABBTrigger 对外接口不变，可独立验证回归
