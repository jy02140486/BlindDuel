# 26.11.27 疲劳感知导致AI行为退化修复计划

> 依据：调查文档《26.11.27 引入疲劳后AI行为多样性退化调查.MD》§9.4 四因子拆分定案。
> 修复原则（GPT 评审采纳）：① repetitionCost 不动；② 先恢复被排挤的候选；③ 低耐力有合理恢复行为；④ 保留角色风格差异；⑤ 不加随机出招。

## 一、P1 疲劳门 / 耐力动力学（第一优先）

### P1.2 RELEASE 通道物理底线（✅ 26.11.27 已实施并验收通过）

- **证据**：调查 §8.4——manatarms 在 stamina=0、proj=0% 时 smash 仍 →RELEASE，硬门唯一的破产漏洞；
- **挂点**：`AIController.js:1906`（原 1904，插入 releaseFloor 读参后顺延）`const releaseable = opportunity === "preemptive" || opportunity === "clashSeeker" && projected >= releaseFloor;`
- **改法**：加投影底线，CombatTuning 加 `releaseFloor: 0.02` 参数（`AIController.js:1889` 读参，设 0 可回滚现行为）；
- **验收**（26.11.27 manatarms 局日志）：8 条带 opp= 资格条目中 6 条 proj=0% + preemptive/clashSeeker 组合（修复前必 RELEASE 的破产场景）全部 →BLOCK，零漏网，无 `proj=0%→RELEASE`；
- **验收边界**：正面路径（proj≥2% 合法 RELEASE 放行）本局未触发——6 次机会窗口时 stamina 全在 5~21；需一场 clashSeeker 机会落在 stamina 22~30 的战斗补正面证据，非阻塞项；
- **rabble 局确认**：RELEASE 通道仅对 clashSeeker/preemptive 生效，rabble 局日志无 opp= 条目属预期，不构成回归。

### P1.1 低耐力恢复倾向（方向 B，核心改动）（✅ 26.11.27 已实施并验收通过）

- **证据**：调查 §9.4——所有世界里 dash 最高 rf 时刻均被门杀（C 世界 tick3922~3946 连续 5 tick rf=0.91 但 stamina 12~16）；26.11.27 复验加强：rabble 局与 manatarms 局 POS retreat=0.000 全程零例外，manatarms stamina 最低探到 5 仍无拉开恢复意图，stamina 死锁 5~100 震荡（rabble 15~52）；
- **rabble 死锁闭环（26.11.27 rabble 局定性）**：stamina 低 → gate 锁 dash/swing → 唯 thrust 可打 → thrust 命中 → fail budget 不累积 → 无失败驱动脱离 → stamina 不恢复 → 循环；P1.1 是该死锁的总闸门；
- **现状**：疲劳周期状态机已存在（`AIController.js:2030-2035` exitLine），但 `#scorePositioning`（2645-2687）不读耐力——低耐力时 AI 缺少"主动拉开等恢复"的入口，只有三招全灭才自发 hold（C 世界实测）；
- **改法**：疲劳周期 active 且 `staminaRatio < fatigueRetreatLine`（建议 0.35，tuning 参数）时，给 hold/retreat 加 `positioningBias`（建议 +0.10~0.15，tuning 参数，设 0 关闭）；优先挂在现有疲劳周期状态机上而非新建机制；
- **防永久后撤**：退出条件复用现有 exitLine（ratio ≥ exitLine 即退出疲劳管理）；bias 设上限；
- **验收**：低耐力 tick 中 `POS: retreat/hold` 加权生效且可归因（打 `fatiguePosBias` 日志）；dash rf≥0.9 被 gate 杀死的 tick 占比下降；stamina 恢复到 exitLine 以上后行为恢复常态。
- **实施记录（26.11.27，含两次调参）**：`AITuning` 新增 `fatigueRetreatLine`/`fatiguePositioningBias`；`#updateFatigueCycle` 三个早退分支清零防 stale，周期末尾按 retreatLine 计算 `_fatiguePosBias`（上升沿打日志）；`#scorePositioning` hold（门控 holdScore>0 尊重带边界）与 retreat 两点平加。复测修正三处：① retreat bias 移到 `retreatScore *= retMult` 之后（首版被 posture multiplier ≈0.73 稀释成 0.088 < approach 0.129 退不干净）；② 疲劳恢复期跳过 holdTimeout 归零闪烁（hold 归零一拍 → retreat 赢半步 → hold 回来的周期性抽搐）；③ 调参 retreatLine 0.35→0.50（盖住 36~45 thrust 抢蓝 gap：bias 35 就退出但 dash 需 46 过 gate）、bias 0.12→0.15。
- **验收结论（26.11.27 复测局）**：四项全过——恢复期连续 15 tick 稳定 `best=retreat` 无闪烁；36~50 全程 thrust 无 commit（spam 断流）；ratio 过 0.50 时 bias 精确退出 → approach 接管拉回（反永久后撤闭环）；低耐力 tired-advance 消失。

### P1.3 reserve 软带（暂缓）

GPT 方向 A（软惩罚）需配套执行层 clamp 才安全（cost 与实际扣费同源，评分放行会真扣穿），调查 §7.2 已证明硬门是破产保护主体——暂缓，待 P1.1 效果观察后再评估。

## 二、P2 仲裁线对短带撞击招的减免（✅ 26.11.27 已实施并验收通过）

- **证据**：dash 两次擦边死 0.143（世界 A）/ 0.148（世界 C）vs 0.15，系统性偏严；26.11.27 补充：rabble 局 dash 过门后三 tick 得分 0.041/0.048/0.124 全 <0.15（最近差 0.026），同款擦边死；manatarms 局三招均被选过（仲裁线 0.0375 天然低），P2-A 需求集中于 rabble 侧；
- **约束**：`AIController.js:519` 注释——0.15 按人格 baseWeight 缩放（manatarms 0.15×0.10/0.40=0.0375），**不能动全局阈值**，否则破坏人格缩放；阈值定义在 `AITuning.js:36`，缩放读取在 `AIController.js:528`；
- **方案（推荐 A）**：在评分侧加 `anchorMisalignRelief`：攻击候选 effR < 当前 idealEffReach 时 +0.03（tuning 参数 `thresholdRelief`，设 0 关闭）——只帮到撞击类短带招，不影响防御候选与人格缩放；
- **备选 B**（不推荐）：全局降 0.15→0.12，会放进更多低分防御候选；备选 C：per-招 attackPreferences 调权，侵入人格定义；
- **验收**：dash 在 rf 健康 + stamina 过门时不再以 <0.01 差距擦边死；仲裁线仍能拦住防御/位置低分候选。
- **实施记录（26.11.27，含一次调参 + 一次岔路口决策）**：方案 A 落地，`AITuning.thresholdRelief` 初值 0.03（effR < idealEffReach 的攻击候选乘性阶段后平加，`#scoreAttack` 末尾）。复测：机制精确生效（同条件 tick 0.048→0.078）但 argmax 层仍全输——① 3.0m 站位点 0.119+0.03=0.149 差 0.001 擦边死 → relief 调 0.04（3.0m 处 0.159 过线，3.1m 外不触发，外溢受控）；② 过线后 dash 0.157~0.273 全输同带 thrust(3.0m)/swing(2.7m)（argmax 竞争，非阈值问题）→ 触发观察项 1 的岔路口决策：走「角色风味加权」，`AI_PROFILE_NORMAL`（rabble 莽夫型）新增 `attackPreferences.dash=1.5`——实测验算 2.74m 处 (0.273−0.04)×1.5+0.04=0.390>swing 0.364 开窗，2.9m+ 不动 thrust 带，cd/rep 负分段乘性放大不穿透；仅 Normal 风味，非全局改动。

## 三、P3 manatarms 锚点偏移（holdAnchorBias 参数化）

- **证据**：调查 §8.1——smash rf 从未达 1.0（AI 最低 dist 3.04 > effR 2.69，无重叠）；rabble 侧锚点已因数据改动结案（§9.4），manatarms 侧仍待处理；
- **挂点**：`#getIdealEffReach`（`AIController.js:3140-3153`）median 结果上加 tuning 参数 `holdAnchorBias`（per-角色可配）；
- **改法**：manatarms 建议初值 -0.3~ -0.45（理想距离 2.94→2.5~2.6，hold 上界 3.38→2.9~3.0，smash 进入 rf 可用区）；rabble 默认 0；
- **验收**：manatarms hold 上界下移（POS: 行可验）；smash 在非 startup 期出现 commit（不再纯迎击专用）；smash 超射程出手（tick9861 型 miss）减少。

## 四、观察项（本轮不动手）

1. **swing 同门压制（✅ 26.11.27 已决策关闭）**：dash 与 swing 同 cost 同门但全维劣（effR 2.49 vs 2.65）——P1/P2 落地后 dash 频率仍为 0 触发决策：不走评分全局改动（burst 伤害/破防加分侵入所有人格），走角色风味——`AI_PROFILE_NORMAL.attackPreferences.dash=1.5`（见 §二实施记录）；"贴脸专属"生态位由 approach 天花板 3.05m + relief 0.04 自然达成；
2. **punish 释放**（R2）：punish 无逐候选时序验证，故意不放行——启用需先补验证，成本高，暂不评估；
3. **拦截评分无距离门**（26.11.27 manatarms 局新增）：smash startup=20ms 拦截评分在 rf=0.00 完全够不到的远距离（dist 4.37/4.99/5.09）仍得 0.15~0.20 被 commit，导致超射程空挥——oppPhase=startup 时 attack 拦截分量应加射程可达性门；
4. **日志阅读坑**：fatigueAttackGate 行有 2500ms 节流（`_fatigueAttackGateLogUntil`），与相邻 commitArbitration 行可能非同 tick，验收时勿将两行作同帧证据配对。

P1.2（一行）✅ → P2-A（一个 relief 项）→ P1.1（疲劳周期挂 positioningBias）→ P3（per-角色 bias）
