## 一、设计基线

### 1.1 角色特性

- **常驻 shield**：strong_blade 颜色的强剑身 collision box 在所有状态下都存在，由 CharacterFactory config 级 `guardType: "shield"` 兜底生效（绕过了 `guardType 只在 guard 状态设` 的约束，但对 Manatarms 无 guard 状态的设计合理）
- **无 guard 状态**：角色不能主动进入防御姿态，防御能力来自被动 shield
- **break rule**：shield 能挡 thrust + light slash，**唯独 heavy slash 能破盾**（被破后进入 stunned 长硬直，shield 吸收本次伤害不扣血）
- **无 dodge / 无 throw / 无 guard**：纯输出 + 被动防御型
- **三个 attack**：quart (light slash) / reverse_quart (light slash, chainBonus → bonusTimeScale: 1.5) / smash (heavy slash)

### 1.2 克制规则（代码已实现）

| 对手攻击 | shield 结果 | 代码位置 |
|---|---|---|
| thrust | 被挡 | ContactResolver.js:91 (`!(thrust && heavy)` = true → blocked) |
| light slash | 被挡 | ContactResolver.js:92 (`!(slash && heavy)` = true → blocked) |
| heavy slash | **破盾** (stunned) | ContactResolver.js:92 (`!(slash && heavy)` = false → blocked=false) |

### 2.5 ContactResolver：shield_broken effect

**✅ 已完成**：Phase 1 shield 分支 blocked=false 路径 + invalidatedAttacks + shield_broken effect + evaluateInteraction 扩展（ContactResolver.js:91-107 + 542-579）

**文件**：`scripts/Systems/ContactResolver.js`

Phase 1 shield 分支（当前代码只处理 blocked=true 路径），补 blocked=false 路径：

```javascript
// 现有
} else if (guardType === "shield") {
    if (!(trajectory === "slash" && weight === "heavy")) blocked = true;
}

// 改为
} else if (guardType === "shield") {
    if (!(trajectory === "slash" && weight === "heavy")) {
        blocked = true;  // 正常挡下
    } else {
        // 破盾！heavy slash 击穿 → shield 吸收本次伤害，跳过 Phase 2
        invalidatedAttacks.add(offenseAttackId);
        effects.push({
            type: "shield_broken",
            targetId: defenseCharId,
            context: {
                attackerId: offenseCharId,
                attackInstanceId: offenseAttackId,
                knockbackX: this.#signedKnockback(offensePos, defensePos, this.tuning.block.knockbackX)
            }
        });
        // 注意：不推 defenseSuccess（那是 blocked 才推的）
    }
}
```

**注意**：`invalidatedAttacks.add` 确保攻击不进 Phase 2 → 被 heavy slash 破盾的 Manatarms **本次不扣血**。shield_broken effect 携带 knockbackX，stunned 状态进入时施加击退。

**evaluateInteraction 扩展**：

返回值加 `shieldBroken: boolean` 分支（heavy slash vs shield），供 AI 区分三种结果：blocked / shieldBroken / 穿透命中。

### 2.6 CombatSystem：处理 shield_broken effect

```javascript
if (effect.type === "shield_broken") {
    const target = combatants.get(effect.targetId);
    if (target?.hasState("stunned")) {
        // 给个击退
        const kb = effect.context?.knockbackX ?? 0;
        if (kb !== 0) target.root.position.x += kb;

}
```

### 2.7 CombatCharacter：passiveShieldDisabled 检查

**✅ 已完成**：CombatCharacter.js:333-335，stunned 状态期间 shield 消失

**文件**：`scripts/Enties/CombatCharacter.js`

getCombatSnapshot() strong_blade boxRole 判定里加状态级开关：

```javascript
// 现有
const boxRole = box.subtype === "strong_blade"
    ? (this.currentStateDef?.guardType || this.config?.guardType ? "shield" : null)

// 改为
const passiveShieldDisabled = this.currentStateDef?.passiveShieldDisabled === true;
const effectiveGuardType = this.currentStateDef?.guardType
    || (this.config?.guardType && !passiveShieldDisabled ? this.config.guardType : null);
const boxRole = box.subtype === "strong_blade"
    ? (effectiveGuardType ? "shield" : null)
```

**效果**：stunned 状态配了 `passiveShieldDisabled: true` → strong_blade box 在 stunned 期间不被当成 shield → 对手后续攻击穿透 → 正常 hit + 扣血。

## 三、stunned 期间行为验证

| 场景 | 预期 | 机制 |
|---|---|---|
| stunned 期间对手 thrust | shield 不存在 → 穿透 → hit + 扣血 | stunned 状态配 passiveShieldDisabled → effectiveGuardType=null |
| stunned 期间对手 light slash | 同上 | 同上 |
| stunned 期间对手 heavy slash | 同上 | 同上 |
| stunned 结束 | 回 idle | transitions: normalized >= 1.0 → idle |
| stunned 期间被连续 hit 打死 | HP 归零 → defeated | 正常 hit → HP ≤ 0 → deathState |

## 四、AI 自我认知 shield（本次要做）

> 方向纠正：Manatarms AI 需要**认识自己的 shield 能力**来减免 threatPenalty，
> 而不是让对手 AI 识别 Manatarms（LongSwordMan 对手预测能力不变）

### 4.1 改动点

**AIController.js #buildSituation**：
```javascript
// 新增：self 防御能力暴露（config 级，不对其他角色产生副作用）
const selfGuardType = this.character.config?.guardType ?? null;
// LongSwordMan / RabbleStick → null（他们 guardType 在状态图 guard 状态里）
// Manatarms → "shield"
```

**AIController.js #scoreAttack threatPenalty 减免**：
```javascript
// 现有：一律全额扣
threatPenaltyApplied = sit.oppThreat * this.tuning.attack.threatPenalty;

// 改为：能挡住的招 → threat 几乎不算威胁
const canBlock = sit.selfGuardType
    ? ContactResolver.evaluateInteraction({
        offenseTrajectory: sit.oppAttack?.trajectory ?? null,
        offenseWeight: sit.oppAttack?.weight ?? null,
        defenseGuardType: sit.selfGuardType,
        defenseIsDodging: false,
    }).blocked
    : false;  // 没防御能力 → 全额扣
const effectiveThreat = canBlock ? sit.oppThreat * 0.1 : sit.oppThreat;
threatPenaltyApplied = effectiveThreat * this.tuning.attack.threatPenalty;
```

**AIController.js #scorePositioning retreat 阈值同理**：能挡的招不需要急着退

### 4.2 效果

| 对手出招 | Manatarms shield 能不能挡 | 旧 threatPenalty | 新 threatPenalty |
|---|---|---|---|
| quart / thrust（light） | ✅ 挡 | 全额扣 | 扣 10% |
| zornhut（heavy slash） | ❌ 破盾 | 全额扣 | 全额扣 |

### 4.3 不受影响的角色

- LongSwordMan：config.guardType=null → selfGuardType=null → canBlock=false → 全额扣 → **不变**
- RabbleStick：同上 → **不变**
