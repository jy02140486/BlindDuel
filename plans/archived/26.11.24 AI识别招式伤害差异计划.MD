# AI 识别招式伤害差异计划

> 类型：AI 系统增量扩展（时序一致性 + 数据接入）
>
> 参考输入：`plans/26.11.24 AI处理招式伤害差异GPT-Guildline.MD`（已按代码视角修正过虑/欠妥点）
>
> 原则：不改四层架构、不加 candidate kind、不改 Action Commitment、不动 aiProfile。

## 一、背景与代码事实

1. **Tag 机制**：`CharacterBase` 有 stateTags（状态内有效）+ timedTags（按 tick 到期）。tag 加速效果硬编码在 `CombatCharacter._getStateTimeScale`：持有 `chainBonus` 或 `postDefenseCounterActive` 时用 `stateDef.bonusTimeScale`。
2. **同一状态两条入场路径**：reverse_quart 从 idle 出 = 基础速度；quart 中接（chainBonus 门）= 1.5× 加速。`enterState` 内 `_getStateTimeScale` 在 `clearTags` **之前**调用，加速才能生效（时序敏感）。
3. **AI 现状**：`#isCommitted` 让 AI 在 attackActive 期间跳过决策 → AI 打不出 quart→reverse_quart 连招（无 chainBonus 豁免；guard+postDefenseCounterActive 豁免是现成先例）。
4. **统一换算口已存在**：`AIController.#getEffectiveTiming(timing, char)`（26.11.9 疲劳计划所建），所有绝对 ms 消费点已收敛至此。`#getAttackPhase` 用 startup/total 比值，均匀缩放下不变。
5. **对手侧感知不可 tag 反推**：AI 预测对手连招发生在对手已进入 reverse_quart 之后，此时 chainBonus 已被 clearTags 清空——任何基于读 tag 的方案在对手侧都算错。
6. **伤害结算规则**：`attackDamage ?? CombatTuning.hit.damageByWeight[attackWeight]`（CombatCharacter 结算同源）。当前表：light=1、heavy=2、nachschlag 覆写 3（玩家专属）；reverse_quart 无覆写=1（26.11.25 复核，见 D4 最终修正）

## 三、实施步骤

### 目标 A：Effective Timing 一致性修复（✅ 已完成 26.11.25）

- A1 `CombatCharacter.enterState`：将 `_getStateTimeScale(stateDef)` 的**返回值**快照到 `combat.stateEntryTimeScale`（已含 bonusTimeScale 与疲劳减速）。
- ⚠ **红线（P2）**：必须在 enterState 内取函数返回值，不能事后读 `animation.getTimeScale()`——hitstop 会把 animation timeScale 置 0，实时读是脏数据。

- A2 `AIController.#getEffectiveTiming(timing, char)`：按目标角色状态**分流**（落地修正，非原稿的"替换"）：char 已在 fatigable 状态（timing 对应状态已入场）→ 快照口径（`base / stateEntryTimeScale` 得缩放系数，对手 chain 加速可被预测）；否则（idle/guard 中预测候选招式，无对应入场快照）→ 保持 26.11.9 实时疲劳口径。两口径互斥不叠加。严格"替换"会让疲劳 AI 在 idle 中丢候选招式疲劳缩放，违反 A-T1。fatigable 名单单一源头 = `CombatCharacter.isFatigableState` getter。
- 回归验证 26.11.9 疲劳日志口径（`fatigueCycle` / `[AI-Diag] COMBAT` 的 stamina 字段，实时分支不受影响）。

- A3 文档：战斗规则说明.MD §8.3 "1.75" → 实际值（zornhut 1.2 / nachschlag 1.0，P3 保持现状）；AI系统说明.MD 补「effective timing 快照口径」（含 A1 红线）。PROJECT_CONTEXT §3 伤害示例保留不动（D4 反转后仍正确）。

### 目标 B：Damage-aware Decision（✅ 已完成 26.11.25）

- B1 数据接入：`AIKnowledgeRegistry` 扫描 attack profile 时记 `damage = stateDef.attackDamage ?? CombatTuning.hit.damageByWeight[attackWeight] ?? 1`，与结算同源。接入 ≠ 决策，B2 才满足需求。
- B2 评分接入：`#scoreAttack` 增加有界乘性次级评价，灵敏度挂 aiProfile.baseAggression（人格差异化）：
  `aggScale = 0.5 + 1.0 × baseAggression`
  `damageFactor = clamp(1 + 0.08 × (damage - 1) × aggScale, 0.85, 1.20)`
  **作用域与组合顺序（防罚项被放大）**：damageFactor 只乘 base 段，罚项在乘法之后原值减去，不被倍率放大：
  `Score_attack = BaseUtility × attackPreference × damageFactor + Bonuses − Penalties`
  （repetitionCost / feedbackFailPenalty / riskA / riskB 均在乘法之后原值扣减）。
  数值：agg=0.25（manatarms）heavy=1.06/3伤=1.12；agg=1.0 heavy=1.12/3伤=1.24→cap **1.20**。伤害因子仅作用于攻击候选，对整体排序的影响被全局上下限约束，**不保证跨类别排序不变**（有界影响≠无影响）——跨类别防线由 B-T3 验证兑底。常量集中定义便于调参。挂配置级而非动态 caution 的理由：动态值随压力浮动会形成反馈环+行为噪声，动态耦合记 backlog。
  **落地记录（26.11.25）**：罚项保护以基座/罚项双跟踪器实现（`_baseBonusSum`/`_penaltySum`，意图权重重组处 `common = 基座×commonW×damageFactor − 罚项×commonW`，damageFactor=1 时与原公式逐项相等，轻招零漂移）；常量块命名 `DAMAGE_FACTOR_TUNING`（评分加权语义，非战斗规则）
- B3 diag：`[AI-Diag]` 候选输出加 `d=` 字段，供边界验证与分布监控。（落地记录：`d=` 输出 KB damage 原值 1/2/3 而非 damageFactor——factor 可由公式反推，`d=?` 即缓存未刷新信号）
- B4 文档：AI系统说明.MD 补「伤害次级评价（有界）」节。

## 四、验收与回归测试

**A 组（时序正确性）**
- A-T1 无 tag：行为与改前完全一致（快照=基础值）。
- A-T2 tag 场景：玩家弹反接 zornhut（1.2×）、Manatarms 连招 reverse_quart（1.5×）——defense timing 门 / dodge i-frame 门与实际攻击时序一致；对手持 tag 预测同验。
- A-T3 疲劳：`fatigueCycle` / `[AI-Diag] COMBAT` stamina 口径与改前一致（验证替换非叠加）。
- A-T4 tag 失效：快照随 enterState 刷新，无残留；hitstop 期间不污染。

**B 组（伤害决策）**
- B-T1 数据：KB 读出 light=1 / heavy=2 / nachschlag=3（reverse_quart 无覆写=1，26.11.25 修正），与结算规则一致。✅ 已验证（26.11.25 日志：Rabby thrust/dash/swing = d=1/2/2，`d=?` 零命中 = KB v7 缓存正常）
- B-T2 边界与人格：agg=1.0 时 3伤=1.24→cap **1.20** / 2伤=1.12 / 1伤=1.0；agg=0.25 时 3伤=1.12 / 2伤=1.06。diag `d=` 核对两档人格输出；另验罚项未被倍率放大（同 damage 不同 rep 值，分差应与倍率无关）。✅ 数学复核通过（26.11.25 日志 tick3391：swing rf=0.45 d=2 sc=0.174≈0.4×0.45×posture×1.08；同 tick thrust rf=0.73 sc=-0.013=罚项压制未被倍率联动放大）。d=3 数值路径机制保留，现役 AI 候选池无 d=3 招式（nachschlag 玩家专属）
- B-T3 跨类别合理性：构造 defense/position 明显更优局面，damage 奖励**不合理**翻转（如轻攻击倍率下仍应输给明显更优的 Guard）应被拦截；允许合理范围内的高伤害招竞争力增强（设计意图）。
- B-T4 多样性与人格：先跑 baseline 记录 `[AI-Diag] best=/top3=` 分布，B 后对比——预期高伤害招使用率随 baseAggression 分化上升（原始需求期望效果），监控无单招垄断，repetitionCost 对高分新宠照常生效。◐ 部分验证（26.11.25：d=2 招在临界局面翻转胜出 tick3391/700；B-T3 旁证：hold(0.142) 胜 attack(0.037)，跨类别序未破坏）；D4 修正后「高伤害招」=heavy(d=2)，长期分布观察并入 P5

## 五、本次明确不做

1. 不让 AI 接 quart→reverse_quart 连招（D2 backlog：#isCommitted chainBonus 豁免 + aiProfile knob 默认 0）。
2. 防御紧迫度不按对手伤害/weight 加权（heavy/light 同分）——defense 侧伤害感知独立 backlog。
3. 双方 HP 不进 Memory/Posture（残血保守语义需独立设计）。
4. damageFactor 不挂动态 posture（cautionFromDamage 等）——反馈环风险，backlog。
3. 不数据化 bonusTimeScale 的 tag 名单（硬编码 → stateDef 声明可后置，独立改动）。
4. 不重构四层架构 / 不加 candidate kind / 不动 Memory 与 Posture。
