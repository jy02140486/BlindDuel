# Phase 1 — Feedback Memory 实施计划

> 基于 `AI_Decision_Adaptation_Guideline.md` Phase 1
> 目标：建立"动作→结果→记忆→下一个评分"的最小闭环

---

## 架构约束（不变）

```
Knowledge 层     — 扫描 StateGraph，只读不改
Rules 层         — CombatResolver 判定结果，只读不改
Decision 层      — AIController 评分选动作
本阶段改动范围   — Decision 层内部 + CombatSystem 结果回传接口
```

Feedback 是**评分输入**，不是新的脚本状态机。连续被 parry 2 次 → 降低 swing 的 Utility → 让评分系统自己决定换不换。

---

## Step 1: CombatResult 事件链（回传接口）

### 需要的 result 类型

| result | 来源 | 含义 |
|---|---|---|
| `hit` | ContactResolver hit 事件 | 我打中了对手 |
| `parried` | ContactResolver parry → 攻击方 | 我被对手 parry 了 |
| `guard_blocked` | ContactResolver guard_block → 攻击方 | 我被对手 guard 挡住了 |
| `clash` | ContactResolver clash → 输方 | 我的攻击被对手拼掉了 |
| `miss` | 攻击动画播完无 hit 事件 | 对手躲开了/我没打中 |

### 接入点

CombatSystem 当前处理完 effect 后有完整上下文，加一个回调即可：

```javascript
// CombatSystem.js — 处理完 hit/clash/guard_block 后
for (const effect of effects) {
    // 现有处理逻辑...

    // 新增：回传给发起攻击的一方的 controller
    if (effect.attackerId && effect.defenderId) {
        const attackerChar = this.scene.getCharacter(effect.attackerId);
        const defenderChar = this.scene.getCharacter(effect.defenderId);

        if (attackerChar?.controller?.onCombatResult) {
            attackerChar.controller.onCombatResult({
                outcome: /* 根据 effect.type + effect.context 判定 */,
                targetState: attackerChar.currentState,
                counteredBy: defenderChar?.currentState ?? null
            });
        }
    }
}
```
### miss 的判定

攻击动画自然结束，没有触发过 hit 事件。在 CombatCharacter 里加：

```javascript
// 攻击状态退出时
if (wasCommittedAttackState && !this._lastAttackHadHit) {
    this.controller.onCombatResult({ outcome: "miss", targetState: prevState });
}
```

## Step 2: Recent Tactical Memory 数据结构

```javascript
// AIController 新增
#memory = {
    entries: [],           // 最近 10 条 { state, outcome, timestamp }
    decayMs: 5000,         // 5 秒前的条目开始衰减权重
    maxEntries: 10
};

onCombatResult({ outcome, targetState }) {
    this.#memory.entries.push({
        state: targetState,
        outcome,
        at: performance.now()
    });
    if (this.#memory.entries.length > this.#memory.maxEntries) {
        this.#memory.entries.shift();
    }
}
```

不做长期学习、不做 player modeling。Phase 1 只需要最近几次结果。

## Step 3: Adaptation 调节器（评分层输入）

```javascript
// AIController 评分前
#computeAdaptationFactor(stateName) {
    const recent = this.#memory.entries.filter(e => e.state === stateName);

    // 连续失败计数
    let consecutiveFail = 0;
    for (let i = recent.length - 1; i >= 0; i--) {
        if (["parried", "guard_blocked", "clash", "miss"].includes(recent[i].outcome)) {
            consecutiveFail++;
        } else {
            break;  // 遇到一次成功就停止
        }
    }

    // 成功计数（衰减失败计数）
    let consecutiveSuccess = 0;
    for (let i = recent.length - 1; i >= 0; i--) {
        if (recent[i].outcome === "hit") {
            consecutiveSuccess++;
        } else {
            break;
        }
    }

    return { consecutiveFail, consecutiveSuccess };
}
```

### 进入评分公式

在 `#scoreAttack` 里加：

```javascript
const { consecutiveFail, consecutiveSuccess } = this.#computeAdaptationFactor(stateName);

// 失败累积惩罚（逐渐加重）
if (consecutiveFail >= 2) score -= this.tuning.attack.feedbackFailPenalty * consecutiveFail;
else if (consecutiveFail === 1) score -= this.tuning.attack.feedbackFailPenalty * 0.5;

// 成功累积奖励（保持惯性）
if (consecutiveSuccess >= 1) score += this.tuning.attack.feedbackSuccessBonus * consecutiveSuccess;
```

### 初始 tuning 值（进 AITuning）

```javascript
// CombatTuning.js 或 AITuning
feedbackFailPenalty: 0.15,    // 每次失败减多少分（连续 2 次 → -0.30）
feedbackSuccessBonus: 0.05,   // 每次成功加多少分（连续 2 次 → +0.10）
```

## Step 4: Continuity 调节器（与 Adaptation 分离）

```javascript
// AIController 新增
#lastCommittedState = null;   // 上一次成功执行的攻击 stateName

#computeContinuityBonus(stateName) {
    if (stateName !== this.#lastCommittedState) return 0;

    // 只有当 Adaptation 没有强烈反对时才给 continuity
    const { consecutiveFail } = this.#computeAdaptationFactor(stateName);
    if (consecutiveFail >= 2) return 0;  // 连续失败 → 不给 continuity

    return this.tuning.attack.continuityBonus;  // 初始 0.05
}
```

### 进入评分公式

```javascript
score += this.#computeContinuityBonus(stateName);
```

## 验证标准

Phase 1 完成后需要看到：

| 场景 | 预期行为 |
|---|---|
| 玩家连续 parry AI swing 2 次 | 第 3 次决策时 swing 评分明显下降，AI 开始考虑 thrust/dash |
| 玩家 guard_block AI swing 2 次 | swing 评分下降，thrust（guard 防不住）有 guardLeakBonus + feedback 间接加持 |
| AI swing 连续命中 2 次 | swing 有 continuity bonus + feedback success bonus → 倾向继续 swing |
| AI 被 parry 1 次 | swing 评分轻微下降，但不一定立刻换招（一次失败不够） |
| AI 换了招后命中了 | 新招开始积累 success bonus，旧招的 fail 计数自然过期（只看最近 10 条） |
