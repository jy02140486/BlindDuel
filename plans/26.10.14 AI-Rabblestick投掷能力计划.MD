# 26.10.14 AI（RabbleStick）投掷能力实现计划

> 状态：方案已定稿（2026-10-14）
> 前置：投掷物基础链路（ThrowComponent / ProjectileManager / ProjectileContactResolver / throw 动画事件）已闭环；AI 投掷物防御（reactive + preemptive）与 Phase 5 统一预测层 `predictedOpponentEvents[]` 已落地
> 原则：为既有同池 Utility 体系**增加一种候选类型**，不重写决策体系；不加入任何「远距离优先投掷」硬编码分支

---

## §1 目标与范围

AI 获得投掷能力：throw 作为独立候选 kind，与 attack / defense / positioning / projectile defense 在同一候选池竞争。AI 无道具栏，弹药数由战斗实例配置直接给定。

- 范围内：BattleDef 弹药配置 → AI ThrowComponent 装配 → 知识层物理射程 → `#scoreThrow` → 执行接线 → AITuning/aiProfile → 诊断日志 → RabbleStick 资产接入。
- 范围外（见 §11 Backlog）：投掷 outcome 回流 Memory、recovery 精确剩余时间、aiProfile 全链路合并、侧移。

## §2 关键设计决策（评审定稿）

1. **独立 `kind:"throw"` + 独立 `#scoreThrow`**。近战与投掷命中机制、时间窗口、资源约束、风险结构不同；`kbProfile.throws` 已由 AIKnowledgeRegistry v3 扫描产出。
2. **配置四层分离**：
   - 弹药数（投掷资源）→ `BattleDef.combatantConfig`（跟战斗走）
   - 投掷意愿 → StateGraph `aiProfile.throwPreference`（方案 a：AIController 直读 `character.stateGraph.aiProfile`，不走 tuning 合并链路）
   - 评分规则/阈值 → `Data/AITuning.js` 新增 `throw` 块（系统级）
   - 运行时弹药真值 → ThrowComponent
   - `projectileType` 单一真相源仍在 throw state（StateGraph），**不进 BattleDef**，避免知识层与运行时类型不一致。
3. **射程来自真实弹道销毁规则**：`R = speed × t_land`（落地时间由 launchVy/gravity 解析）。不用 startupMs 折算射程（release 前投掷物不存在），不拍 lifetime/2。
4. **风险 A 与风险 B 独立计分**：A=release 前被近战打断；B=出手后被 slash 斩落（仅 cuttable 投掷物有此项）。不可斩类型只免 B，不免 A。
5. **recovery 不凭相位白给分**：throw 命中时间长（startup+飞行常 >500ms），仅当 `predictedOpponentEvents` 证明窗口成立才加惩罚分；无数据则 0，不伪造精度。
6. **重复成本复用 `#consecutiveAttackUsage`**，key=throw stateName，不新建计数器；throw→throw 计成本，throw→近战 key 不同自然切换。有限弹药已是天然限制，费率不加重。
7. **冷却共享** `attackCooldownMs` / `lastAttackTime`；throw 执行时同样写时间戳，throw 评分套同形 cooldown 惩罚但**不享 startup 豁免**。
8. **双层合法性**：决策层 `canThrow()` 硬门控（非法候选不进池）；执行层既有 transition gate（`CombatCharacter._matchesTransitionCondition` 已拦截无弹 throw）保留为兜底。
9. `posture.attackMultiplier` 乘入 throw 终分（投掷是进攻行为），不建独立 throwMult。

## §3 Step 0 审计结论（已完成）

- AI 命令与玩家同路：`BaseController.queueCommand()` → `applyToCharacter()` → `character.pushCommand()` → 同一条 StateGraph transition（`{"command":"throw"}`）。
- 弹药在 `throw_release` 动画事件、Projectile spawn 成功后原子扣除（`ThrowComponent.release()`，spawn 失败不扣）；release 帧前被 Hit 打断则不扣。
- BattleDef 当前只有 `combatants` ID 数组（`SceneDefs.js:84`），无每战斗人员配置；BattleMode 仅给 player 装配 ThrowComponent（`BattleMode.js:63` 注释「AI 路径延后」）——**AI 装配路径需新建，不是复用**。
- `CombatMemory.pushCommit(kind, stateName)` 为自由字符串、无按 kind 分支消费，传 `("throw", stateName)` 安全。
- `#consecutiveAttackUsage` 语义：仅 stateName 精确相同时计成本，dodge/guard/positioning 提交时 reset。
- ⚠ `ThrowComponent.DEBUG_INFINITE_AMMO` 当前为 **true**（全局，会让弹药配置失效）——验收前必须置 false。
- ⚠ `ProjectileDefs.rock` 已定义（cuttable:false）但 `proj_rock` 美术不存在；当前仅 dagger 有美术。
- aiProfile 合并链路整体未接通（Posture 未收 overrides、Scene 传裸 AITuning、attackPreferences 永远走 `?? 1.0`）。本次按方案 a 直读绕开，技术债记 Backlog。

## §5 Step 2：知识层补弹道物理射程

### 5.1 物理模型（与 Projectile 真实积分一致）

Projectile 为 X 匀速 + Y 重力抛物线，回到 thrower 的 groundY 即落地销毁（`Projectile.js:159-172`）：

```
t_land  = 2 × launchVy / gravity        （秒，launchVy>0）
R_phys  = speed × t_land                （世界单位）
launchVy ≤ 0 的直射类型：t_usable = lifetimeMs / 1000（lifetime 兜底）
```

当前数值：dagger = 0.5s × 6 = **3.0m**；rock = 0.6s × 5 = **3.0m**；spear = 0.4s × 8 = **3.2m**。

### 5.2 `AIKnowledgeRegistry.#scanThrowState()` 扩展

该函数本就 cross-reference ProjectileDefs（`AIKnowledgeRegistry.js:564`），射程在扫描期算一次，评分层只读不算。profile 在现有字段上新增：

```js
flight: {
    landingFlightMs,    // t_land × 1000（或 lifetimeMs 兜底）
    physicalRange,      // speed × t_land
    effectiveRange,     // physicalRange × AITuning.throw.rangeConservatism（扫描期注入默认 0.85）
}
```

- `#SCHEMA_VERSION` bump（扫描逻辑变化，强制缓存失效，项目既定约定）。
- 战斗 Y 轴被 stageBounds 限制在 ±0.05，双方近似同线，R 直接按 X 距离使用。

### 5.3 近战边界口径统一

三区间需要的「近战最远有效距离」必须与 `#scorePositioning` 的 `maxEffReach = maxReach + maxFwdBoost + rangeBuffer` 完全一致。当前该口径在 positioning 内联计算——本次抽一个私有 helper（如 `#getMeleeMaxEffReach()`），positioning 与 throw 共用，禁止 throw 自造第二份边界。

## §6 Step 3：`#scoreThrow(throwProfile, sit)`

候选接入（`#makeDecision()` 现有 attacks/dodges/guards 循环旁并列，**不加任何 if 距离分支**）：

```js
for (const t of this.kbProfile?.throws || []) {
    scored.push({ kind: "throw", action: t, score: this.#scoreThrow(t, sit) });
}
```

### 6.1 硬门控（非法候选不进池，return 0）

1. `this.character.canThrow() !== true`（无 ThrowComponent / 无弹）。
2. `distance > effectiveRange × (1 + distanceStartupSmooth)`（物理不可达；smooth 复用 `attack.distanceStartupSmooth`，不新增同义字段）。

### 6.2 距离三区间（rangeFactor，连续衰减非二元）

| 区间 | rangeFactor | 说明 |
|---|---|---|
| `distance ≤ maxEffMeleeReach` | `meleeZoneFactor`（0.35，非零） | 近战够得到，throw 留弹性不禁止 |
| `maxEffMeleeReach < distance ≤ effectiveRange` | 1.0 | 投掷甜点：近战 0 分、throw 自然胜出 |
| `effectiveRange < distance ≤ effectiveRange×(1+smooth)` | 1→0 线性衰减 | 与 attack 边缘衰减同构 |
| 更远 | 门控 0 | — |

`score = throw.baseWeight × rangeFactor` 起步。

### 6.3 风险 A：release 前被近战打断（独立项）

比较「对手首次能命中我的时刻」与「我的 release 时刻 = throwProfile.timing.startupMs」。优先消费 `predictedOpponentEvents` 的 `opp_attack_active_window`（含 startMs/trajectory），无事件时按 `sit.opp.phase` 退化：

- opp `active` 且 `distance ≤ opp maxEffReach` → 满额扣分 `interruptRiskPenalty`（0.25）。
- opp `startup`：事件 startMs（或 opp attackProfile 的 startup 剩余估计）+ 对手 reach 校验；`startMs ≤ startupMs + startupInterruptMarginMs(50)` 且够得到我 → 按时间裕量 0→1 线性扣分；够不到 → 0。
- opp `idle/none/recovery` → 0。
- opp `throw_windup` → 风险 A=0（对手无近战出手）；其投掷物威胁由同池 projectile defense 候选竞争表达，throw 自身不重复扣分。

### 6.4 风险 B：出手后被斩落（仅 cuttable）

`cuttable === false`（rock）→ 本项恒 0，但风险 A 照常。

cuttable 时：
1. `opponentKB.attacks` 无 `trajectory==="slash"` → 0。
2. `flightMs = distance / speed × 1000`。
3. opp 反应线 `cutReadyMs = fastestSlash.startupMs + tuning.defense.reflexMaxMs`：
   - `flightMs ≥ cutReadyMs` → factor 1.0（对手来得及出刀）；
   - 否则 factor = `flightMs / cutReadyMs`（飞到太快，斩不掉，风险线性降低）。
4. opp 当前 `active` 且招式 trajectory=slash 时 factor 直接 1.0（weaponbox 可能已在场）。
5. 扣分 = factor × `cutRiskPenalty`（0.20）。

v1 不做逐帧轨迹交汇；factor 是时间可行性的简化模型。

### 6.5 相位/窗口加减项

- `idle/none`：+ `idleOpportunityBonus`（0.05，弱主动机会，与 attack proactive 基调一致）。
- `recovery`：**不凭相位加分**。仅当预测事件证明 `recovery 剩余 ms ≥ startupMs + distance/speed×1000`（释放+飞到时 opp 仍未恢复）才 + `recoveryPunishBonus`（0.15）；无事件数据 → 0。
- `startup/active`：无加分，仅承受风险 A。

### 6.6 冷却与重复成本

- cooldown：`sit.now - lastAttackTime < attackCooldownMs` → 扣 `attack.cooldownPenalty`（复用，不新增）。**不享 startup 豁免**（对手 startup 时扔东西本就是风险动作，风险 A 另外计）。
- repetition：复用 `#consecutiveAttackUsage` 机制，key = throw stateName，费率/上限读 `throw.repetitionCostRate/Max`（默认与 attack 同值 0.06/0.18，因弹药已是天然限制，不加重）。
- jitter：沿用 #scoreAttack/#scoreDefense 现有的 `reactionVariance` 扰动写法，保持 tie-break 一致性。

### 6.7 终分汇总

```
finalThrowScore = ( baseWeight×rangeFactor
                    - riskA - riskB
                    + idleBonus + recoveryBonus(事件门控)
                    - cooldownPenalty - repetitionCost )
                  × posture.attackMultiplier
                  × throwPreference
```

`throwPreference` 读取（方案 a，默认 **1.0** 中性）：

```js
this.character.stateGraph?.aiProfile?.throwPreference ?? 1.0
```

默认中性的理由：甜点距离近战候选已被距离门控归 0，throw 无需全局压分；「不爱扔」的角色在 aiProfile 显式配低值。负分按现有候选池惯例允许存在（排序自然落败），不 clamp 到 0。

## §7 Step 4a：`Data/AITuning.js` 新增 throw 块

```js
throw: {
    baseWeight: 0.35,            // 低于 attack.baseWeight(0.4)，但量级同档可竞争
    rangeConservatism: 0.85,     // R_effective = R_physical × 0.85
    meleeZoneFactor: 0.35,       // 近战区间 throw 距离系数（非零）
    interruptRiskPenalty: 0.25,  // 风险 A 满额

    cutRiskPenalty: 0.20,        // 风险 B 满额

    recoveryPunishBonus: 0.15,

    repetitionCostMax: 0.18,
    // distanceStartupSmooth / cooldownPenalty / reflexMaxMs 显式复用 attack/defense 字段
},
```

## §8 Step 4b：`#executeCommitted()` 接 throw

现有结构（`AIController.js:1849-1887`）：positioning 三 kind 提前 return；attack/dodge/guard 统一 `setMoveIntent(0,0)` + `queueCommand(action.stateName)` + `pushCommit`，随后 attack 更新冷却与重复计数、其余 reset。

throw 归入「进攻提交」一侧：

```js
// queueCommand/pushCommit 与 attack 共用，pushCommit("throw", action.stateName)
if (kind === "attack" || kind === "throw") {
    this.lastAttackTime = performance.now();          // 共享近战↔投掷冷却
    if (this.#consecutiveAttackUsage?.stateName === action.stateName)
        this.#consecutiveAttackUsage.count++;
    else
        this.#consecutiveAttackUsage = { stateName: action.stateName, count: 1 };
} else {
    this.#consecutiveAttackUsage = null;              // dodge/guard/positioning reset
}
```

- `queueCommand(action.stateName)`（即 `"throw"`）走既有 transition；执行期无弹由 `CombatCharacter` transition gate 兜底（双层合法性）。
- throw 是 committed state，现有「非 idle/move 跳过决策」机制自动覆盖 action commitment，无需新增分支。
- 弹药扣除/被打断语义完全不动：release 事件 spawn 成功才扣，release 前被 Hit 打断不扣。

## §11 验收矩阵

| # | 场景 | 预期 |
|---|---|---|
| 1 | 距离 > maxEffMeleeReach 且 ≤ R_eff，有弹 | throw 候选胜出并提交；飞刀命中/被斩走现有管道；弹药 -1 |
