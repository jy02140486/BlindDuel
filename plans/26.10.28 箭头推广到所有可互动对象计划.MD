# 箭头推广到所有可互动对象计划

## 0. 目标与范围

### 目标

将现有的 Trigger 互动箭头机制（`AABBTrigger` 内嵌 `ArrowIndicator`）扩展到**所有可交互对象**，让玩家在探索场景中对"哪里可以互动"有统一的视觉提示。

### 范围（本期覆盖）

| 目标 | 检测方式 | 现有提示 | 本期改造 |
|---|---|---|---|
| **AABBTrigger**（sceneSwitch / battle / sequence） | AABB 盒子重叠 | ✅ Arrow | **保留**，作为扩展后的基础 |
| **PickableEntity** | 距离检测 `<= 1.6²` | ❌ 无 | ✅ **新增 Arrow** |
| **NPC** `_needsInteract === true` | 距离检测 `<= greetingRadius²` | ⚠️ 只有 dialogueBubble | ✅ **新增 Arrow** |

### 设计决策（已定）

| # | 问题 | 决策 | 说明 |
|---|---|---|---|
| 1 | Pickable 箭头可见策略 | **接近才显示** | 与现有 trigger 一致，避免场景中箭头过多造成视觉噪声 |
| 2 | NPC 箭头 | **只在 `_needsInteract === true` 时显示** | 普通 idle NPC 不加箭头，保持画面干净 |
| 3 | 箭头方向 | **静态配置 up/down/left/right** | 复用现有 `direction` 字段，不做动态指向 |
| 4 | 配置方式 | **统一在 EntityDef JSON 里加 `"arrow": {...}`** | 数据驱动，与 trigger.arrow 风格完全一致 |

### 不在本期范围

- **箭头浮动动画**（Y 轴 sin 波动）— 后续可扩展 `arrow.bob`
- **多种箭头皮肤**（quest/warning/default）— 后续可扩展 `arrow.skin`
- **屏幕空间 off-screen HUD 箭头**（指向屏幕外的交互对象）
- **箭头方向动态指向玩家**（智能但复杂度高，本期用静态配置）
- **普通 idle NPC 的对话箭头**（只有 quest 交付状态显示）

### 2.2 改造前后对比

**改造前（静态模式）：**
```javascript
// ArrowIndicator 构造时一次性算死位置
constructor(scene, triggerPosition, triggerSize, config) {
    this._triggerPosition = triggerPosition.clone();  // 存死
    this._triggerSize = { ...triggerSize };           // 存死
    const pos = this._computePosition(config.edge, config.offset);  // 一次算完
    this.plane.position.copyFrom(pos);
    // ...
}
// 后续 updateArrow 只调 setVisible + stepFrame，不更新位置
```

**改造后（支持动态）：**
```javascript
class ArrowIndicator {
    constructor(scene, config) {
        // 不再传入 position/size，只传配置
        this._targetNode = null;        // 动态目标 TransformNode
        this._targetOffset = null;      // 动态偏移 { edge, offset }
        this._staticPosition = null;    // 静态 fallback（AABBTrigger 用）
        // ... mesh 创建不变
    }

    // 动态绑定实体（Pickable / NPC）
    attachTo(node, offsetConfig) {
        this._targetNode = node;
        this._targetOffset = offsetConfig;  // { edge, offset }
    }

    // 静态位置（AABBTrigger 向后兼容）
    setStaticPosition(position) {
        this._staticPosition = position.clone();
        this._targetNode = null;
    }

    // 每帧更新位置 + 帧动画
    tick(dtMs) {
        // 位置更新
        if (this._targetNode) {
            const p = this._targetNode.position;
            const edge = this._targetOffset.edge ?? "top";
            const offset = this._targetOffset.offset ?? 0.3;
            // 从实体 root + edge/offset 算箭头位置
            this.plane.position.copyFrom(this._resolveDynamicPos(p, edge, offset));
        } else if (this._staticPosition) {
            this.plane.position.copyFrom(this._staticPosition);
        }

        // 帧动画步进（不变）
        if (this.plane.isEnabled()) this.stepFrame(dtMs);
    }
}
```

### 2.3 模块职责变化

| 模块 | 改造后职责 |
|---|---|
| **ArrowIndicator** | 从"静态 trigger 附属品"升级为"通用箭头组件"，支持动态绑定 + 静态 fallback |
| **AABBTrigger** | 内部调用 ArrowIndicator，**对外接口不变**（setupArrow / updateArrow / disposeArrow 保持兼容） |
| **Scene.js** | spawn 实体时如果 EntityDef 有 `arrow` 配置 → 自动创建 ArrowIndicator |
| **ExploreMode** | 拆为两个方法：#updateTriggerArrows（保留）+ #updateInteractableArrows（新增，管 Pickable + NPC） |
| **PickableEntity** | pickup() 时 dispose 自己的 arrow |
| **NpcController** | `_needsInteract` 生命周期内由 ExploreMode 管理 arrow 创建/销毁（NPC 自己不持有） |

## 3. 数据结构

### 3.1 EntityDef.arrow 字段（SceneDef JSON，统一格式）

与 triggerDef.arrow 完全一致，可用于 Pickable / NPC / 未来其他实体类型：

```json
"arrow": {
    "enabled": true,
    "edge": "top",           // "top" | "bottom" | "left" | "right"，默认 "top"
    "direction": "up",       // "up" | "down" | "left" | "right"，默认 "up"
    "offset": 0.3,           // 箭头与目标边缘的间隙（世界单位），默认 0.3
    "scale": 0.4,            // 箭头缩放，默认 0.4（Pickable/NPC 用较小值避免遮挡）
    "frameMs": 250           // 帧时长，默认 250
}
```

### 3.2 典型配置示例

**Pickable（默认配置）：**
```json
{
    "archetype": "pickable",
    "id": "ham_01",
    "pos": [6.0, -2.704],
    "visualYOffset": 1.5,
    "arrow": { "enabled": true, "edge": "top", "offset": 0.5, "scale": 0.4 },
    "itemDef": { "id": "ham", "name": "火腿", ... }
}
```

**NPC（默认配置，实际由 NpcDef 或 SceneDef 注入）：**
```json
{
    "archetype": "npc_customer",
    "id": "customer",
    "pos": [2.8, -2.04],
    "arrow": { "enabled": true, "edge": "top", "offset": 0.5, "scale": 0.5 }
}
```

**AABBTrigger（保持不变，向后兼容）：**
```json
{
    "type": "sceneSwitch",
    "id": "exit_house",
    "pos": [-2, -1, 0],
    "size": [2, 2, 2],
    "arrow": { "enabled": true, "edge": "top", "direction": "up", "offset": 0.3 }
}
```

### 3.3 默认值约定

| 字段 | AABBTrigger 默认 | Pickable/NPC 默认 | 理由 |
|---|---|---|---|
| `edge` | `"bottom"` | `"top"` | trigger 通常在地面，箭头从底部伸出；实体头顶更自然 |
| `scale` | `1.0` | `0.4` | trigger 盒子大（2×2），实体 sprite 小（0.96×0.96） |
| `enabled` | 需显式 `"arrow": {}` | 需显式 `"arrow": {}` | 统一：不写 arrow 即无箭头 |

## 4. 位置计算方案

### 4.1 ArrowIndicator 需支持两套路径

**路径 A：静态位置（AABBTrigger 向后兼容）**
- 输入：trigger center + trigger size + edge + offset
- 输出：一次性计算好的 Vector3
- 逻辑不变（保留现有 `_computePosition`）

**路径 B：动态实体位置（Pickable / NPC 新增）**
- 输入：`entity.root.position`（每帧变化）+ edge + offset
- 输出：从 root + edge/offset 算的 Vector3，**每帧重算**

### 4.2 动态实体的锚点含义

Pickable / NPC 没有 size 概念，`edge` 字段语义调整为：

| edge | 位置公式 | 说明 |
|---|---|---|
| `"top"` | `(root.x, root.y + offset, root.z)` | 头顶上方，**本期统一用这个** |
| `"bottom"` | `(root.x, root.y - offset, root.z)` | 脚下 |
| `"left"` | `(root.x - offset, root.y, root.z)` | 左侧 |
| `"right"` | `(root.x + offset, root.y, root.z)` | 右侧 |

> **注**：Pickable 的 `visualYOffset` 让 sprite 显示在 root 上方 1.5 处，但 **root 位置仍是逻辑锚点**（`ExploreMode.#checkInteraction` 用的就是 root 距离），所以箭头也以 root 为基准 + `edge: "top"` + `offset: 0.5` ≈ sprite 头顶附近，视觉上对齐。

### 4.3 统一的 `_resolveDynamicPos` 实现

```javascript
_resolveDynamicPos(rootPos, edge, offset) {
    const { x, y, z } = rootPos;
    switch (edge) {
        case "top":    return new BABYLON.Vector3(x, y + offset, z);
        case "bottom": return new BABYLON.Vector3(x, y - offset, z);
        case "left":   return new BABYLON.Vector3(x - offset, y, z);
        case "right":  return new BABYLON.Vector3(x + offset, y, z);
        default:       return new BABYLON.Vector3(x, y + offset, z);  // 默认 top
    }
}
```

## 5. 显隐判定（ExploreMode 集成）

### 5.1 拆分两个方法

**保留** `#updateTriggerArrows(character, dtMs, sequencerBusy)` — 只管 AABBTrigger
**新增** `#updateInteractableArrows(character, dtMs, sequencerBusy)` — 管 Pickable + NPC

### 5.2 `#updateInteractableArrows` 详细设计

```javascript
#updateInteractableArrows(character, dtMs, sequencerBusy) {
    const { sceneDef, babylonScene } = this.context;
    const hidden = sequencerBusy;

    // ── 1. Pickable：按 EntityDef.arrow 配置，接近才显示 ──
    for (const pickable of this.pickables) {
        if (pickable.isDisposed) continue;
        if (!pickable._arrow) continue;

        const dx = character.root.position.x - pickable.root.position.x;
        const dy = character.root.position.y - pickable.root.position.y;
        const dist = Math.sqrt(dx * dx + dy * dy);
        const PICKUP_RADIUS = 1.6;  // 与 #checkInteraction 保持一致

        const visible = !hidden && dist <= PICKUP_RADIUS;
        pickable._arrow.tick(dtMs, visible);  // 新增 tick 接口
    }

    // ── 2. NPC needsInteract：动态创建/销毁 arrow ──
    for (const npc of this.interactables) {
        const controller = npc.npcController;
        const needsArrow = controller?._needsInteract === true;

        if (!needsArrow) {
            // 不需要交互 → 销毁 arrow（如果存在）
            if (npc._arrow) {
                npc._arrow.dispose();
                npc._arrow = null;
            }
            continue;
        }

        // 需要交互但还没 arrow → 创建（用 NpcDef/SceneDef 配置或默认）
        if (!npc._arrow) {
            const arrowConfig = this._resolveNpcArrowConfig(npc);
            npc._arrow = new ArrowIndicator(babylonScene, arrowConfig);
            npc._arrow.attachTo(npc.root, { edge: arrowConfig.edge ?? "top", offset: arrowConfig.offset ?? 0.5 });
        }

        // 判定可见性：在 greetingRadius 内 + 非 sequencer
        const greetingRadius = controller.greetingRadius ?? 1.6;
        const dx = character.root.position.x - npc.root.position.x;
        const dy = character.root.position.y - npc.root.position.y;
        const distSq = dx * dx + dy * dy;
        const visible = !hidden && distSq <= greetingRadius * greetingRadius;
        npc._arrow.tick(dtMs, visible);
    }
}

_resolveNpcArrowConfig(npc) {
    // 优先读 EntityDef.arrow → 兜底默认值
    const entityDef = this.context.sceneDef?.entities?.find(e => e.id === npc.id);
    if (entityDef?.arrow) return entityDef.arrow;
    // 默认配置
    return { enabled: true, edge: "top", offset: 0.5, scale: 0.5, frameMs: 250 };
}
```

### 5.3 ArrowIndicator 新增 `tick` 接口

```javascript
// 替代原 setVisible + stepFrame 的组合调用
tick(dtMs, visible) {
    // 先更新可见性
    this.setVisible(visible);
    if (!visible) return;

    // 再更新位置（动态模式）
    this._updatePosition();

    // 最后推进帧动画
    this.stepFrame(dtMs);
}
```

### 5.4 ExploreMode.fixedUpdate 调用顺序

```javascript
// fixedUpdate 内部，在 controller.update 之后、交互检测之后
const sequencerBusy = sceneSequencer?.isBusy() ?? false;

// ... controller.update ...

// 交互检测（不改）
if (!sequencerBusy) {
    this.#checkInteraction(character, tickCount);
    // ...
}

// 箭头更新（统一放在 sequencer 门控之外，让每个方法内部自己判定）
this.#updateTriggerArrows(character, dtMs, sequencerBusy);
this.#updateInteractableArrows(character, dtMs, sequencerBusy);  // 新增
this.#updateDialogueBubble();
```

## 6. AABBTrigger + ArrowIndicator 改造

### 6.1 ArrowIndicator 新接口

| 方法 | 类型 | 说明 |
|---|---|---|
| `constructor(scene, config)` | 改 | 只接收 scene + config，不再接收 position/size |
| `attachTo(node, { edge, offset })` | **新增** | 绑定动态 TransformNode（Pickable.root / NpcCharacter.root） |
| `setStaticPosition(position, size, { edge, offset })` | **新增** | 静态模式（AABBTrigger 用），内部调 `_computePosition` 算死一次 |
| `tick(dtMs, visible)` | **新增** | 统一入口：可见性 → 位置 → 帧动画 |
| `setVisible(visible)` | 保留 | 原接口，内部 plane.setEnabled |
| `stepFrame(dtMs)` | 保留 | 原接口，帧动画步进 |
| `_updatePosition()` | **新增** | 根据 `_targetNode` 或 `_staticPosition` 更新 plane.position |
| `dispose()` | 保留 | 原接口 |

### 6.2 AABBTrigger.setupArrow 适配

AABBTrigger 内部调用 ArrowIndicator 时改用新接口，**对外接口不变**：

```javascript
setupArrow(config) {
    if (this._arrow) {
        this._arrow.dispose();
        this._arrow = null;
    }
    // ArrowIndicator 构造改为只传 scene + config
    this._arrow = new ArrowIndicator(this.scene, config);
    // AABBTrigger 用静态模式（向后兼容，位置一次算死）
    this._arrow.setStaticPosition(this.position, this.size, {
        edge: config.edge ?? "bottom",
        offset: config.offset ?? 0.3
    });
}

// updateArrow 改为调新的 tick 接口
updateArrow(visible, dtMs) {
    if (!this._arrow) return;
    this._arrow.tick(dtMs, visible);
}
```

### 6.3 AABBTrigger 完整新旧接口对照

| 旧接口 | 新接口 | 变化 |
|---|---|---|
| `setupArrow(config)` | `setupArrow(config)` | 内部适配，**对外签名不变** ✅ |
| `updateArrow(visible, dtMs)` | `updateArrow(visible, dtMs)` | 内部调 `tick`，**对外签名不变** ✅ |

## 10. 风险与回退

### 风险

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| ArrowIndicator 构造失败（纹理加载） | 低 | 该实体无箭头，不影响其他 | try-catch + console.warn，实体正常创建 |
| NPC arrow 生命周期管理复杂（needsInteract 变 false 时销毁） | 中 | 可能有瞬态闪烁 | ExploreMode 检测到后延迟 1 帧销毁；实测验证 |
| 动态模式每帧更新 position 带来性能开销 | 极低 | 多 2-3 个 Vector3 赋值 | 每次最多几个实体，Babylon 处理量可忽略 |
| Pickable pickup 后 arrow 未 dispose | 低 | 场景残留不可见 mesh | pickup() 显式 dispose + Scene.dispose 兜底 |

### 回退

1. **全局禁用**：删掉所有 EntityDef / triggerDef 的 `"arrow"` 字段 → 零箭头
2. **模块禁用**：注释 ExploreMode.#updateInteractableArrows 调用 → 只剩 trigger 箭头
3. **ArrowIndicator 新接口回退**：`setStaticPosition` 是向后兼容的，AABBTrigger 不受影响
